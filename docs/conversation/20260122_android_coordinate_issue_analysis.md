# 안드로이드 데모 좌표 고정 및 추적 불가 이슈 분석 보고서

## 1. 이슈 개요
- **현상**: 안드로이드 데모 앱에서 얼굴 인식용 노란색 랜드마크 점들이 실제 얼굴을 따라가지 않고 화면 상단 중앙(어두운 영역)에 고정되어 나타남.
- **특이사항**: C++ 데모는 정상 작동함. 이는 코어 알고리즘의 문제보다는 안드로이드 플랫폼과의 연결부(JNI, 회전 처리, 좌표 매핑) 혹은 안드로이드 특유의 최적화 로직 문제일 가능성이 높음.

## 2. 기술적 원인 분석 (가설)

### 가설 A: 추적 캐시(Tracking Cache)의 오염 및 고착
- `mediapipe_detector.cpp`의 `use_tracking` 로직이 원인일 가능성.
- 첫 프레임에서 얼굴이 아닌 배경(어두운 물체)을 얼굴로 오인식(이미지에서 Confidence 0.81)하여 `prev_face_rect`가 고정됨.
- 이후 프레임에서 `skip_face_detection = true`가 되면서 전체 화면을 보지 않고 고정된 영역만 크롭해서 검사하기 때문에 얼굴이 움직여도 인식 영역이 따라가지 못함.
- **C++ 데모와의 차이**: C++ 데모는 조명 조건이나 초기화 시점이 달라 오인식이 발생하지 않았거나, `use_tracking` 설정이 다를 수 있음.

### 가설 B: 회전(Rotation) 처리 시의 좌표계 불일치
- 안드로이드 카메라는 프레임이 90/270도 회전되어 들어옴.
- `detectOnlyWithRotation` -> `cv::rotate` 과정에서 이미지는 회전되지만, `actual_face_crop` 계산 시 사용되는 종횡비(Aspect Ratio)가 원본 기준인지 회전 후 기준인지 혼용되어 ROI가 상단으로 밀릴 수 있음.
- 특히 `ISS-001`, `ISS-002` 보정 로직이 회전된 좌표계에서 오작동할 가능성.

### 가설 C: UI 레이어(OverlayView)의 스케일링 오류
- SDK가 반환하는 좌표는 0.0 ~ 1.0의 정규화 좌표임.
- `OverlayView.kt`에서 이 좌표를 화면에 그릴 때 사용하는 `scaleX`, `scaleY`의 기준이 되는 `imageWidth`, `imageHeight`가 회전된 프레임의 크기가 아닌 원본 센서의 크기를 사용하여 좌표가 상단으로 압축되어 보일 수 있음.

## 3. 해결 계획 (Plan)

### 1단계: 진단 (Diagnosis)
- [ ] **추적 로직 비활성화**: `mediapipe_detector.cpp`의 `use_tracking`을 강제로 `false`로 설정하여 매 프레임 전체 검출을 수행했을 때 얼굴을 따라오는지 확인.
- [ ] **로그 강화**: JNI 경계에서 전달되는 `rotationDegrees`, `width`, `height`와 SDK 내부에서 인식하는 값을 로그로 출력하여 비교.

### 2단계: 수정 (Remediation)
- **추적 로직 개선**: 오인식 방지를 위해 `min_presence_confidence`를 높이거나, 추적 실패 시 즉시 캐시를 비우는 로직 강화.
- **좌표계 동기화**: `detectOnlyWithRotation` 내부의 `actual_face_crop` 계산 로직이 회전 후의 해상도를 정확히 반영하도록 수정.
- **안드로이드 UI 보정**: `OverlayView.kt`에서 `imageWidth/Height`를 전달받을 때 회전 정보를 고려하여 가로/세로를 스왑(swap)하는 로직 추가.

## 4. 결론
이 문제는 **"잘못된 초기 검출 결과가 추적 알고리즘에 의해 고정(Lock)"**된 상태에서, 안드로이드 특유의 **"회전된 좌표계"**가 복합적으로 작용하여 발생하는 것으로 보입니다. 추적 로직을 끄고 순수 검출 성능을 먼저 확보한 뒤, 추적 로직을 안전하게 다시 켜는 방향으로 수정이 필요합니다.
