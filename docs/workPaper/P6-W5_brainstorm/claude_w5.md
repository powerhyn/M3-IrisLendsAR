## 6.1 SKU 중복 사용 — **별도 확보 추천 (로뮤_디어 + 클라셋_돌)**

근거:
- (1) "불투명 서클(랜덤 도트 패턴)"과 "다크브라운(균일 채움)"은 **디테일 패턴 차이가 CRL 수식에 감수성이 다를 가능성이 큰 SKU**. B1 벤치의 핵심이 "어느 SKU에서 CRL이 승리하는지" 파악이라면 이 두 유형을 묶어버리면 관찰 정보 손실.
- (2) B1 매트릭스가 5 SKU로 이미 고정이면 한 슬롯(예: 어두운 톤)에 클라셋_돌 초코 1개만 넣고, 별도 불투명 서클 SKU(로뮤_디어 멜로우)는 추가 슬롯. 5→6 SKU로 증가해도 벤치 시간 영향 제한적.

## 6.2 B1×B8 조합 라벨링 — **런타임 버튼 UI A/B/C/D + 정답표 암호화**

근거:
- (1) 디버그 커맨드 기반은 평가자가 매번 매니저에게 요청해야 하므로 흐름 끊김. 런타임 UI 버튼 4개(A/B/C/D)가 빠름.
- (2) 블라인드: 버튼 라벨만 노출, **내부 매핑(A=Normal+color-veto, B=CRL+color-veto, …)은 암호화 파일**. W4 §5.11 방식과 동일.
- (3) 토글 방식: sampleReflection uniform 스위치(W3 방식 A) 재사용 — blendMode ID + scleraPath ID 2개 uniform 병렬 제어.

## 6.3 CRL `detail` clamp 범위 / `maxDetail` 기본값 — **`[0.75, 1.25]` 유지 + `uMaxDetail = 1.25` 기본**

근거:
- (1) 현재 수식 `clamp(pow(lum/avgLum, 0.7), 0.75, 1.25)`에서 상한 1.25는 "1.5 이상 허용하면 하이라이트가 과하게 튐" 가정. `uMaxDetail`을 1.25로 두면 제약 없음과 동일, W5 벤치에서 **추가 clamp 안 거친 "raw CRL"로 시작**.
- (2) 벤치 결과 "CRL이 과하다" 피드백 2/3 → `uMaxDetail = 1.15`로 내림. "CRL이 약하다"면 1.35로 올림(단 1.5 초과 금지).
- (3) 하한 0.75는 디테일 저하 방지선이라 안정 값. 튜닝 대상 아님.

## 6.4 B1 조건부 채택 — **SKU 메타 `prefers_crl` 플래그 + 런타임 자동 선택, UI 비노출**

근거:
- (1) 플래그 있는 SKU는 자동 CRL. 플래그 없으면 TintLinearV2(기본값, W2 §5.12 확정). 평가자/사용자가 수동 덮어쓸 필요 없음 — SKU 제작자가 판단한 후 플래그 박으면 끝.
- (2) UI 노출 금지 이유: 블렌드 모드를 사용자가 직접 선택하는 건 W3-04 시절 실패 패턴. 피팅 체험의 "자연스러움"을 흐림.
- (3) 메타 형식 제안: `lens_config.prefers_crl = true/false` (기본 false). SDK C API 변경 없음 (내부 메타).

## 6.5 Gemini luma-only 임계값 — **`smoothstep(0.35, 0.60, lum)`으로 조정**

근거:
- (1) 원 `smoothstep(0.45, 0.65, lum)`은 iris 평균 루마가 0.3~0.4인 한국인에게 하한이 너무 높음 — iris 외곽 normal 영역까지 veto 발동 위험.
- (2) 0.35~0.60으로 낮추면 iris 본체는 거의 veto 없음, 밝은 반사(specular, 눈꺼풀 그림자 경계)만 선택적 veto. 실기기 벤치 시 0.05 단위 ±1 swing(0.30/0.65 ~ 0.40/0.60) 평가 권장.
- (3) **단, 이는 Claude 추정** — 실제 shader에서 iris 루마 분포 확인 후 확정 필요. Gemini R1에 "현 임계 유지" 반론 있으면 재검토.

## 6.6 calcScleraFactor — **단순 수식 교체 (함수명 유지, 호출부 무영향)**

근거:
- (1) 함수명 유지 → 호출자 수정 0. Git blame으로 수식 변경 이력만 추적 가능하면 충분.
- (2) 새 함수 추가 + deprecated는 P6-W2 §5.11 "realSpec 완전 삭제" 원칙과 일관. 불필요한 deprecated 저류 방지.

## 6.7 color-veto `0.6` 튜닝 — **기본 0.6 유지, [0.4, 0.8] W5 벤치 스위프**

근거:
- (1) Codex R3 §8 "감쇄를 일부 되돌리는 veto" 해석 재확인 — veto 강도는 "어느 정도까지 감쇄를 해제할지"의 자유도. 0.6은 "감쇄의 60%를 되돌린다"는 의미이므로 완전 원복(1.0)과 완전 감쇄(0.0) 사이 가중치.
- (2) W5 벤치 매트릭스에 veto=0.4, 0.6, 0.8 스위프 포함. 클립 수 증가(5 SKU × 3 veto × 2 동작 = 30 → 한계 있음) → **대표 SKU 2종에만 veto 스위프**, 나머지는 0.6 고정.
- (3) 결과에 따라 W5 완료 시 단일 값 확정. 후속 W 재튜닝 가능성 유지.

## 자기비판 (편향 경계)

- 6.5 Claude가 독단적으로 임계 조정 제안. Codex/Gemini가 "현 0.45/0.65 유지"라 하면 실측 우선으로 수용.
