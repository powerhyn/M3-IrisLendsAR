# P6-W6 브레인스토밍 R2 - Codex 교차 비판

**대상:** `P6-W6_temporal_detail_bench.md` §6의 닫힌 7개 쟁점 및 §5.5~§5.11 반영안  
**판정 기준:** 새 대안은 추가하지 않고, R1 결정을 그대로 구현해도 되는지만 검증한다.

## 1. 최종 결론

R1의 핵심 선택은 철회하지 않는다. EMA의 95% 도달 의미, gate의 ±0.03 폭, 3x3 blur, 부드러운 innerMask, `avg_iris_luma` 기반 저조도 정의, B5/B9 동시 측정은 모두 유지한다.

다만 **전면 동의는 아니다.** 닫힌 결정의 값을 다시 투표할 필요는 없지만, 다음 네 가지는 구현 전에 문서/호출 계약을 정정해야 한다.

1. §5.5 EMA는 `fps` 기반 함수가 아니라 실측 `dt_ms`를 매 프레임 받는 함수로 단일화해야 한다.
2. §5.7의 ±0.03은 루마 축 전이 폭이지 "30fps 기준 2~3프레임"의 시간 평활화가 아니다.
3. §5.9는 현재 셰이더 계약상 이미 정규화된 `dist`를 사용하므로 `/iris_radius`를 다시 붙이면 안 된다.
4. §5.11의 "C10 후행"은 **최종 튜닝 후행**을 뜻해야 한다. B9 캡처 전에는 gate 후보를 비교할 C10 프로토타입이 먼저 있어야 한다.

위 네 항목은 새 쟁점이 아니라 각각 §6.1, §6.3, §6.5, §6.7 결정의 구현 정합성 점검이다.

## 2. 내 R1 입장 유지/수정/철회

| 원 쟁점 | R2 입장 | 판정 |
|---|---|---|
| §6.1 / §5.5 EMA 공식 | **수정** | 공식 `1 - pow(0.05, dt_ms / target_ms)`와 95% 정의는 유지. R1의 `fps` 표현은 버리고 실측 `dt_ms` 호출 계약으로 명시한다. |
| §6.2 / §5.6 B5 user 수 | **유지** | `3명 x 5 블링크 x 3 up 시간 = 45 이벤트`는 정성 선호 판정용 축소안으로 타당하다. 통계적 일반화의 근거로만 과장하지 않으면 된다. |
| §6.3 / §5.7 gate smoothstep | **유지 (근거 정정)** | `smoothstep(threshold - 0.03, threshold + 0.03, uAvgIrisLum)`은 유지. 단 시간적 flicker 제거를 보장한다는 설명은 삭제해야 한다. |
| §6.4 / §5.8 blur 커널 | **유지** | 3x3 footprint와 single-pass 선택을 유지한다. 현재 §5.2의 중앙 가중 9-sample 커널도 3x3 결정 범위 안이다. |

| §6.7 / §5.11 B5/B9 동시 측정 | **수정** | 동시 캡처와 분리 판정은 유지. C10은 비교 가능한 프로토타입을 먼저 만들고, B5/B9 결과에 따른 최종 튜닝만 후행한다. |

**철회 항목은 없다.**

## 3. 상대 모델 R1 논리 평가

### 3.1 Gemini R1

- **EMA (§5.5): 동의.** Gemini가 채택한 `1.0 - pow(0.05, dt/target_ms)`는 target을 95% 도달 시간으로 정의할 때 정확하다. 다만 "가변 프레임레이트에서도 보장"하려면 구현 입력이 명시적으로 매 프레임 실측 `dt_ms`여야 한다.
- **gate (§5.7): 결론 동의, 근거는 제한적 동의.** ±0.03은 hard on/off보다 연속적인 밝기 응답을 준다. 그러나 입력 루마가 프레임마다 흔들릴 때 자체로 flicker를 제거하는 temporal filter는 아니다.
- **3x3 blur (§5.8): 결론 동의, 성능 단정은 불수용.** 5x5보다 비용이 낮고 single-pass 방향에 맞는다. 반면 "MID GPU 예산 내 성능 저하 없이 수행 가능"은 측정 전에는 근거가 없다. 결정은 유지하되 구현 검증에서 비용을 확인해야 한다.
- **innerMask (§5.9): 동의.** Gemini의 `smoothstep(0.7, 0.5, dist)` 표기가 현재의 정규화 `dist` 계약과 맞다. 이 점에서는 종합문의 `/iris_radius` 표기보다 안전하다.
- **B5/B9/C10 수행 순서: 보정 필요.** 동일 시나리오에서 검증 가능하다는 말은 맞지만, C10의 최종 파라미터까지 캡처 전에 확정되는 것은 아니다. B9용 프로토타입과 결과 반영 튜닝을 구분해야 한다.

### 3.2 Claude R1

- **EMA (§5.5): 반대 유지.** Claude의 `alpha = 1 - exp(-dt/tau)`는 `tau`를 63% 도달 시간으로 정할 때 수학적으로 맞다. 그러나 이는 오류 수정이 아니라 target 의미의 변경이다. W6가 요구하는 target이 "80ms에 95% 도달"이면 Claude 식은 80ms에 약 63%만 도달하므로 채택할 수 없다.
- **gate (§5.7): 공식은 동의, 시간 근거는 반박.** `threshold +/- 0.03`은 수용 가능하다. 하지만 이를 "30fps 기준 2~3프레임 smooth"라고 설명한 것은 틀렸다. `smoothstep`은 루마 값의 매핑이며 프레임 수를 규정하지 않는다.
- **3x3 blur (§5.8): 동의.** 25-fetch 5x5나 별도 패스를 들이지 않는 판단은 W6의 single-pass 방향과 일치한다.
- **innerMask (§5.9): 방향은 동의, 표기는 조건부 반박.** inner에서 1, outer에서 0으로 감소하는 smoothstep 선택은 맞다. 다만 W6 §5.2처럼 `dist`가 이미 정규화되어 있다면 `dist/iris_radius`는 중복 정규화이므로 구현식으로는 받아들일 수 없다.
- **C10 후행: 유효한 보정이지만 표현 보완 필요.** 최종 튜닝을 B5/B9 판정 뒤에 놓자는 지적은 Gemini/내 R1보다 정확하다. 단 B9 자체가 C10 gate 비교이므로 프로토타입 구현까지 후행시키면 벤치를 수행할 수 없다.

## 4. 핵심 수식 교차 검증

### §5.5 EMA `1 - pow(0.05, dt_ms / target_ms)`

유지한다. 매 프레임 잔존량은 다음과 같다.

```text
1 - alpha_i = pow(0.05, dt_i / target_ms)
누적 잔존량 = pow(0.05, sum(dt_i) / target_ms)
```

따라서 누적 시간이 `target_ms`에 도달하면 잔존량은 `0.05`, 즉 목표값의 95%에 도달한다. 구현 계약은 다음 한 형태로 통일해야 한다.

```cpp
float computeEmaAlpha(float dt_ms, float target_ms) {
    return 1.0f - std::pow(0.05f, dt_ms / target_ms);
}
```

§5.1의 `computeEmaAlpha(target_ms, fps)` 예시는 §5.5의 확정과 충돌하므로 구현 기준으로 사용하면 안 된다.

### §5.7 gate `smoothstep(threshold - 0.03, threshold + 0.03, uAvgIrisLum)`

유지한다. 낮은 루마에서 `detail`을 끄고 충분한 루마에서 켜는 방향도 맞다. 단 이 식이 확정하는 것은 threshold 주변 **0.06 linear-luma 폭의 연속 전이**뿐이다. 프레임 시간이나 전이 프레임 수에 관한 주장은 이 수식에서 나오지 않는다.

### §5.9 innerMask `smoothstep(0.7, 0.5, dist)`

부드러운 경계 선택은 유지하되 구현 표기를 정정한다. W6 §5.2는 `dist`가 이미 `/scaledRadius`로 정규화되어 추가 나누기를 금지한다고 명시한다. 따라서 §5.9 및 종합문의 `dist/iris_radius`는 `dist`로 바로잡아야 한다.

또한 이 식은 중심에서 1이므로 **동공 제외를 단독으로 수행하는 마스크가 아니다.** 기존 iris/pupil 적용 마스크와 교차된 C10 영역 안에서 사용한다는 전제를 유지해야 한다. 이는 C10의 기존 "동공 제외 iris 영역" 조건을 그대로 지키기 위한 확인이다.

### §5.8 3x3 blur

유지한다. §5.2에 제시된 중앙 샘플 가중치 2, 나머지 8개 가중치 1의 합계 10 커널은 9 texel을 읽는 3x3 커널이며 R1의 footprint 결정과 충돌하지 않는다. R2에서 5x5 또는 별도 패스를 다시 열 이유는 없다. 다만 ROI 한정 비용이라는 근거는 구현 후 GPU 측정으로 확인해야 한다.

## 5. 구현 전 재검토 판정

| 결정 | 재검토 필요성 | 구현 전 처리 |
|---|---|---|
| EMA 공식/목표 의미 | **필수 정합성 수정** | 공식은 고정하고 `dt_ms` 기반 API와 로그 검증으로 통일 |
| B5 표본 축소 | 없음 | 정성 판정 범위로 그대로 진행 |
| gate ±0.03 | **설명 수정** | 프레임 평활화 주장을 제거하고 루마 폭으로 문서화 |
| 3x3 blur | 없음 | 3x3 구현 후 성능 로그만 확인 |
| innerMask smoothstep | **필수 정합성 수정** | 정규화 1회: `smoothstep(0.7, 0.5, dist)` |
| 저조도 정의 | 없음 | B9 후보 결과로 threshold 선택 |
| B5/B9 동시 캡처 | **순서 명료화** | C10 후보 프로토타입 → 동시 캡처/분리 판정 → 최종 C10 튜닝 |

**최종 판정:** 네 가지 정합성 수정 후에는 W6 §6의 닫힌 결정을 그대로 구현해도 된다. 결정값을 다시 여는 재논의는 필요하지 않다.
