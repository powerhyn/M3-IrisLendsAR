## 2. 다수결 결정 (2/3 동의)

### 6.1 EMA α → ms 공식 — **`computeEmaAlpha(dt_ms, target_ms) = 1 - pow(0.05, dt_ms / target_ms)` 채택 (Codex+Gemini 2/3)**
- Codex, Gemini: 정밀식 `1 - pow(0.05, dt/target_ms)`, **target = 95% 도달 시간 (5% 잔존 시점)**.
- Claude: `α = 1 - exp(-dt/τ)`, τ = 63% 도달 시간 (time constant 관례).
- **판정:** **Claude 편향 정정**. Codex+Gemini 공식 채택.
- **이유:**
  - (1) 수학적으로 두 공식 모두 유효하지만 "95% 도달" 정의가 **UX 체감 관점에서 직관적** ("80ms 이내에 거의 다 올라와야 함" = 95% 도달 의미).
  - (2) 기존 문서(Codex R3 원문 + W6 §5.1)가 `pow` 형태를 전제.
- **공식 문서화:** W6 §5.1에 **target_ms 정의 "95% 도달 시간"** 명시 추가. 계수 불일치(Codex R3 지적) 해소.
- **실측 검증:** 구현 후 30fps/60fps 실기기 로그로 "80ms 만에 0.95 도달" 확인. `dt`는 실측값 사용 (30fps 고정 가정 금지).

- **Claude 편향 정정 사례 (6.1):** EMA 공식을 time constant 관례(`exp(-dt/τ)`)로 바꾸자는 주관적 해석이 Codex+Gemini 다수에 의해 기존 `pow(0.05,...)` 공식 + "95% 도달 시간" 의미 정의로 수렴. Claude 편향 3번째 정정 사례 (W3 6.3, W5 6.5, W6 6.1).

- **§5.9** gate smoothstep: `smoothstep(threshold - 0.03, threshold + 0.03, avg_iris_luma)`. 폭 ±0.03 대칭.
- **§5.10** blur 커널: 3×3 유지 (single-pass).
