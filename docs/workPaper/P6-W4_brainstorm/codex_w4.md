# P6-W4 브레인스토밍 — Codex 의견

대상: `docs/workPaper/P6-W4_env_reflection_bench.md` §6.1 ~ §6.7

참고: Pupil 체감 판정은 문서 원안대로 재확인한다. `3명 중 2명 이상 Y → P6-W8 착수`, `모두 N → 폐기`, `1명만 Y → 사용자 최종 판단`.

## 6.1 env_map 에셋 제작

- 추천: **일반 실내 사무실/형광 톤의 중립 장면 1장 + 보수적 Reinhard 계열 톤매핑 + 256×128 LDR PNG**.
- 근거: W4 1차 벤치는 env-map 소스의 실패 모드를 보는 단계라 stylized 카페/선셋보다 generic한 실내가 낫다. 벤치 단계에서는 KTX/RGBM보다 단순한 PNG가 제작·교체·비교가 쉽다.

## 6.2 Periphery face_region_mask 근사

- 추천: **옵션 A**. 샘플 포인트를 화면 상단/좌우 가장자리 고정으로 두고 중앙 70%는 자동 제외한다.
- 근거: Codex R3가 지적했듯 `face_region_mask`는 아직 정의되지 않았으므로 1차 벤치에서 detector 기반 동적 마스크를 넣으면 변수가 늘어난다. 먼저 단순 근사로 periphery 자체의 가능성만 본다.

## 6.3 Env map 회전 (reflection_dir 활용)

- 추천: **옵션 A**. W4 1차 벤치는 정적 env로만 진행하고, pose 회전은 2차 검토로 미룬다.
- 근거: 이번 B2의 질문은 `env-map vs periphery vs OFF`라서 env 회전까지 넣으면 소스 비교와 pose 보정 효과가 섞인다. 회전은 env-map이 채택되거나 근소 열세일 때 후속 개선 변수로 보는 편이 맞다.

## 6.4 평가자 3명 구성

- 추천: **아시아 짙은 홍채 1명 + 밝은/중간 홍채 1명 + 개발자/디자이너 1명**.
- 근거: Pupil 체감은 짙은 홍채 평가자가 꼭 필요하고, 자연스러움 일반화와 기술적 위화감 포착을 위해 대조군과 실무자 시각이 같이 들어가야 한다.

## 6.5 촬영 절차 표준화

- 추천: **스크린 레코딩으로 통일하고, 동일 동작 take에서 셰이더 uniform 토글로 3 프로토타입을 캡처한 뒤 클립을 분리·무작위 라벨링해 블라인드 평가한다**.
- 근거: 외부 카메라는 노출/모아레 변수를 추가하고, 별도 APK 3종은 동작 차이를 섞는다. 같은 take에서 분리 캡처해야 소스 차이만 비교되고 블라인드도 유지된다.

## 6.6 클립당 녹화 내용

- 추천: **한 클립은 한 환경 + 한 동작 + 한 프로토타입 + 한 SKU로 고정하고, SKU를 섞지 않는다**.
- 근거: 한 클립 안에 SKU가 섞이면 자연스러움과 Pupil 체감의 원인을 반사 소스와 분리해서 해석할 수 없다. Pupil 집중 SKU와 대조 SKU는 별도 세트로 나누는 편이 낫다.

## 6.7 결과 반영 절차

- 추천: **W4 종료 직후 `99_final_decision.md`의 C5/D3와 W4 문서 결과 표를 함께 업데이트하고, `sampleReflection` no-op 교체는 채택 소스가 확정된 뒤 한 번만 반영한다**.
- 근거: 반사 소스 판정, realSpec 상태, Pupil 2/3 룰 결과가 서로 연결되어 있으므로 문서와 코드 반영을 따로 끊으면 해석이 흔들린다. 특히 W8 착수 여부는 소스 승패와 별개로 2/3 룰을 그대로 적용해야 한다.
