# Gemini의 P6-W2 브레인스토밍: 블렌드 확정 권고안

**작성일**: 2026-04-24
**대상**: docs/workPaper/P6-W2_blend_canonical.md §6

## 1. 미결 사항에 대한 입장 및 권고

### 6.1 ColorReplaceLinear 수식 구현 시점
*   **추천**: **옵션 B (W2에서 수식 및 분기 활성 등록)**
*   **근거**: W5 B1 벤치마크에서 Normal과 CRL을 1:1로 비교하기 위해서는 셰이더 내에 즉시 실행 가능한 코드가 준비되어야 하며, 구조적 기반을 미리 갖춰야 벤치마크 설계의 불확실성을 제거할 수 있음.

### 6.2 ID 3/4/6 빈 슬롯 유지 vs 재번호화
*   **추천**: **옵션 A (기존 ID 유지 및 빈 슬롯 fallback 처리)**
*   **근거**: ID 재번호화는 Java API 및 Android 데모 앱 등 외부 호출부 전반의 수정을 강제하여 불필요한 호환성 리스크를 발생시키므로, 빈 슬롯을 유지하고 기본값으로 유도하는 것이 아키텍처상 안전함.

### 6.3 fallback default를 Normal vs TintLinearV2
*   **추천**: **옵션 B (TintLinearV2)**
*   **근거**: Phase 6의 캐노니컬 블렌드 모드인 TintLinearV2를 기본값으로 설정함으로써, 잘못된 ID가 전송되는 예외 상황에서도 SDK가 지향하는 최적의 렌더링 품질을 일관되게 보장할 수 있음.

### 6.4 LUMA_COEFFS 정합성
*   **추천**: **Rec.709 Linear 계수(0.2126, 0.7152, 0.0722)로 전면 통일**
*   **근거**: TintLinearV2의 노출 정규화 수식이 선형 공간을 전제로 설계되었으므로, 측정(W1)과 렌더링(W2) 전 과정에서 동일한 계수를 사용하여 수치적 무결성을 확보해야 함.

### 6.5 realSpec 복원 경로: 주석 유지 vs 완전 삭제
*   **추천**: **완전 삭제**
*   **근거**: 복원이 필요한 경우 Git 히스토리를 활용하면 충분하며, 셰이더 코드 내에 과거의 해킹성 잔재인 `realSpec` 주석을 남기는 것은 코드 품질과 가독성을 저해하므로 완전히 제거하는 것이 원칙에 부합함.

### 6.6 기본값 블렌드 모드 확정
*   **추천**: **TintLinearV2 (ID 5)**
*   **근거**: 99 §1.1 D6 결정에 따라 TintLinearV2를 SDK의 기본 동작으로 확정하고, Android 데모의 초기 진입 상태 역시 이에 맞춰 동기화하여 사용자에게 최상의 첫인상을 제공해야 함.

### 6.7 Android Demo UI 변화
*   **추천**: **W9 통합 테스트 단계에서 UI 정리**
*   **근거**: W2의 본질은 셰이더 수식 구조의 정립과 선형화에 있으므로, UI 레이어의 클린업은 전체 기능 구현이 완료된 후 통합 검증 단계에서 일괄 처리하는 것이 개발 리소스 관리 측면에서 효율적임.
