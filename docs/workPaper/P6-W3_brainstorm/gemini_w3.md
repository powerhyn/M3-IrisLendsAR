# Gemini의 P6-W3 브레인스토밍: 환경 반사 구조 권고안

**작성일**: 2026-04-24
**대상**: docs/workPaper/P6-W3_env_reflection_scaffold.md §6

## 1. 미결 사항에 대한 입장 및 권고

### 6.1 Fresnel 수식 확정
*   **추천**: **옵션 C (가짜 Fresnel — iris 거리 기반)**
*   **근거**: 각막 노멀을 복원하는 복잡한 연산을 회피하면서도, 홍채 외곽(limbal)으로 갈수록 반사가 강해지는 시각적 특성을 가장 효율적으로 모사할 수 있음.

### 6.2 분석 노멀 계산의 W3 포함 여부
*   **추천**: **제외**
*   **근거**: 6.1에서 옵션 C를 선택함으로써 노멀 연산의 필요성이 사라졌으며, 분석 노멀을 재도입하는 것은 S1에서 해체한 D1(고정 조명) 로직의 변칙적 부활로 비춰질 리스크가 큼.
*   **판단**: 옵션 C는 기존 `dist` 변수를 재활용할 뿐 노멀/라이트 벡터를 재구축하지 않으므로 **D1 재도입이 아님**.

### 6.3 renderMask hook 활성 방식
*   **추천**: **`#ifdef` (컴파일 타임 분기)**
*   **근거**: W8 Pupil material 복구는 조건부 트랙이므로, 사용하지 않는 코드를 바이너리에서 완전히 배제하여 셰이더를 가볍게 유지하고 런타임 오버헤드를 제로화하는 것이 유리함.

### 6.4 sampleReflection 함수 추상화 방식
*   **추천**: **방식 A (Uniform `uSourceType` 스위치)**
*   **근거**: W4 B2 벤치마크 수행 시 실시간으로 소스(EnvMap/Periphery/OFF)를 토글하며 정성적인 품질 차이를 즉각적으로 비교하기 위해 단일 바이너리 내 분기가 가장 적합함.

### 6.5 reflectUV 계산 수식
*   **추천**: **옵션 C (iris local 좌표)**
*   **근거**: 홍채 영역의 좌표를 그대로 반사 소스 UV로 매핑하는 것이 노멀 연산 없이 가장 직관적인 반사 투영을 가능케 하며, 벤치마크용 env-map이나 periphery 샘플링에 충분한 품질을 제공함.

### 6.6 env_map 에셋 크기 및 포맷
*   **추천**: **256×128 LDR (PNG/RGB), SDK 내장**
*   **근거**: 각막 반사의 흐릿한 특성상 고해상도나 HDR 정보가 필수적이지 않으며, SDK 내장 에셋으로 관리하여 외부 의존성 없이 즉시 벤치마크 환경을 구축할 수 있음.

### 6.7 B2 벤치 매트릭스 draft 준비
*   **추천**: **수용 (4개 환경 × 2개 동작 × 3개 프로토타입)**
*   **근거**: W3 단계에서 매트릭스를 확정해야 W4 진입 즉시 프로토타입 구현과 검증에 집중할 수 있으며, 특히 Gemini가 강조하는 '실시간 기기 체감' 데이터 수집을 가속화할 수 있음.
