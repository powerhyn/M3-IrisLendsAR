# Gemini의 P6-W1 브레인스토밍: 미결 사항 권고안

**작성일**: 2026-04-24
**대상**: docs/workPaper/P6-W1_eye_render_packet.md §6

## 1. 미결 사항에 대한 입장 및 권고

### 6.1 측정 경로: CPU 1회 vs shader 내
*   **추천**: **옵션 A (CPU 1회)**
*   **근거**: 홍채 루마는 프레임 간 변화가 급격하지 않아 1프레임 지연이 시각적 품질에 미치는 영향이 미미하며, GPU 대역폭과 셰이더 연산 부하를 절약하는 것이 모바일 환경에서 더 유리함.

### 6.2 ROI 마스크 구체: `inner iris r<0.65 AND eyelidMask` 충분?
*   **추천**: **r < 0.55로 반경 축소 및 0.3~0.7 범위 클램핑 적용**
*   **근거**: r < 0.65는 동공이 확장된 경우 어두운 픽셀이 유입될 위험이 있음. 보다 보수적인 0.55 반경을 사용하고, 극단적인 이상치 유입을 막기 위해 최종 luma 값을 유효 범위로 제한해야 함.

### 6.3 Fallback 중립 상수 값
*   **추천**: **0.35 (옵션 α)**
*   **근거**: 기존 Codex R2에서 제안된 값이며 한국인 등 아시아인 사용자의 평균 홍채 명도에 근사함. 실측 실패 시 급격한 노출 변화를 방지하는 가장 검증된 보수적 수치임.

### 6.4 어댑터 레이어 위치
*   **추천**: **옵션 1 (`cpp/src/gpu/eye_render_packet_adapter.{h,cpp}`)**
*   **근거**: `EyeRenderPacket`은 렌더러 전용 인터페이스이므로 GPU 네임스페이스 내에 위치시키는 것이 아키텍처상 응집도가 높고 SDK 공통 영역의 오염을 방지함.

### 6.5 시간적 스무딩 중복 체크 (avg_iris_luma EMA)
*   **추천**: **렌더러 내부에서 EMA(α=0.3) 적용**
*   **근거**: 루마는 'Material 속성'이므로 렌더러가 스스로의 시간적 봉투(Temporal Envelope)를 관리하는 것이 원칙에 부합하며, 블링크 시 발생하는 급격한 수치 튀기를 방지해 W2 블렌딩 안정성을 확보함.

### 6.6 head_pose_yaw_roll / reflection_dir optional
*   **추천**: **스키마에 포함하되 W1에서는 구현 스킵**
*   **근거**: 인터페이스 고정(Interface Freeze)이 W1의 핵심 목표이므로 필드는 미리 정의하되, 실제 활용은 후속 W4 벤치마크 단계에서 구현하여 불필요한 조기 최적화를 방지함.

### 6.7 render_confidence optional 설계
*   **추천**: **TemporalStabilizer의 기존 신뢰도 지표 재활용**
*   **근거**: 상위 계층인 `TemporalStabilizer`가 이미 계산한 기하학적 신뢰도를 패킷에 담아 전달함으로써, 렌더러가 별도 연산 없이도 측정값 유지(Hold) 여부를 판단할 수 있는 일관된 기준을 제공함.

## 2. W8 Pupil 조건부 트랙에 미치는 영향

1.  **인터페이스 선점**: W1에서 `pupil_center_norm`을 optional로 확정함으로써, 추후 W8에서 동공 정렬(Alignment) 기능을 추가할 때 공개 API나 렌더러 인터페이스를 다시 수정할 필요가 없는 구조적 기반을 마련함.
2.  **신뢰도 기반 제어**: 6.7의 `render_confidence` 도입은 W8에서 동공 영역의 렌더링 마스크를 복구하거나 보정할 때, 검출 상태에 따라 부드럽게 전환(Alpha Hysteresis)할 수 있는 핵심 트리거가 됨.
3.  **데이터 무결성**: 6.2의 ROI 마스크 강화 결정은 동공 정보를 홍채 평균에서 분리해내는 과정이므로, 향후 W8에서 동공 전용 Material을 적용할 때 데이터 오염 없는 순수한 홍채 기준값을 제공함.
