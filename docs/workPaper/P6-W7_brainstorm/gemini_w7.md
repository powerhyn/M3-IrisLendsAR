# Gemini의 P6-W7 브레인스토밍: 림발 정책 권고안

**작성일**: 2026-04-24
**대상**: docs/workPaper/P6-W7_limbal_policy.md §6

## 1. 미결 사항에 대한 입장 및 권고

### 6.1 자동감지 ROI 경계 튜닝 ([0.85, 1.0] vs [0.80, 1.0])
*   **추천**: **[0.85, 1.0] 유지**
*   **근거**: 림발은 홍채의 가장 바깥쪽 경계에 집중되어 있으므로 범위를 너무 넓히면 홍채 내부 그래픽 패턴이 평균 루마에 간섭하여 감지 정확도를 떨어뜨릴 리스크가 있음.

### 6.2 임계값 0.75 튜닝 (0.70 / 0.75 / 0.80)
*   **추천**: **0.75 (기본)**
*   **근거**: 15_asset_analysis.md 실측 결과 대다수 에셋이 림발을 포함하지 않으므로, 지나치게 엄격한 0.70보다는 0.75가 미세하게 베이크된 림발을 잡아내기에 더 적절한 균형점임.

### 6.3 메타데이터 저장 방식 (JSON vs 하드코드 vs 파일명)
*   **추천**: **JSON 파일 (`lens_sku_metadata.json`)**
*   **근거**: 에셋 업데이트 시 바이너리 재빌드 없이 메타데이터만 교체하여 즉시 반영할 수 있고, 하드코드 방식보다 구조적 확장성이 뛰어나 향후 Phase 7+ 설정 추가에도 유리함.

### 6.4 메타 누락 경고 로그 레벨 (DEBUG / WARN / ERROR)
*   **추천**: **WARN**
*   **근거**: 림발 정책은 시각적 품질과 직결되므로 개발 단계에서 누락 사실을 명확히 인지해야 하지만, 런타임에 앱이 중단되어서는 안 되므로 경고 로그 수준이 가장 적절함.

### 6.5 9/10 vs 10/10 엄수 (Gemini 완화안)
*   **추천**: **9/10 완화안 수용**
*   **근거**: 10/10은 실기기 환경의 노이즈나 텍스처 압축 손실을 고려할 때 과도하게 엄격한 기준임. 9/10 도달 시에도 fallback으로 채택하되, 오판된 1개에 대해 임계값 튜닝으로 10/10을 지향하는 전략이 현실적임.

### 6.6 엔비_샤모 브라운 특별 처리
*   **추천**: **`prefers_graphic_outline = true` 플래그로 셰이더 림발 강제 OFF**
*   **근거**: 그래픽 아웃라인이 강한 SKU는 셰이더 기반 림발이 중첩될 경우 디자인 의도가 완전히 왜곡되므로, 자동감지 결과와 무관하게 메타데이터로 렌더링 개입을 차단해야 함.

### 6.7 B10 신규 벤치 추가 여부
*   **추천**: **기각 (추가 안 함)**
*   **근거**: 99 합의본에서 이미 제외된 사항이며, R1~R3를 거치며 Claude의 편향이 3번이나 뒤집힌 끝에 도달한 B4 자동감지 fallback 체제만으로도 정책 확정에는 충분함.

## 2. 세션 간 맥락: Claude 편향 교정 인식

본 권고안은 Claude가 Phase 6 동안 림발 정책(기본 OFF → ON → 자동감지 이관 → 실측 후 재검토)에 대해 보여준 입장 변화를 충분히 고려하였습니다. 에셋 실측 결과 대다수가 림발을 포함하지 않는다는 점을 수용하여, **"기본 ON" 체제를 유지하되 SKU 메타데이터와 자동감지 fallback으로 정교함을 더하는 R4 최종 합의안**을 엄수합니다.
