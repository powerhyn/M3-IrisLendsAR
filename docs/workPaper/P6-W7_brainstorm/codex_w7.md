# P6-W7 브레인스토밍 — Codex 의견

대상: `docs/workPaper/P6-W7_limbal_policy.md` §6.1 ~ §6.7

참고: 이 축은 R1→R4 동안 **Claude 판단이 3번 뒤집힌** 영역이라, W7에서는 새 해석보다 `99_final_decision.md`의 경계와 실측 결과를 더 엄격히 따른다.

## 6.1 자동감지 ROI 경계 튜닝

- 추천: **기본값 `[0.85, 1.0]` 유지**.
- 근거: 자동감지의 리스크는 false positive라서 edge band를 더 안쪽으로 넓히는 `[0.80, 1.0]`보다 가장자리만 보는 편이 안전하다. W7의 질문은 fallback 가능 여부이지 탐지 recall 극대화가 아니다.

## 6.2 임계값 `0.75` 튜닝

- 추천: **`0.75` 유지**.
- 근거: 99 합의본의 기준값이 이미 이 값으로 닫혀 있고, W7에서 추가 완화까지 동시에 하면 `10/10` 엄수 여부와 변수 분리가 안 된다. 먼저 ROI/threshold 기본축은 고정한 채 정확도만 본다.

## 6.3 메타데이터 저장 방식

- 추천: **코드 내 하드코드 레지스트리 (`LensSkuRegistry`)**.
- 근거: W7 메타는 내부 material 모델 필드이고 대상 SKU도 소수라 외부 JSON 파이프라인을 새로 열 이유가 없다. 이 축은 이미 판단이 흔들린 곳이라 편집 편의성보다 결정적이고 버전 고정된 소스가 낫다.

## 6.4 메타 누락 경고 로그 레벨

- 추천: **WARN**.
- 근거: 메타 누락은 품질 리스크이지만 앱 동작 자체를 중단할 수준은 아니다. DEBUG는 조용하고 ERROR는 과하므로 개발자가 즉시 인지하되 사용자 플로우는 깨지지 않는 WARN이 적절하다.

## 6.5 Gemini 완화안 채택 여부

- 추천: **`10/10` 엄수**.
- 근거: 99 합의본이 이미 `9/10 이하 → 자동 감지 드롭`으로 닫았고, 이 쟁점은 Claude 편향이 가장 많이 흔들린 축이라 기준을 풀 이유가 더 없다. fallback은 "드문 메타 누락"용이므로 false positive 1회도 비싸다.

## 6.6 엔비_샤모 브라운 특별 처리

- 추천: **`prefers_graphic_outline = true` 별도 플래그를 두고, 셰이더 림발은 그대로 OFF로 간다**.
- 근거: 이 SKU는 일반 baked limbal이 아니라 의도된 강한 그래픽 아웃라인 예외라서 일반 규칙에 흡수하면 오판정이 난다. 특별 처리는 새 기능이 아니라 예외 SKU를 메타로 명시하는 수준이면 충분하다.

## 6.7 ~~B10 신규 벤치 필요성~~

- 추천: **추가하지 않는다. W7 out of scope 유지**.
- 근거: `P6-W0_index.md`와 본문이 이미 `B10 신규 벤치`를 W7 범위 밖으로 닫았다. 이 축에서 다시 벤치를 열면 R1~R3에서 흔들린 논점을 W7이 재개하는 셈이라 범위 통제가 깨진다.
