## R2 핵심 타깃 (의견이 갈렸던 2개)

### T1 — 6.3 메타 저장: JSON(다수) vs 하드코드 레지스트리(Codex 소수)

- **Codex에게:** R1 하드코드 `LensSkuRegistry` 주장 유지하는가? JSON 다수안의 완화 조치(git 체크인 버전 고정 + default false fallback + WARN 로그)가 당신의 "버전 고정/결정적 소스" 우려를 충분히 흡수하는가? 유지한다면 그 완화로도 안 되는 구체적 위험은?
- **Gemini/Claude에게:** Codex의 "내부 material 필드를 외부 JSON 파이프라인으로 여는 것이 과한가" 비판에 답하라. JSON이 정말 재빌드 사이클 제거 가치가 있나, 아니면 SKU 소수(20개)라 하드코드가 더 단순한가?

### T2 — 6.5 자동감지 정확도: 10/10 엄수(다수) vs 9/10 완화(Gemini 소수)

- **Gemini에게:** R1 9/10 완화안 유지하는가? R4 실기기 "10/10 달성" 팩트 앞에서 "실기기 노이즈/압축 손실 우려"가 여전히 유효한가? 다수안의 "10/10 엄수 + 실패 SKU만 개별 메타 fallback"이 당신의 노이즈 우려를 흡수하지 못하는 지점은?
- **Codex/Claude에게:** Gemini의 "10/10은 과도하게 엄격" 비판에 답하라. 10/10 엄수가 실제로 운영에서 너무 빡빡해 메타 fallback이 남발될 위험은 없나?
