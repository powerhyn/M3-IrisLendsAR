## 2. Critical 수정 필요 (Hard findings)

## 3. 권장 수정 (Soft findings)

- **[P6-W1] [§1.6]**: `IrisResult` → `EyeRenderPacket` 어댑터 레이어 구현 시, `IrisResult`의 기존 필드 중 `confidence`가 `render_confidence`로 매핑되는 로직을 명시하면 더 명확할 것 같습니다.
- **[P6-W6] [§1.4]**: EMA α 계산 공식 `3 / (fps * target_sec)`은 근사치입니다. §5.1의 `pow` 기반 정밀 공식으로 통일하여 혼선을 방지하는 것이 좋습니다.
- **[P6-W7] [§1.2]**: 텍스처 리사이징(256x256)이 CPU 자동 감지(B4)의 정확도에 미치는 영향(다운샘플링 시 림발 경계 뭉개짐 등)을 벤치 시 고려해야 한다는 노트를 추가하면 좋을 것 같습니다.

## 4. W 간 충돌 / 불일치

- **일관성 확인**: P6-W3에서 정의한 `renderMask` hook의 예시 수식과 P6-W8에서 제안한 Option E 수식의 `centerProximity` 범위가 상호 보완적으로 작동하는지 확인했습니다. (충돌 없음)
- **반사 계층 순서**: 모든 문서에서 `블렌드 → 디테일 재주입 → 환경 반사` 순서가 일관되게 유지되고 있습니다.

## 5. 누락된 결정 / 쟁점

- **텍스처 리사이징 공급**: R4 Patch 5의 "사용자 직접 리사이징 공급" 결정이 P6-W0 §1.2에 반영되어 있으나, 실제 에셋 로딩을 담당하는 W7이나 통합을 다루는 W9의 목표에 "리사이징 가이드 전달" 또는 "규격 검증" 항목으로 포함되면 더 완벽할 것입니다.

## 6. 전체 구조 피드백

- **W 분할**: 벤치와 구현을 논리적/시간적 의존성에 따라 매우 조밀하게 잘 나눴습니다. 특히 W4의 Pupil 체감 수집을 조건부 W8의 트리거로 설정한 구조가 합리적입니다.
- **가독성**: 섹션 1(인사이트)의 요약이 매우 훌륭하여 새 세션 재개 시의 컨텍스트 스위칭 비용을 최소화했습니다.

## 7. 이 리뷰에서 자기 편향 가능성 (메타 인지)

- **Pupil Cutout (W8)**: 본 리뷰어(Gemini)는 R2/R3에서 이 기능의 W3-05 포함을 강력히 주장했습니다. 리뷰 과정에서 W8이 "조건부"로 밀려난 것에 대해 비판적 시각을 견지하려 했으나, W4 벤치 지표와 연동된 "Hard 착수 조건" 설계가 내 우려를 충분히 실용적으로 해소하고 있다고 판단하여 수용했습니다.
- **Periphery Sampling (W4)**: 벤치 설계에서 `env-map-only` vs `periphery-only` 대결 구도가 내 R3 지적대로 명확히 잡혀 있는 것을 확인했습니다.
