## 2. Critical 수정 필요

- [W1 §5.2, W2 §5.1/§5.3, W6 §5.2]: `avg_iris_luma` 색공간 계약이 불명확하다. W1은 `LUMA_COEFFS = Rec.709 linear`라고 쓰지만 W2는 `uAvgIrisLum * uAvgIrisLum`로 다시 선형화한다. W1 출력이 sRGB luma인지 linear luma인지 하나로 고정하고, W2/W6 수식을 그 계약에 맞춰야 한다.
- [W1 §5.5]: 공개 C API 예시 `iris_sdk_render_lens_gpu`는 현재 코드의 exported API가 아니다. `iris_sdk_render_lens_texture`/`iris_sdk_render_with_result` 등 실제 이름으로 고치거나 명시적으로 pseudocode라고 표시해야 한다.
- [W3 §5.3, W6 §5.2, W8 §5.4]: 기존 shader의 `dist`는 `distance()/scaledRadius`로 이미 0~1 정규화된 값이다. `dist / iris_radius`, `smoothstep(iris_radius * 1.2, 0.0, dist)`는 좌표계를 섞는다. `dist_norm`/`dist_px`를 분리해 모든 예시 수식을 정정해야 한다.
- [W7 §2.3, §6.7]: B10 신규 벤치와 “기본 ON vs OFF 최종 판정”이 W7 목표로 다시 들어왔다. 99의 범위는 B4 자동감지 fallback + 내부 SKU 메타데이터다. B10은 제거하거나 명확히 out of scope로 내려야 한다.

## 3. 권장 수정

- [W0]: §2~§8 stub은 의도된 상태지만, 최소한 W별 파일명/선행조건/착수 순서 표는 채우는 편이 새 세션 안전성이 높다.
- [W2]: `ColorReplaceLinear`는 “함수만 존재, 호출/등록 대기”인지 “ID 7 분기 등록”인지 문구가 섞인다. B1 전 상태를 한 문장으로 통일해야 한다.
- [W4]: 72개에서 24개로 줄인다고 했으나 최종 24개 SKU/환경 조합이 고정되어 있지 않다. 벤치 직전 혼선을 막도록 matrix를 닫아야 한다.
- [W6]: EMA 본문 초반의 `α≈0.22` 설명은 §5.1의 `1 - pow(0.05, dt/target)` 공식과 충돌한다. 잘못된 근사 설명은 제거해야 한다.
- [W6]: front matter 선행 의존에 W1을 추가해야 한다. B9/C10은 `avg_iris_luma` 없이는 실행 의미가 없다.
- [W8]: 과거 명칭 `P6-W1 조건부 트랙`이 여러 군데 남아 있다. 현재 문서명 기준 `P6-W8`로 통일해야 한다.
- [W9]: deprecated no-op 제거 시점이 W9/Phase7 사이에서 흔들린다. “W9에서는 유지, 별도 PR에서 제거”처럼 하나로 닫는 편이 낫다.

## 4. W 간 충돌 / 불일치

- W1/W2/W6의 luma 색공간 계약이 하나로 닫히지 않았다. 이건 블렌드와 저조도 gate를 동시에 흔드는 공통 결함이다.
- W3/W6/W8의 거리 변수 좌표계가 불일치한다. 현재 코드 기준으로는 정규화 `dist`를 쓰는 문서와 픽셀/반경 단위 수식이 섞였다.
- W7이 99에서 닫힌 C6 범위를 다시 넓힌다. “실측 재검토 여지”와 “새 벤치 추가”는 다르다.

## 5. 누락된 결정 / 쟁점

치명적 누락은 위 Critical 항목 외에는 보이지 않는다. 다만 W1의 fallback 0.35는 “Codex R2 값”처럼 확정 출처로 쓰지 말고 “last resort TBD”로 낮춰야 한다.

## 6. 전체 구조 피드백

W grain은 적절하다. W1 기반, W2/W3 구조, W4~W7 병렬 벤치, W8 조건부, W9 통합 순서도 실행 가능하다. 문서는 길지만 §1 인사이트와 §7 체크리스트가 있어 새 세션 입력으로는 충분하다. 다만 §6 미결 사항에 “Claude 추천”이 많아 다음 라운드에서 추천이 결정처럼 읽힐 위험은 있다.

## 7. 자기 편향 가능성

내 R1~R4 입장 때문에 `avg_iris_luma`, realSpec 폐기, 림발 자동감지 엄격 기준에 과가중했을 가능성은 있다. 그래서 Critical은 코드 기준으로 확인 가능한 색공간/API/좌표계 오류와 99 범위 재개방에만 제한했다.

## 8. Hard Veto 유무

**없음.** P6 전체 착수를 막을 수준은 아니다. 단 W1/W3/W6/W7/W8은 위 Critical 수정 없이 해당 W 구현으로 들어가면 잘못된 코드나 범위 재논의로 바로 이어진다.
