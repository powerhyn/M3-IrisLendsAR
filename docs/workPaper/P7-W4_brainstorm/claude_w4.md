## 6.1 재베이스라인 gating — **W4 첫 작업으로 필수, "잔존 미미"면 코드 0줄 조기 종결**

**추천**: 코드 작성 전에 S23+에서 SKU 2/5/6 재베이스라인. W2의 `lum:fb↔lum:meas` 토글이 보존돼 있어 **W9 당시 조건(fallback) 재현 vs 현재(실측)를 같은 자리에서 즉시 비교 가능** — 별도 인프라 불요.

- **(a) 잔존 뚜렷** → 원안 진행.
- **(b) 잔존 미미** → **코드 추가 없이 조기 종결 + Spike-A 미진행 + P8 진입 권고**. 1단계 lightweight 원칙의 가장 lightweight한 결말은 "불필요해진 작업을 안 하는 것".

**"잔존 미미" 판단 기준 제안**: 가장 강한 SKU 6에서 본인 토글 체감으로 "거슬리지 않음" — solo-dev-bench-method상 이것이 유일하게 의미 있는 기준. 수치 기준(픽셀 luma 차) 도입은 반대 — 정성 체감 우선 (메모리 `qualitative-device-judgment`).

**어두운 환경(avgLum<0.12, clamp 7.0 영역)**: W4 범위 제외. 메모리 `low-light-usage-rare` — 뷰티 시뮬레이션 사용 환경은 밝음. 어두운 환경의 빛남은 fallback 시절과 동일 메커니즘이라 W9 관측과 같고, 사용 빈도가 낮아 1단계 대상 아님.

## 6.2 수식 형태 — **(c) 비율 clamp 상한 추천** (인덱스 원안 (a) 대신)

```glsl
float scale = clamp(0.85 / max(0.01, uAvgIrisLum), 0.8, 7.0);
float ratio = min(lum * scale, 0.85 * uTintRatioCap);   // cap: 무차원 비율 상한
vec3 tinted = toLinearFast(blend) * ratio;
```
(동치 표현: `tinted = lensL · 0.85 · min(lum/avgLum, cap)` — 단 clamp 7.0 포화 구간에선 `lum·scale` 기준이 실제 증폭량이므로 위 형태가 안전)

**근거**:
1. **원인 직접 차단**: 빛남의 직접 원인은 "비율 무상한"(§1.2). (a)는 증폭을 놔두고 상수(0.85)를 곱하는 것 — 증폭이 3~5배인 픽셀에 15% 감쇄는 체감 불가, 체감시키려면 A를 0.5 이하로 내려야 하고 그러면 경계 부자연 위험.
2. **설계 의도 보존**: brightness-invariant 틴트(W2 §5.6)의 "iris 내부 비율≈1" 동작은 그대로, 상한만 명시. `refactor-vs-retune` 정합 — 수식 해체가 아니라 재조율.
3. **변수 최소화의 연쇄 효과**: smoothstep 임계 2개(0.65/0.85)·luma 공간 선택·attenuation 강도가 전부 불필요해지고 **cap 1개**만 남음 → §6.3·§6.5·§6.7 쟁점이 소멸 또는 대폭 단순화.
4. **CRL과 일관**: ID=7의 `detail clamp(…, 0.75, maxDetail)`과 동형 구조 — 코드베이스에 이미 검증된 패턴.
5. **변경량 최소**: `blendTintLinearV2` 1~2줄 + uniform 1개. (a)의 sclera_factor 계산보다 작음. GPU 비용 min() 1회.

**cap 초기값**: 1.5 제안 (sclera lum/iris avgLum 실측 분포 로그 후 1.5/2.0/무제한 토글 비교 — W2 디버그 로그 인프라 재사용). **(d) alpha 감쇄는 반대** — 그래픽 outline SKU(5 샤모)의 외곽 디자인이 소실되며, 림발·외곽은 에셋 책임 원칙(메모리 `limbal-in-asset-not-shader`)과 충돌. 기존 geometry veto가 이미 alpha 역할 담당.

## 6.3 luma 공간 + 임계 — **(c) 채택 시 쟁점 소멸. (a) 강행 시 linear Rec.709 + 임계 하향 필수**

- (c)면 `lum`·`uAvgIrisLum` 모두 이미 linear Rec.709로 정합(W2 §5.7 측정=정규화 계약) — 추가 결정 없음.
- (a) 강행 시: **linear Rec.709** (블렌드 내부 `lum` 재사용, 추가 계산 0, sRGB 0.299 계수는 veto 쪽 레거시일 뿐). 단 **임계 (0.65, 0.85)는 sRGB 감각의 수치** — linear에선 sRGB 0.82~0.93에 해당해 흰자 대부분(sRGB 0.7~0.9 = linear 0.45~0.8)이 안 걸림. linear 기준 (0.4, 0.7) 수준으로 하향 후 실측 보정 필요.

## 6.4 기존 veto와 결합 — **변수 분리: B8 판정은 W4에 포함하지 않음**

- W2 §5.6 전례(측정과 상수 동시 변경 금지)와 동일 원리: **한 번에 한 변수**. W4 벤치는 `uScleraVetoMode=0`(현 기본) 고정으로 진행해 교란 차단.
- B8 판정(0→1/2 단일화)은 W4 결과 후 별도 처리 — W4가 빛남을 줄이면 veto에 남는 역할(외곽 alpha)이 명확해져 B8 판정이 오히려 쉬워짐.
- 이중 감쇄 우려는 (c)에선 해당 없음 — (c)는 "감쇄"가 아니라 "증폭 상한"이라 veto(alpha)와 작용 축이 완전 분리.

## 6.5 iris 내부 밝은 픽셀 — **(c)에서 허용 (오발 아님), geometry 보조 게이트 불요**

- 하이라이트 픽셀: 비율이 cap에 걸려 틴트가 상한 — 실제 물리(강한 반사가 렌즈색을 씻어냄)와 부합해 오히려 자연.
- 밝은 홍채(밝은 환경 avgLum~0.6): iris 내부 비율≈1이라 cap(1.5)에 안 걸림 — 구조적으로 안전.
- (a)+강한 attenuation이었다면 하이라이트가 칙칙해지는 위험이 더 컸음 — (c) 선호의 보조 근거.

## 6.6 적용 범위 — **ID=5만. 순서는 W4 먼저 → ID=7 결정**

- Multiply(ID=1)는 어두워지는 방향이라 빛남 무관, ScreenLinear(ID=2)는 밝아짐 자체가 수식 의도, CRL(ID=7)은 detail 상한(≤1.25)이 이미 있어 증폭 구조가 다름(최대 1.25배) — 공통 적용 불요.
- **순서**: 빛남 있는 ID=5와 CRL을 비교하면 CRL이 과대평가됨 → W4로 ID=5 개선 후 B1 재비교가 공정. 사용자가 W3에서 "blend dropdown 축소는 P7-W4 후"로 보류한 결정과 정합.

## 6.7 SKU별 오버라이드 — **글로벌 단일값 시작, 1차 메타 도입 반대**

- W5 §5.10 전례("1차에서 clamp 튜닝 금지 — 변수 배제")와 동일 원리. (c) 채택 시 파라미터가 cap 1개뿐이라 SKU별 분기 필요성 자체가 낮음.
- 1차 결과 특정 SKU만 과/부족이 확인되면 그때 `has_baked_limbal`/`prefers_crl` 패턴으로 후속 — 진입점만 문서에 명시.
