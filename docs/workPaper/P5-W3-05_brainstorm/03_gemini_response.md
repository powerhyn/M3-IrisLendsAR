# Gemini 렌즈 렌더링 자연스러움 브레인스토밍 응답 (R1)

## 한 줄 결론
현재의 "스티커" 느낌을 벗어나려면 정적인 분석적 조명을 버리고, **카메라 프레임을 재활용한 실시간 환경 반사(Screen-space Reflection)와 선형 공간 기반의 하이라이트 보존 블렌딩**으로 전환해야 합니다.

## 핵심 주장 (3~5개)
- 분석적 구면 노멀은 지나치게 매끄러워 가짜 티가 나므로, 각막(Cornea)과 홍채(Iris)의 이중 레이어 구조를 흉내 낸 **이중 노멀 굴절(Refraction)**이 필요합니다.
- 블렌드 모드는 8종에서 **3종(Natural, Opaque, Tint)으로 압축**하고, 나머지는 수학적 하위 호환으로 흡수해야 합니다.
- 하이라이트 보호는 Hard Threshold(>0.7)가 아닌 **휘도 기반 부드러운 전이(Luminance-based Soft-roll) 전략**을 취해야 합니다.
- **림발 다크닝은 셰이더에서 동적으로 제어**되어야 하며, 텍스처 의존도를 낮춰야 합니다.

## 축별 결론

### 축 A — 광학 리얼리즘
- **추천: 카메라 프레임 샘플링 기반의 가짜 SSR (Screen-space Reflection)**
  - **무엇**: 현재 프레임의 고휘도 영역(조명원)을 다운샘플링하여 환경맵처럼 사용하고, 이를 렌즈 표면에 반사시킴.
  - **근거**: 사용자의 실제 조명 환경(창문, 형광등 등)이 렌즈에 맺혀야 "그 자리에 있음"이 성립됨. Perfect의 IBL은 정적이라 실시간 환경 변화에 대응 불가.
  - **비용**: 저 (기존 프레임 텍스처 재사용, 저해상도 Mipmap 수준 샘플링 1회)
  - **리스크**: 저조도 환경에서 노이즈가 반사로 보일 수 있음.
  - **기각한 대안**: HDR IBL (에셋 용량 증가 및 현재 환경과의 불일치), 분석적 노멀 단독 사용 (이미 Claude가 구현했으나 "플라스틱 공" 느낌을 지우지 못함).
- **기각**:
  - **풀 PBR**: 모바일 온디바이스에서 렌즈 하나를 위해 렌더링 파이프라인 전체를 PBR로 바꾸는 것은 배보다 배꼽이 더 큼.
  - **사전 베이크 노멀**: 홍채 크기와 각도가 가변적인 상황에서 텍스처 기반 노멀은 샘플링 오버헤드만 늘릴 뿐 분석적 수식보다 유연하지 않음.

### 축 B — 블렌드 모드 (4종 이하 최종 세트)
- **최종 세트 (3종)**:
  1. **LTL (LuminanceTintLinear+)**: (기존 ID 5 개선형) 선형 공간에서 베이스 디테일을 보존하며 색을 입힘. "내 눈 같은 렌즈"의 90%를 커버.
  2. **Circle (Normal-Overlay Hybrid)**: 렌즈 테두리는 불투명하게(Normal), 안쪽은 대비를 살려(Overlay) 합성. "서클렌즈/코스프레"용.
  3. **Vivid (SoftLight-Multiply)**: 짙은 홍채 위에서 색 발색을 극대화하면서도 이질감을 줄인 혼합형.
- **드롭**: 
  - **Multiply/Screen**: LTL이 선형 공간에서 에너지 보존을 수행하므로 이 둘의 역할을 더 정확하게 대체함.
  - **ColorReplace**: 디테일을 다 날려버리므로 AR의 목적인 "자연스러움"에 위배됨.
- **신규/대체**: **Energy-Conserving LTL**. 단순히 0.7로 자르는 것이 아니라, `1.0 / (1.0 + exp(-10.0 * (lum - 0.7)))` 식의 시그모이드 함수로 하이라이트를 부드럽게 보존.
- **기본값 1개**: **LTL**. 가장 물리적으로 타당하며 사용자 만족도가 높음.

### 축 C — 경계·마스킹
- **추천: 동적 림발 링(Dynamic Limbal Ring) 생성기**
  - **무엇**: 텍스처의 알파값과 상관없이 셰이더에서 홍채 외곽에 `1.0 - smoothstep` 기반의 어두운 띠를 강제로 입히되, 텍스처 자체의 밝기에 반비례하게 강도 조절.
  - **근거**: 경쟁사 렌즈들이 자연스러운 이유는 홍채와 흰자의 경계가 명확하기 때문임. 텍스처에 맡기면 품질 편차가 너무 큼.
  - **비용**: 초저 (수식 1줄)
  - **리스크**: 이미 림발이 두꺼운 디자인의 렌즈에서 과하게 어두워질 수 있음 (자동 억제 로직 필수).
- **기각**:
  - **별도 속눈썹 패스**: 검출 모델이 속눈썹을 분리하지 못하는 이상, 단순 알파 맵은 역효과. 눈꺼풀 마스크만 정교화하는 것이 비용 효율적.
  - **Sclera Protect 색상 기반 방식**: 조명 변화에 따라 흰자 색이 변하므로 기하학적 마스크(`r>0.75`)가 훨씬 안정적임.

### 축 D — 시간적 안정성
- **추천: 조명 파라미터 및 하이라이트 지연 스무딩**
  - **무엇**: 좌표뿐만 아니라 조명의 방향(lightDir)과 반사 강도에 지수 이동 평균(EMA) 적용.
  - **근거**: 눈은 미세하게 떨리는데(Saccade), 이때 반사광이 같이 떨리면 "가짜"임이 바로 들통남.
- **기각**: **전체 렌즈 페이드**. 블링크 시 페이드를 주면 렌즈가 눈꺼풀 위로 투영되는 것처럼 보임. 블링크는 즉시 Off가 맞음.

### 축 E — 입력 계약
- **추천: Gaze Vector(시선 방향) 추가**
  - **무엇**: 홍채 중심뿐만 아니라 사용자가 어디를 보는지에 대한 3D 벡터를 입력받아, 렌즈 텍스처에 미세한 Parallax(시차) 오프셋 적용.
  - **근거**: 정면을 볼 때와 측면을 볼 때 홍채와 각막 사이의 깊이감 차이가 자연스러움의 핵심임.
- **기각**: **Pupil Center 별도 입력**. 홍채 중심과 동공 중심은 대개 일치하며, 불일치 시 렌더러가 이를 보정하기엔 데이터가 부족함.

### 축 F — 성능
- **추천: Single-pass + LUT (Look-Up Table)**
  - **무엇**: 복잡한 sRGB <-> Linear 변환 및 선형 하이라이트 계산을 1D LUT 텍스처로 베이크하여 연산량 감소.
  - **비용**: 중 (초기 구현 필요), 런타임 이득 (Adreno 등에서 ALU 부하 감소).

### 축 G — 와일드카드
- **추천: 절차적 홍채 디테일 주입 (Procedural Iris Fibers)**
  - **무엇**: 렌즈 텍스처가 뭉개놓은 사용자 홍채 무늬를 대신해, 셰이더에서 아주 미세한 노이즈로 방사형 섬유 조직을 덧입힘.
  - **근거**: 렌즈를 끼면 홍채 무늬가 사라져서 "눈"이 아니라 "플라스틱"처럼 보임. 가짜로라도 결(Texture)을 살려야 함.

## Claude가 W3-04까지 해놓은 것 중 틀렸다고 보는 것
1. **LuminanceTintLinear의 실반사 보호 방식**: `spec > 0.7`에서 `1.0`으로 믹스하는 방식은 0.69와 0.71 사이에서 계단 현상(Aliasing)을 유발함. 반드시 smoothstep이나 시그모이드로 처리해야 함.
2. **분석적 노멀의 단순성**: 현재 구면 노멀은 `z = sqrt(1.0 - x*x - y*y)` 식일 텐데, 실제 눈은 각막 부분만 더 튀어나온 비구면임. 이 곡률 차이가 반사광의 모양을 결정하는데, 현재는 너무 정직한 원형 하이라이트만 나옴.
3. **고정 조명 `vec3(0.3, 0.4, 1.0)`**: 양쪽 눈에 동일한 방향의 조명을 적용하면 입체감이 죽음. 머리 포즈에 따라 이 벡터가 변해야 함.

## 내가 가장 확신 없는 부분
- **카메라 프레임 SSR의 실효성**: 프레임에서 고휘도 영역을 찾는 연산이 셰이더 내에서 가벼울지, 아니면 별도의 다운샘플링 패스가 필수적일지 실험이 필요함.

## 다음 단계 제안
1. **Highlight Soft-roll 실험**: LTL 블렌딩에서 하이라이트 보호 수식을 계단식에서 곡선식으로 변경 후 실기기 비교.
2. **Simple Parallax 적용**: Gaze 벡터 없이 `(coord - center)` 값을 이용해 텍스처를 미세하게 반대 방향으로 밀어보는 "가짜 깊이감" 테스트.
