# Gemini 렌즈 렌더링 자연스러움 브레인스토밍 응답 (R2)

## A. 개요 및 R1 대비 입장 변화
- **I1 (환경 반사)**: **수정**. Claude의 "카메라 재사용" 철학을 유지하되, Codex의 "재귀 반사" 우려를 반영하여 **얼굴 영역을 제외한 주변부(Periphery) 샘플링**으로 구체화함.
- **I2 (블렌드)**: **수정**. 제 R1의 하이브리드(Circle, Vivid) 입장을 철회하고, **Codex의 선형 4종 세트(ColorReplaceLinear 포함)로 수렴** 제안.
- **I9 (디테일)**: **철회**. 절차적 노이즈 생성을 포기하고 **Codex의 원본 휘도 재주입(Detail Reinjection) 수용**.

## B. 열린 쟁점 (I1~I10)

### I1. 환경 반사 소스 — 입장: 수정 (Claude-Gemini 연합 유지 + Codex 보완)
- **평가**: Codex의 "얼굴 재귀 반사" 지적은 타당하나, 에셋 env map은 "사용자 환경 불일치"라는 더 큰 문제를 안고 있음.
- **수렴 제안**: **Periphery-Filtered Camera Reflection**.
  - 카메라 텍스처의 **화면 가장자리(Top/Side) 영역 8포인트**만 샘플링하여 평균 색상/휘도를 추출, 이를 가상의 돔 라이트로 사용.
  - 얼굴이 화면 중앙을 점유하므로 가장자리는 높은 확률로 배경(천장 조명, 창문)임. 에셋 없이도 환경 반응성 확보 가능.

### I2. 블렌드 최종 세트 — 입장: 수정 (Codex 4종 세트 수용)
- **평가**: 제 R1의 하이브리드 블렌드는 튜닝 파라미터를 블랙박스화할 위험이 있음. Codex의 `ColorReplaceLinear`는 불투명 렌즈의 색 정확도 문제를 선형 공간에서 우아하게 해결함.
- **수렴 제안**: **Codex 4종(TintLinearV2, Multiply, ScreenLinear, ColorReplaceLinear)**으로 확정.
  - **I2-a (Normal)**: `ColorReplaceLinear`로 흡수 가능함에 동의. 드롭.
  - **I2-b (Screen)**: 어두운 홍채 위 밝은 렌즈 시나리오에서 LTL만으로는 발색 부족함 인정. `ScreenLinear` 유지.

### I3. LTL 실반사 보호 — 입장: 수정 (Codex 입장 수용)
- **평가**: "실반사 보호는 블렌드 모드 밖(반사 계층)으로 나가야 한다"는 Codex의 아키텍처 비판이 전적으로 옳음.
- **수렴 제안**: I1의 환경 반사가 분리된 계층(Additive Pass)으로 구현되므로, 블렌드 내부의 `realSpec` 해킹은 폐기.

### I4. 림발 링 — 입장: 유지 (메타데이터 + 자동 조절 하이브리드)
- **평가**: Codex의 SKU 플래그는 안전하지만, 플래그가 없는 구형 텍스처 대응력이 떨어짐.
- **수렴 제안**: **메타데이터 우선 + 셰이더 Fallback**.
  - `has_baked_limbal` 플래그가 없으면 셰이더 림발을 켜되, 제 R1 제안대로 텍스처 외곽 휘도를 분석해 이미 림발이 있으면 강도를 낮추는 **Soft-gate** 적용.

### I5. 블링크 처리 — 입장: 수정 (Claude/Codex 입장 수용)
- **평가**: 60~80ms(2~3프레임)의 짧은 페이드는 "눈꺼풀 위 투영"을 인지하기 전에 사라지므로 시각적 안정성에 득이 큼.
- **수렴 제안**: **60ms Fade-out**. 단, `eyelidMask`를 통과한 후 적용하여 투영 리스크 원천 차단.

### I6. 입력 계약 확장 — 입장: 수정 (Codex Packet 구조 수용)
- **평가**: `EyeRenderPacket` 구조체는 유지보수 측면에서 압도적 우위. `gaze_vector`는 `pupil_center`로부터 유도 가능하므로 중복 필드임.
- **수렴 제안**: **Codex의 EyeRenderPacket 채택**. Parallax 구현을 위해 `pupil_center`를 필수급 선택 필드로 격상 권장.

### I7. uAvgIrisLum = 0.35 하드코드 — 입장: 철회 (Codex 비판 전격 수용)
- **평가**: 개인화를 방해하는 "평균의 함정"임.
- **수렴 제안**: **Adaptive Iris Luma**. ROI의 히스토그램을 매 프레임(또는 n프레임 간격) 측정하여 전달. 측정 실패 시에만 0.35를 최후의 수단으로 사용.

### I8. calcScleraFactor 존폐 — 입장: 유지 (폐기론)
- **평가**: 조명 변화에 따른 색상 기반 판정은 False Positive 리스크가 너무 큼. 
- **수렴 제안**: **Geometric-First + Luma-Veto**. 색상(채도)은 버리고, 기하학적 영역 밖인데 너무 어두운 경우(그림자)만 렌즈를 깎는 luma 기반 가중치만 남김.

### I9. 홍채 디테일 재주입 — 입장: 수정 (Codex 방식 수용)
- **평가**: 제 R1의 절차적 생성은 "가짜"를 만드는 리스크가 큼. 원본 휘도를 재주입하는 Codex의 방식이 AR의 본질(현실 강화)에 부합.
- **수렴 제안**: **Codex의 Detail Reinjection 수식 채택**. 단, 저조도 노이즈 증폭 방지를 위해 `avg_iris_luma`가 일정 수준 이하일 때 감쇄하는 gate 추가.

### I10. W2와의 경계 — 입장: 유지 (W3 범위 밖)
- **평가**: 렌더러가 refiner를 직접 소유하면 셰이더 코드가 무거워짐. 
- **수렴 제안**: W2 산출물(Refined Landmarks)을 `EyeRenderPacket`에 담아 보내는 것으로 계약만 열어두고, 렌더러는 수동적으로 렌더링만 수행.

## Claude가 W3-04까지 해놓은 것 중 틀렸다고 보는 것 (추가)
- **동공(Pupil) 영역 처리 부재**: 현재 렌즈 텍스처의 중심부(동공)를 단순히 투명하게만 처리하고 있는데, 실제 눈은 동공 안쪽도 어두운 휘도 구조를 가짐. 렌즈가 동공을 덮을 때 `baseLum`의 하한선을 강제하여 "구멍 뚫린 느낌"을 지워야 함.

## 내가 가장 확신 없는 부분
