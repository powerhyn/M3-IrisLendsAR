# 렌즈 에셋 실측 분석 (20개 전수)

> **작성**: Claude Opus 4.7
> **시점**: 2026-04-23 R3 합의본 작성 후, 에셋 맹점 발견
> **대상**: `docs/items/lens_assets_100x100/*.png` (20개 PNG, 4개 브랜드)
> **목적**: 실제 렌더링 대상 에셋의 구조를 실측 확인하여 `99_final_decision.md`의 C6 림발 처리 / Pupil cutout / B1 벤치 SKU 구성을 교정.

---

## 0. 핵심 발견 3줄

1. **20개 중 대다수(~14개)에 베이크된 림발이 없다.** R1~R3에서 "대부분 렌즈에 림발 내장"이라 가정한 전제는 **실측으로 반증됨**.
2. **20개 전부 중심이 완전 투명**. 원본 홍채/동공이 그대로 노출되는 구조. Gemini의 Pupil cutout 우려가 에셋 수준에서 재확인됨.
3. **그래픽 렌즈(엔비_샤모 브라운) 1개 존재**. Codex R3가 지적한 "화이트/그래픽 렌즈" 셀이 실제 라인업에 있음 → B1 벤치 SKU 포함 정당성 확보.

## 1. 파일 메타데이터 (전수)

- **해상도**: 100×100 (분석용. 사용자 피드백: 원본 1000×1000 구조 동일)
- **색공간**: RGB + Alpha 8bit (ICC 프로필 정보 없음 → sRGB 가정 안전)
- **형식**: PNG (무손실, 알파 완전 지원)
- **개수**: 20개 = 로뮤(6) + 엔비(5) + 오OH(4) + 클라셋(5)

## 2. 렌즈별 특성 분류표

### 2.1 컬러 스펙트럼

| 그룹 | 렌즈 | 주 색상 | 명도 |
|------|------|--------|------|
| **짙은** | 클라셋_돌 초코, 로뮤_디어 멜로우, 엔비_플럼 블랙 | 초코/블랙/플럼 | 낮음 |
| **중간 브라운** | 오(OH)_베이글, 로뮤_러브 글림, 엔비_샤모 브라운 | 브라운 계열 | 중간 |
| **베이지/탄** | 로뮤_밀키 탄, 엔비_무스 베이지, 로뮤_마틀 피치 | 웜 베이지 | 중간~높음 |
| **그레이** | 클라셋_런웨이 그레이, 클라셋_클라우드 그레이, 로뮤_그레이 토프 | 뉴트럴 그레이 | 중간~높음 |
| **블루/쿨톤** | 엔비_퍼퓸 글로우, 오(OH)_리즈, 엔비_코랄 치크 | 블루/블루그레이 | 높음 |
| **올리브/그린** | 오(OH)_샤이, 오(OH)_키위, 클라셋_네버 올리브 | 그린/올리브 | 중간~높음 |
| **핑크/로즈** | 클라셋_누드 애쉬 로제 | 로즈 핑크 | 중간 |
| **그래픽/특수** | 로뮤_문 글림 (별 하이라이트), 엔비_샤모 브라운 (강한 블랙 아웃라인) | 혼합 | 혼합 |

### 2.2 림발 처리 (실측)

| 림발 강도 | 개수 | 해당 렌즈 |
|----------|------|----------|
| **없음/미미** | ~14 | 클라셋_돌 초코, 클라셋_런웨이 그레이, 클라셋_누드 애쉬 로제, 클라셋_네버 올리브, 클라셋_클라우드 그레이, 로뮤_밀키 탄, 로뮤_마틀 피치, 로뮤_문 글림, 엔비_무스 베이지, 엔비_퍼퓸 글로우, 엔비_코랄 치크, 오(OH)_샤이, 오(OH)_키위, 오(OH)_리즈 |
| **약하게 베이크** (자연 그라디언트 수준) | ~5 | 로뮤_그레이 토프, 로뮤_디어 멜로우, 로뮤_러브 글림, 엔비_플럼 블랙, 오(OH)_베이글 |
| **강한 블랙 아웃라인** (디자인 요소) | 1 | 엔비_샤모 브라운 |

**→ 결론**: **기본값 "림발 강하게 베이크됨" 전제는 실측에 반함.** R3 합의본 C6의 "SKU 메타 `has_baked_limbal` 플래그" 구조는 유지하되, **기본값은 `false`(셰이더 림발 활성)**이어야 함. 플래그는 약/강 베이크된 **5~6개 소수 SKU에만 `true`** 설정.

### 2.3 중심 투명 (Pupil 영역)

- **20개 전부 중심 완전 투명** (α=0 또는 거의 0). 예외 없음.
- 투명 영역 크기 편차: 대략 **렌즈 반경의 20~40%**. 브랜드/SKU별로 다름.
- 알파 전이(edge feather) 형태: 대부분 중심 → 점진적 알파 증가 (부드러운 그라디언트)

**→ Gemini의 Pupil cutout 우려 근거 강화**: 원본 홍채(+동공)가 그대로 투과되므로, 사용자 홍채가 짙을 때 동공 검은 영역과 iris 색이 구분 안 돼 "구멍 뚫린" 느낌 발생 가능.

### 2.4 외곽 페이드

- 대부분 알파 그라디언트 (자연스런 경계)
- 예외: 엔비_샤모 브라운은 외곽에 **의도된 강한 블랙 아웃라인** (코스프레/포인트 렌즈 스타일)

### 2.5 패턴 유형

| 패턴 | 해당 렌즈 | 특징 |
|------|----------|------|
| 도트 (random dot) | 대다수 | 컬러렌즈 표준 |
| 방사형 (radial) | 오(OH)_베이글 | 홍채 섬유 모사 |
| 메쉬 | 클라셋_런웨이 그레이 | 격자 무늬 |
| 별 하이라이트 | 로뮤_문 글림 | 포인트/코스프레 |
| 그래픽 아웃라인 | 엔비_샤모 브라운 | 강한 경계 강조 |

## 3. B1 벤치 SKU 선정 (대비되는 대표 6개)

Codex R3 지적(5 SKU 30클립)을 실제 라인업으로 매핑.

| # | SKU | 대표 특성 | B1 매트릭스 포함 이유 |
|---|-----|----------|--------------------|
| 1 | **클라셋_돌 초코** | 짙은 불투명 서클, 림발 없음, 명도 낮음 | 다크 톤 × Normal vs CRL 극단 비교 |
| 2 | **클라셋_런웨이 그레이** | 밝은 그레이, 림발 없음, 명도 높음 | 라이트 톤 × 짙은 홍채 (아시아인 주류) 시나리오 |
| 3 | **오(OH)_베이글** | 중간 브라운, 약한 베이크 림발, 방사형 패턴 | 자연 톤 + 베이크 림발 있는 SKU 표본 |
| 4 | **엔비_퍼퓸 글로우** | 매우 밝은 블루/쿨톤, 반투명 | 쿨톤 × 짙은 홍채에서 ScreenLinear 가치 검증 |
| 5 | **엔비_샤모 브라운** | 그래픽 렌즈 (강한 아웃라인) | Codex R3 지적 "화이트/그래픽" 셀 = CRL의 존재 이유 |
| 6 | **클라셋_누드 애쉬 로제** | 핑크/로즈 웜톤 | 컬러 다양성 + LTL의 웜톤 톤매치 검증 |

**홍채 톤**: 짙음(아시아인 주류), 중간, 밝음 3단계. 단 사용자 피드백 대로 **짙은 홍채 가중치 크게** (50% 테스트 분량).

**총 벤치 분량**: 6 SKU × 3 홍채 × 2 모드 = **36 클립**. R3 합의본의 30클립보다 6클립 추가. 6개 SKU 중 1~2개를 특정 벤치에서만 쓰는 방식으로 시간 조정 가능.

## 4. 정적 텍스처 크기 추천

### 4.1 시나리오 분석

- 모바일 카메라 프레임: 보통 1080×1920 (FHD) ~ 720×1280 (HD)
- 얼굴 차지 비율: 화면의 약 60%
- iris 반경 (정규화 좌표): 약 0.04~0.08 (Android 데모 실측 기준)
- **iris 반경 픽셀 환산**: FHD 세로 1920 × 0.04 = ~77px / × 0.08 = ~154px
- **렌즈 표시 영역**: iris 반경의 약 1.5~2배 → **120~310px 직경**

### 4.2 크기별 비교

| 크기 | 대표 렌즈 표시 영역(200px)에서의 배율 | GPU 텍스처 메모리 (RGBA8) | 20 SKU 기준 총 메모리 | 품질 |
|------|---------------------------------|------------------------|--------------------|------|
| 100×100 | 2× 업스케일 → **도트 뭉개짐** | 40KB | 800KB | ❌ 품질 저하 |
| 256×256 | 1.28× 다운샘플 → 자연 | 262KB | 5.2MB | ✅ 권장 |
| 512×512 | 2.5× 다운샘플 → 여유 있음 | 1MB | 20MB | ○ 고사양 |
| 1000×1000 | ~5× 다운샘플 → 과도 | 4MB | 80MB | ❌ 메모리 과다 |

### 4.3 추천

**1차 권장: 256×256 RGBA PNG 단일 해상도**
- 이유: MID tier 안드로이드에서 충분, 20 SKU 총 메모리 5MB 수준으로 매우 경량
- GPU 텍스처 mipmap 생성 시 추가 33% → 약 7MB (허용 범위)

**대안: Tier-based 선택**
- HIGH tier: 512×512 사용 (고사양 기기에서 렌즈 경계 선명도 향상)
- MID/LOW: 256×256
- 네이밍 규칙: `{SKU}_256.png` / `{SKU}_512.png`
- `LensConfig` 또는 SDK 초기화 시 tier 파라미터로 자동 선택

**불채택: 1000×1000**
- GPU 메모리 과다 + 다운샘플 중 셰이더 mipmap 자동 생성이 이미 품질 확보
- 원본 아카이빙 용도로만 유지

## 5. 99_final_decision.md 반영 필요 사항

### 5.1 C6 림발 처리 — 기본값 뒤집기

**현재 (R3)**: 림발 기본 ON + SKU 메타 `has_baked_limbal`가 true면 셰이더 림발 off
**수정 방향**: 구조는 유지. 단 기본값과 문구를 명확히:
- `has_baked_limbal` 기본값: **false** (거의 모든 SKU가 림발 없음 — 실측)
- 5~6개 약-베이크 SKU(로뮤_그레이토프/디어멜로우/러브글림, 엔비_플럼블랙, 오(OH)_베이글)에 `true` 설정
- 엔비_샤모 브라운은 `has_baked_limbal=true` + 추가 **`has_graphic_outline=true` 플래그**로 별도 처리 (셰이더 림발을 off하지 않으면 중첩되어 부자연)

### 5.2 Pupil cutout — W3-05 포함 여부 재검토 (사용자 최종 판단)

실측으로 모든 렌즈 중심 투명 확인 → Gemini 우려 강화. **2 vs 1 Phase 6 이월 결정 재논의 가치 있음**. 수식 단순(`baseLum = max(baseLum, floor)` 또는 알파 기반 `finalAlpha = max(finalAlpha, pupil_min)`), S2 구현 비용 낮음.

**사용자 최종 판단 권장 전환**: Phase 6 이월 → **W3-05 S2 포함** (실측 근거)

### 5.3 B1 벤치 SKU 업데이트

실제 라인업 6개로 명시:
- 클라셋_돌 초코 (다크)
- 클라셋_런웨이 그레이 (밝은 그레이)
- 오(OH)_베이글 (자연 + 베이크 림발)
- 엔비_퍼퓸 글로우 (쿨톤)
- 엔비_샤모 브라운 (그래픽)
- 클라셋_누드 애쉬 로제 (핑크)

### 5.4 텍스처 크기 공식 결정

**256×256 RGBA PNG** 표준화. `LensConfig`에 `texture_size` 필드 추가 (기본 256, optional 512).

## 6. 비어있는 정보 (사용자 확인 or Claude 후속 작업)

### 6.1 Claude가 후속 조사할 것

- **웹 검색 교차검증**: 로뮤/엔비/오/클라셋 실제 제품 착용 사진 vs 이미지 에셋의 림발 처리 일치도. 만약 실제 제품이 에셋보다 림발이 진하다면, 에셋의 림발 부족은 "디자인 의도"가 아니라 "에셋 단순화"일 가능성. → 셰이더 림발 강도 재설정 영향.

### 6.2 사용자 확인 부탁

- **원본 1000×1000 중 대표 1~2개 샘플 공유 가능?** 100×100은 도트 패턴이 뭉개져 보일 수 있음. 원본에서 **림발이 더 선명**하게 보인다면 위 5.1 결정이 달라질 수 있음.
- **"이 렌즈들이 전부인가"**: 사용자가 "훨씬 더 많다"고 했으나 시뮬레이터 제공 여부 미지수. **벤치 결과를 시뮬레이터 외 전체 라인업에 일반화 가능한지** 판단 필요. 라인업에 큰 스타일 차이(예: 홀로그램, 무지개, 매직 그라디언트)가 있다면 **B1/B2 벤치 표본이 부족**해질 수 있음.

## 7. 결론

에셋 맹점 발견으로 R3 합의본 3개 지점이 **실측 교정** 필요:

1. **C6 림발 기본값 false** (실측 우선)
2. **Pupil cutout W3-05 포함 전환** (실측으로 Gemini 주장 근거 강화)
3. **B1 SKU 실 라인업 6개로 업데이트**

**정적 텍스처 크기 공식화**: 256×256 표준, 512×512 HIGH tier 옵션.

이 변경은 `99_final_decision.md`에 반영 후 S1 착수 권장. 에셋을 블랙박스로 둔 R1~R3 전체의 방법론적 맹점을 드러낸 단계 — 향후 다른 Phase에서도 "실제 에셋/데이터 실측"을 브레인스토밍 초기에 포함하는 프로세스 개선이 필요함.
