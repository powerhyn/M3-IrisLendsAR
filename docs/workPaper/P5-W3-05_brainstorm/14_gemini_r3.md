# Gemini R3 — Claude 종합 검토

## 0. 전체 평가 (한 줄)
Claude의 `99_claude_synthesis.md`는 **일부만 맞다** — Codex의 아키텍처적 엄격함에 지나치게 매몰되어 Gemini가 제안한 "실시간성 기반의 실용적 품질 개선" 요소들을 Phase 6로 과도하게 미루거나 벤치로 회피하고 있다.

## 1. 내 R2 입장 vs Claude 종합의 불일치
- **정확히 반영된 것**:
  - **I6 EyeRenderPacket**: Codex의 구조체 기반 계약 체결에 동의한 것이 정확히 반영됨.
  - **I7 uAvgIrisLum 실측**: 하드코딩 폐기 및 ROI 실측 합의 반영됨.
  - **I9 홍채 디테일 재주입**: 절차적 노이즈 포기 및 원본 휘도 재주입(Codex 안) 수용 반영됨.
- **왜곡되어 반영된 것**:
  - **I5 블링크 ramp**: 내가 R2에서 60ms Fade-out을 수용한 것은 "안정성" 때문이지, 120ms라는 느린 Fade-in(up)을 허용한 것이 아님. 120ms는 사용자가 눈을 떴을 때 렌즈가 뒤늦게 나타나는 "지연 현상"으로 인지될 위험이 큼.
- **누락된 것**:
  - **동공(Pupil) 영역 baseLum 하한 강제**: R2에서 "구멍 뚫린 느낌"을 지우기 위해 제안한 내용이 W3-05 확정분에서 누락되고 Phase 6로 밀려남. 이는 렌더러 자연스러움의 핵심인데 왜 미뤄졌는지 의문임.
- **내 입장과 다르게 "합의"로 분류된 것**:
  - **I3 realSpec 폐기**: 환경 반사 계층(I1) 도입이 "벤치 이관"인 상황에서, I3를 "완전 수렴(폐기)"으로 분류하는 것은 위험함. 벤치 결과 환경 반사가 폐기될 경우, LTL 내의 realSpec은 유일한 하이라이트 보호 수단으로 남아야 함.

## 2. Claude가 "완전 수렴"이라 분류한 7쟁점 재검증
- **I3 (realSpec 폐기)**: **부동의**. I1(환경 반사) 도입 확정 전까지는 "조건부 폐기"여야 함.
- **I5 (블링크 ramp)**: **부동의**. `up 100~120ms`는 너무 김. `down 60ms / up 60ms` 대칭 또는 `up`을 더 짧게 가져가야 함.
- **I6, I7, I9, I10**: **동의**. Codex의 제안이 합리적이며 수식과 구조에 이견 없음.
- **I2 (3종 확정분)**: **동의**. TintLinearV2, Multiply, ScreenLinear로의 압축에 찬성함.

## 3. Claude가 "벤치 이관"이라 분류한 4쟁점 재검증
- **I1 (환경 반사 소스)**: **벤치 이관 찬성**. 특히 Gemini의 "Periphery 샘플링"이 Codex의 "정적 에셋" 대비 얼마나 환경 정합성이 높은지 증명할 기회임. 단, Claude의 "hybrid" 옵션은 프로토타입 복잡도만 높이므로 `env-map-only` vs `periphery-only` 대결이 선행되어야 함.
- **I2-4번째 슬롯**: **벤치 이관 찬성**. 불투명 렌즈에서 CRL의 우위는 눈으로 확인해야 함.
- **I4 (림발 자동감지)**: **벤치 없이 확정 가능**. 메타데이터 우선 원칙에 동의하되, 자동 감지는 "안전한 임계값" 내에서만 동작하도록 셰이더에 구현하면 됨. 굳이 벤치로 시간을 끌 필요 없음.
- **I8 (sclera color-veto)**: **벤치 이관 찬성**. 채도(saturation) 포함 여부가 그레이 렌즈에서 독이 되는지 득이 되는지 확인 필요.

## 4. `99_claude_synthesis.md` §1 (즉시 확정 17개)에 대한 검증
- **D1~D6 (제거)**: 동의. 특히 D1(고정 조명)과 D4(평균 휘도 하드코드) 제거는 필수적임.
- **C1~C11 (추가)**:
  - **C10 (디테일 재주입)**: 저조도 gate 수치(0.15)가 너무 낮을 수 있음. 실측 결과에 따라 유동적이어야 함.
  - **EyeRenderPacket**: `gaze_vector`가 빠진 것은 아쉽지만, `pupil_center`로 유도 가능하다는 논리에 동의함.

## 5. `99_claude_synthesis.md` §3 구현 순서(S1~S5) 검증
- **전략 적절성**: W3-04 직전에서 분기하여 롤백(S1)부터 시작하는 전략은 매우 합리적임.
- **순서 문제**: S2(스캐폴드) 단계에서 **Gemini의 Pupil Cutout 처리**가 포함되어야 함. 단순한 클램핑 로직이므로 S4까지 기다릴 이유가 없음.

## 6. `99_claude_synthesis.md` §4 Phase 6 이월 8개 검증
- **부적절한 이월**: **"Pupil cutout 동적 처리"**는 W3-05에 포함해야 함. 렌즈 착용 시 동공이 텅 비어 보이는 현상은 경쟁사 대비 가장 큰 약점임.
- **나머지**: 동의. 3D Geometry나 PBR 등은 현재 범위 밖임.

## 7. 내가 R2에서 놓쳤거나 약하게 표현했던 것
- **I1 Periphery 샘플링의 실시간성**: Codex는 전면 카메라 프레임에 광원이 없다고 비판하지만, 모바일 사용 환경(카페, 사무실)에서는 화면 가장자리에 천장 등기구나 창문이 걸리는 경우가 다수임. 에셋 env map은 "반사광이 눈을 따라 움직이지 않는" 치명적 결함이 있음을 재강조함.
- **I3 조건부 유지**: I1이 벤치에서 탈락하거나 성능 이슈로 취소될 경우에 대한 대비책(fallback)이 Claude 종합에는 부재함.

## 8. R4 필요성 판단
- **R4 불필요**. Claude가 본 R3의 비판(I5 ramp 시간 조정, Pupil Cutout 복구, I3 조건부 폐기)을 수용하여 `99_final_decision.md`를 작성한다면 즉시 구현 착수 가능.
- 만약 Claude가 여전히 내 Pupil Cutout 제안을 Phase 6로 미루겠다면, 그 지점에 대해서만 짧은 R4 또는 모더레이터 판단 요청.
