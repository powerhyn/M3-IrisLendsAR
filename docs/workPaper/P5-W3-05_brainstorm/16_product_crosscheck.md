# 실제 렌즈 제품 vs 에셋 림발 교차검증

> **작성**: Claude Opus 4.7
> **시점**: 2026-04-23
> **방법**: 웹 검색 4건 + WebFetch 3건(성공 2 / 실패 1) + 업계 일반 검색 1건
> **목적**: 15_asset_analysis에서 발견한 "에셋 대부분 림발 없음"이 실제 제품의 특성을 반영한 것인지, 아니면 에셋 단순화인지 교차검증

## 0. 한 줄 결론

**에셋의 "림발 없음/미미"는 (아마도) 실제 제품 특성과 대체로 일치**한다. 단 이 검증은 **쇼핑몰/블로그 이미지·후기 기반**이라 보정·마케팅 개입 리스크가 크다. **절대 증거로 취급 금지**. 그럼에도 업체가 제공한 20개 원본 에셋의 특성 자체는 이 검증과 독립적으로 유효하며, **R3 합의본의 "셰이더 림발 기본 ON" 결정은 재검토 여지**가 생겼다.

## 0-1. ⚠️ 이 문서의 증거 강도 한계 (반드시 먼저 읽기)

1. **이미지 실측이 아닌 텍스트 기반 간접 검증**. WebFetch는 HTML→마크다운 변환이라 이미지 직접 대조 불가.
2. **쇼핑몰/블로그/리뷰 사진은 보정이 강하게 들어간다** — 화이트닝, 채도 부스트, 렌즈 강조 보정. 보정된 이미지에서 읽은 "림발 강도"를 기준 삼으면 위험.
3. **업계 용어("Natural 써클라인", "얇은 써클라인이 예쁜")는 마케팅 언어**일 수 있음. 제품 실물 특성과 마케팅 카피 사이 간극 존재.
4. **후기 "경계가 너무 안 나눠짐"** 같은 표현은 개인 주관적 인지. 육안 경험과 카메라 렌더링에서의 선명도는 다를 수 있음.

따라서 이 문서의 결론은 **"참고 가중치"** 로만 사용. 절대 증거는:
- **업체 제공 원본 에셋 20개** (이건 보정 없이 업체 의도 그대로 — 신뢰 가능)
- **실기기 A/B 벤치 결과** (B1/B2/B5/B8 수행 시 최종 판단 근거)

## 1. 검증 방법

### 1.1 수행한 검색/페치

| 방법 | 대상 | 결과 |
|------|------|------|
| WebSearch | 로뮤/엔비/클라셋/오렌즈 브랜드별 "착용샷 후기" | 링크 리스트 확보 (TikTok/인스타/쇼핑몰) |
| WebFetch | 오렌즈 비비링 원데이 브라운 (`o-lens.com/product/20007`) | ✅ 후기 텍스트 성공 |
| WebFetch | 렌즈베리 초코 렌즈 리뷰 (`lensvery.com/article/.../12074`) | ✅ 제품 리뷰 성공 |
| WebFetch | 성예사 초코 렌즈 토론 (`sungyesa.com/new/secret/582016`) | ❌ 403 Forbidden |
| WebSearch | "컬러렌즈 써클라인 림발 디자인 특징 자연스러운 브라운" | ✅ 업계 트렌드 정보 확보 |

### 1.2 한계

- WebFetch는 HTML→마크다운 변환으로 **이미지 직접 대조 불가**. 텍스트 설명과 후기에만 의존.
- 각 브랜드 공식 상세 페이지는 대부분 이미지 위주라 디자인 설명 텍스트가 빈약.
- 따라서 **제품 사진 1:1 비교가 아닌, 업계 용어·후기·트렌드를 통한 간접 검증**.

## 2. 검증 발견

### 2.1 업계 트렌드 (검색 결과 요약)

- **"Natural 써클라인"**이 최근 컬러렌즈 셀링 포인트
- **"2세대 프린팅 기술력(Dual Printing Technology)"**은 "균일한 써클라인" 구현용 — 즉 미세한, 자연스러운 경계 추구
- 렌즈베리 기사 제목: **"얇은 써클라인이 정말 예쁜 렌즈"** — 얇은 림발이 긍정 셀링 포인트
- 업계 움직임: **과거의 강한 블랙 림발(사대 렌즈 / 코스프레)** → **얇고 자연스러운 그라디언트 경계(자연 데일리 렌즈)**

### 2.2 실제 제품 후기

**오렌즈 비비링 원데이 브라운**:
> "경계가 막 너무 안 나눠져있고 색도 딱 눈동자 색이에요"

→ **"경계가 너무 안 나눠짐"** = 림발이 선명하지 않고 자연스러운 그라디언트. 긍정 표현. 우리 에셋의 "림발 없음" 대다수와 동일한 톤.

**렌즈베리 초코 렌즈 리뷰** (팅커베리 초코 추정):
> "초코 컬러라 눈에 띄지 않고 자연스럽게 쓰기 좋더라구요"
> "직경이 커서 나~ 렌즈꼈어요!" — 직경이 주요 임팩트, 림발은 언급 없음

→ 렌즈의 존재감은 **색상과 직경**으로 만들어지고 **림발은 주요 요소가 아님**. 우리 에셋 특성과 일치.

### 2.3 제품 카테고리별 림발 분포 (추정)

| 카테고리 | 업계 림발 특성 | 우리 에셋 대응 |
|---------|--------------|-------------|
| 데일리 내추럴 브라운 | 얇음 or 없음 | 클라셋 시리즈, 로뮤_밀키탄, 엔비_무스베이지 등 (없음) |
| 미디엄 톤 데일리 | 자연스런 그라디언트 | 오(OH)_베이글, 로뮤_러브글림 등 (약한 베이크) |
| 컬러 포인트 (그레이/블루/올리브) | 얇음 | 엔비_퍼퓸글로우, 오(OH)_샤이/키위 등 (없음) |
| 짙은 브라운/블랙 서클 | 색상 자체가 경계 | 클라셋_돌초코, 엔비_플럼블랙 (약한 베이크~없음) |
| 그래픽/코스프레 | 강한 블랙 아웃라인 | 엔비_샤모 브라운 (강한 아웃라인) |

**→ 우리 에셋이 업계 카테고리별 특성을 잘 반영**. 에셋 단순화가 아니라 **각 제품의 디자인 의도 그대로**.

## 3. R3 합의본 C6 결정의 교정

### 3.1 R3 합의본 (99_final_decision.md §1.2 C6)

> **림발 기본 ON + SKU 메타데이터 플래그**. 플래그는 내부 material 모델 필드. `has_baked_limbal: true` 시 셰이더 림발 강도 0.

### 3.2 교차검증 후 수정 방향

**C6 전면 재수정**:

```
Before (R3):  림발 기본 ON, 베이크된 SKU만 false
After:        림발 기본 OFF. LensConfig.shader_limbal_strength (0.0~1.0, 기본 0.0) optional.
              대신 `LensConfig.prefers_graphic_outline` 플래그로 엔비_샤모브라운 스타일
              처리 (해당 SKU는 에셋이 이미 강한 아웃라인 포함, 셰이더는 보강 금지).
```

**근거**:
1. 업계 트렌드는 **얇은/자연스러운 림발**. 셰이더에서 인위적으로 강한 림발을 만들면 **제품 정체성 훼손**.
2. **에셋이 이미 디자인 통제권 행사** — 업체가 의도한 림발 강도 그대로 렌더링되는 것이 맞음.
3. 셰이더 림발은 **텍스처가 애매한 edge case에만 opt-in 대응** — 거의 모든 상용 제품은 필요 없음.
4. Codex의 "asset authoring에 품질 책임 떠넘김" 비판은 렌즈 도메인에서는 **업계 관행과 반대** — 에셋 authoring이 제품 정체성이므로 이건 SDK가 책임질 영역이 아님.

### 3.3 B4 벤치 (림발 자동 감지) 전면 재평가

R3는 B4로 "텍스처 edge/center 대비로 자동 감지 fallback" 벤치를 계획. 수정 후:

- **셰이더 림발이 기본 OFF이므로, 자동 감지 자체가 필요 없음**
- B4 **폐기** 또는 **극소수 edge case (향후 신제품 중 림발 표현 애매한 텍스처 등장 시)** 대비용으로 보류

### 3.4 Claude R1 원안 재평가 (복귀 확정이 아닌 재검토 여지)

| 지점 | Claude R1 | R2/R3 수정 | 에셋+간접검증 후 |
|------|-----------|-----------|---------------|
| 림발 기본값 | OFF (opt-in) | ON + 메타 | **재검토 여지**: 업체 에셋이 림발 표현을 이미 담당하므로 OFF에 무게. 단 웹 교차검증 보정 리스크로 단정 불가 |
| 책임 소재 | 텍스처 제작 가이드라인 | SDK 셰이더가 소유 | **재검토 여지**: 업체가 20개 에셋에서 각각 다른 림발 강도를 의도한 정황. 셰이더가 임의 개입은 의도 훼손 가능성 |
| Codex 비판 "책임 떠넘김" 수용 | 반대 | 수용 | **완전 거부 아님**: 일부 SKU(엔비_샤모브라운 같은)는 셰이더 지원 필요. 단 기본 동작이 셰이더 림발 추가는 아닐 가능성 |

**중간 결론**: C6를 "기본 OFF"로 바로 뒤집기보다, **실기기 벤치(B4 재설계 또는 B10 신규)에서 "셰이더 림발 ON / OFF" 양쪽 렌더링을 같은 SKU로 비교**해 실측 데이터로 최종 결정. 웹 교차검증만으로는 R3 결정 뒤집기 부족.

R3 검토 라운드에서조차 이 교정을 발견 못 한 이유:
- Codex R3는 "B4 벤치 매트릭스 검증"만 했지, **B4 필요성 자체 재평가는 안 함**
- Gemini R3는 "메타+자동 hybrid"를 유지하며 자동감지 유지 주장
- Claude R3는 자기 R1 원안을 "확실히 아니다"라고 철회한 상태로 회귀 고려 안 함
- **실제 제품/에셋을 보지 않고 추상 논의만 한 것이 공통 맹점**

## 5. 핵심 교훈

### 5.1 방법론적 맹점

R1~R3 3라운드 + 종합본 + Claude 자기비판까지 거쳤지만, **실제 에셋을 보지 않고 결정한 쟁점이 2개 있었다**:

1. C6 림발 처리 (셰이더 기본 ON vs OFF)
2. Pupil cutout 우선순위 (Phase 6 vs W3-05)

둘 다 **실측 5분 만에 R3 결정과 반대 방향이 맞음**을 확인할 수 있는 지점이었다.

### 5.2 프로세스 개선 제안

향후 렌더링/데이터 처리 관련 브레인스토밍은 **라운드 0 = 실측 데이터 수집**을 먼저 수행:
- 대상 에셋 목록 확보
- 대표 샘플 시각/통계 분석
- 업계 트렌드 교차검증 (웹 검색)
- **이 실측을 R1 브리프에 포함**

이번 P5-W3-05는 너무 큰 라운드를 돌고 마지막에 실측이 들어와서 R3 결정 일부가 **뒤집히는 교정**이 발생. 시간 낭비는 크지 않았지만 (R3 사용 결정이 대부분 유효), **실측이 프로세스 설계 단계에 들어가야 함**.

## 6. 99_final_decision.md 반영 필요

### 6.1 즉시 수정 (보수적)

- **C6를 "기본 OFF로 뒤집기"는 보류**. 대신 **B10 신규 벤치** 추가: 같은 SKU 3~4개로 "셰이더 림발 ON / OFF" 렌더링 비교
- **B4 재설계**: "자동 감지 정확도" 대신 "셰이더 림발 기본값 결정" 벤치로 목적 수정
- **Codex R3 지적 거부 근거는 약화**: "업계 관행과 반대"라는 주장을 완전 거부로 쓰지 않음. 보정 리스크 있는 검증.

### 6.2 사용자 최종 판단 재요청

Pupil cutout은 에셋 실측으로 Gemini 근거 강화됨. **W3-05 S2 포함 여부 최종 판단** 요청.
