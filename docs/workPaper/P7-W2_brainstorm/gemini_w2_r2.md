# P7-W2 R2 — 블렌드 파급(blast radius) Gemini 입장 정리

R1에서 확정된 측정 메커니즘을 바탕으로, `uAvgIrisLum` 실측값이 메인 블렌드 수식에 미치는 파급력과 정합성 유지 방안을 다음과 같이 추천합니다.

## R2.1 정규화 해석 확인
- **추천**: **해석 동의 (Brightness-invariant normalization)**
- **근거**: `shader_sources.cpp:877` 수식 `0.85 / max(0.01, uAvgIrisLum)`과 `toLinearFast(blend) * lum * scale`의 결합은 결과적으로 `blendL * 0.85 * (lum / avgLuma)`가 됩니다. 이는 개별 픽셀 휘도(`lum`)를 홍채 평균 휘도(`avgLuma`)로 나누어 정규화함으로써, 조명 환경 변화에도 렌즈 틴트의 상대적 밝기를 일정하게 유지하려는 설계 의도와 일치함을 코드로 확인했습니다.

## R2.2 현 0.1225 고정 = 버그 vs 의도
- **추천**: **(a) 실측으로 반드시 고쳐야 할 결함 (Missing Connection)**
- **근거**: 현재 `avgLuma`가 0.1225(sRGB 0.35의 제곱)로 고정된 상태는 모든 환경을 "어두운 실내"로 가정하고 scale을 7.0(최대치) 근처로 포화시킵니다. 이는 밝은 야외에서 렌즈가 과도하게 밝게 렌더링되는(over-tint) 원인이므로, W2의 목적인 실측값 연결을 통해 '적응형 정규화'를 완성해야 합니다.

## R2.3 clamp[0.8, 7.0] + K=0.85 재튜닝
- **추천**: **K=0.85 유지하되 하단 clamp 0.8 상향 검토 (실측 분포 기반)**
- **근거**: 실측값이 연결되면 `avgLuma`가 0.5 이상으로 올라가는 밝은 환경에서 scale이 0.85/0.5 = 1.7 등으로 급격히 떨어집니다. 기존 고정값(scale 7.0)에 익숙해진 시각적 룩이 너무 어두워 보일 수 있으므로, 실측값 도입 후 하단 clamp를 1.0~1.2 수준으로 올려 '최소 시인성'을 보장하는 재튜닝이 필요합니다.

## R2.4 측정=정규화 정합 보장
- **추천**: **Detector(C안)에서 `(sRGB/255)^2` 선형화 후 Rec.709 휘도 산출 강제**
- **근거**: 셰이더는 `toLinearFast`(`x*x`)와 `LUMA_709_LENS`를 사용합니다. `CameraGLRenderer.kt`의 OES→2D 변환은 sRGB를 유지하므로, Detector의 `rgb_buffer` 역시 동일한 sRGB 공간입니다. 따라서 C안의 CPU 측정 루프에서 각 픽셀을 제곱하여 선형화한 뒤 Rec.709 계수를 곱해야만 셰이더의 `lum / uAvgIrisLum` 연산이 수학적으로 동일 공간에서 정규화됨을 보장할 수 있습니다.

## R2.5 W5/W6 튜닝 보존 전략
- **추천**: **(a) 실측 도입 + 재튜닝을 통한 기존 룩(Baseline) 보존**
- **근거**: (c)와 같이 gate와 blend를 분리하면 셰이더 연산량과 uniform 개수가 늘어납니다. (a) 전략을 택하여, 실측값이 공급되는 표준 환경(예: 럭스 500)에서 기존 0.1225 고정 시의 시각적 결과와 유사하게 나오도록 K값이나 clamp 범위를 미세 조정하는 것이 아키텍처적으로 가장 깔끔합니다.
