# Codex 트래킹 축 교차 리뷰 + 비판적 검토 (2026-07-09)

> 대상: NLR-W2 트래킹 스윕 R1~R3 결론 (canonical = iris 중심 1.0/150, 축 분리).
> Codex(gpt-5.5 xhigh, 리포 직접 탐독 + 수치 시뮬레이션 수행) 단독 교차.
> 본 문서 = Codex 원판정 + Claude 비판적 검토(critical-review 스킬) + LensSim 클리핑 핸드오프 교차.

## 1. Codex 원판정 요약

- **(a) 해석 타당성 [동의]**: OneEuro 구현(`dx=(value−lastFiltered)/dt`, `cutoff=minCutoff+beta·|filtered_dx|`) 기준으로 "운동 중 beta 지배" 해석 정확. 축 분리 논리 강하게 동의. 단 문구는 "beta 단독"보다 **"실측한 운동 구간에서 beta 지배적"** 이 정확 — 저속 추종·미세 떨림·고노이즈에선 minCutoff·d_cutoff 재부상.
- **(b) 기본값 승격 [보류]**: 방향 합리적이나 조건부. 리스크의 정확한 표현은 "저프레임에서 느려진다"(오답 — dt 보정은 nanoTime 경로로 정상)가 아니라 **"고 beta가 검출 노이즈·재검출 스파이크를 운동으로 오인해 필터를 엶 → 저프레임일수록 덜 안정"** (수치: d_cutoff=1에서 파생 필터 alpha 30fps≈0.17 vs 15fps≈0.30). 승격 전 최소 mid-tier 실기기 확인 권고.
- **(b-추가) outlier_confirm_frames=1 지적**: 기본 1이라 outlier reject가 사실상 즉시 수용 — beta 150은 재검출 스파이크를 거의 그대로 따라가므로 별도 확인 항목.
- **(c) 눈꺼풀 위상 미발생 [보류]**: 추정(사카드 중 눈꺼풀 정지 + 경계 직교)은 그럴듯. 단 렌더러에 별도 OneEuro(4.0/12~15)가 있어 구조적으로 닫힌 리스크는 아님 — "현재 사용 시나리오에서 미발생"까지가 안전한 결론.
- **(d) 백로그 우선순위 [이견]**: ① 기기 일반화 = 승격 전 P0 ② 승격+벤치 API 정리 ③ beta 175c/200c 짧은 확인(필수 아님) ④ contour 정렬 = 재현 전 보류(무작정 150 정렬은 eyelid 지터 유발 위험) ⑤ d_cutoff = 공개 API 확장 전 벤치 전용 먼저 ⑥ 2-state = 과설계 가능성.

### 수용 (6건)

1. **문구 정정**: "추종 노브 = beta 단독" → "실측 운동 구간에서 beta 지배적" (저속·고노이즈 한정 조건 명시) — 인사이트 #1 반영.
2. **리스크 재정의**: dt 스케일 문제가 아니라 "고 beta의 노이즈→운동 오인 개방, 저프레임일수록 심화" — 백로그 문구 반영.
3. **outlier_confirm_frames=1 확인 항목**: 신규 발견, 타당. 재검출 스파이크 스냅 관찰을 승격 전 게이트에 추가.
4. **(c) 결론 한정**: "미발생" → "현재 사용 시나리오(수평 사카드·정상 프레임·밝은 환경)에서 미발생" — 문서 반영.
5. **contour 무작정 정렬 금지**: LensSim 선례와 상충해 보이나 §3 교차 분석으로 해소(아래) — 조건부 보류 유지 수용.
6. **d_cutoff는 벤치 전용 먼저 / 2-state는 재현 기기군 확인 후**: 백로그 우선순위 반영.

### 부분 수용 (2건)

1. **"15/24/30fps 리플레이 검증 P0"**: 기기 일반화 방향은 수용. 단 리플레이 인프라 구축은 1인 개발 벤치 방법론(실기기 육안 정본)에 과함 — **A23(SM_A235N, 보유·연결 가능) 실기기 스모크로 대체**. 게이트 = 정지 지터 / 사카드 추종 / 재검출 스냅 / 마스크 클리핑 4항목 육안.
2. **beta 175c/200c "필수 아님"**: 동의하되 폐기하지 않음 — 3/200 추종이 "최고"였다는 실측이 있으므로 저비용 1라운드 가치는 유지 (우선순위만 하향).

### 거부 (0건)

명백히 틀린 사실 주장 없음. 사실 주장 5건 전건 코드 검증 통과 — 무비판 수용이 아니라 검증 결과임.

## 3. LensSim 클리핑 핸드오프 §4(위상 정렬)와의 교차 — 상충 해소

LensSim: "윤곽은 본체와 **동일 상수** One-Euro 필수" ↔ Codex: "무작정 정렬 금지" ↔ 우리 실측: "미스매치 상태로 잘림 미발생". 세 입장은 **미스매치의 방향**으로 정합된다:

- LensSim의 증상("경계만 따로 떨리는 이중 떨림")은 **무필터(=본체보다 빠른) 윤곽** 케이스 — 정지 상태에서 윤곽만 raw 노이즈로 떨림.
- IrisLens는 반대 방향: 윤곽(4.0/12~15)이 본체(1.0/150)보다 **느림** — 정지에선 양쪽 다 안정(이중 떨림 구조적으로 불가), 리스크는 **운동 중 클립 지연**뿐이며 이는 판정 ④에서 실측 미발생.
- 따라서 "동일 상수" 제약의 본질은 "윤곽을 본체보다 빠르게 두지 말 것 + 위상차를 체감 이하로" — 현 구성은 전자를 만족, 후자는 실측 통과. **정렬은 관찰 항목으로 유지** (증상 발견 시 즉시 처방 가능하도록 LensSim 확정 상수 기록: 3.0/0.3/1.0 픽셀 공간).
