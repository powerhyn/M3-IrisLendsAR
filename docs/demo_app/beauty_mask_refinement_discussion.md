# 뷰티 마스크 정밀도 개선 토론

> **선행 문서**: `beauty_smoothing_discussion.md` — 매끈하게/모공 2축 토론 + 프로토타이핑 결과
> **배경**: 프로토타이핑에서 매끈하게/모공 모두 **마스크 정밀도가 1순위 병목**으로 확인됨 (3자 합의)

---

## 1. 문제 정의

프로토타이핑에서 매끈하게 파라미터를 극단까지 올렸을 때, B612 대비 **"뿌연 느낌(haze)"**이 발생. 원인은 비피부 영역(안경테, 코 윤곽, 헤어라인)에 스무딩이 누수되기 때문.

### 관찰된 마스크 누수 영역

| 영역 | 상태 | 프로토타이핑에서 관찰된 문제 |
|------|------|---------------------------|
| **코 윤곽/콧볼** | 보호 없음 | 매끈하게 시 콧볼 그림자가 밀려서 뿌옇게 보임 |
| **안경테** | 보호 없음 | 매끈하게 시 안경 프레임이 흐려짐 |
| **헤어라인** | 부분 축소(상단 16%) | 이마 경계가 약간 뿌옇게 |
| **콧구멍 내부** | 보호 없음 | 어두운 영역이 밝아짐 |

### 현재 마스크 구조

```
Face Oval (36 landmarks) → 내부 축소 (상단 0.84, 하단 0.96)
    ↓
Skin Mask (이진, fillPoly)
    ↓
보호 마스크 3종:
  - Eye (16+16 landmarks, dilate 7×5)
  - Eyebrow (8+8 landmarks, dilate 5×3) — 항상 활성
  - Lips (22 landmarks, dilate 5×5) — 선택적
    ↓
Combined = skin × (1-eye) × (1-eyebrow) × (1-lip)
    ↓
Feathering: GaussianBlur (kernel 31×31)
    ↓
최종 마스크 (64~256px, 0~255 그라데이션)
```

**보호되는 것**: 눈, 눈썹, 입술
**보호되지 않는 것**: 코, 안경테, 헤어라인, 콧구멍

## 2. 개선 방안 (CLAUDE 의견)

### 방안 A: 코 보호 마스크 추가 (저비용, 즉시 가능)

MediaPipe Face Mesh에 코 랜드마크가 이미 있지만 현재 사용하지 않음.

```
추가할 것:
- NOSE_BRIDGE_INDICES: 코 브릿지 (콧등 중심선)
- NOSE_TIP_INDICES: 코끝/콧볼 윤곽
→ createNoseProtectionMask() 함수 추가
→ combineMasks에 × (1-nose) 추가
```

**장점**: 코드 변경 최소, 기존 구조와 동일한 패턴
**단점**: 안경테/헤어라인은 해결 안 됨. 코 보호가 과하면 코 위 피부도 보정 안 됨
**예상 효과**: 콧볼/콧구멍 뿌옇게 되는 문제 개선

### 방안 B: Erode/Dilate 기반 마스크 정제 패스 (중비용)

> Gemini 제안 채택

현재 마스크의 경계를 정제하는 후처리 패스 추가:

```
현재: skin_mask → combineMasks → feathering → 최종
변경: skin_mask → combineMasks → erode(경계 안쪽으로 축소) → feathering → 최종
```

**Erode 효과**: 마스크 경계를 2~3px 안쪽으로 축소 → 안경테/코 윤곽/헤어라인 경계에서 자동으로 마스크가 빠짐
**장점**: 랜드마크 추가 없이 경계 누수 전체적으로 감소. 비용 낮음 (CPU OpenCV 연산)
**단점**: 균일한 축소라서 볼/이마 중심부의 마스크도 살짝 줄어듦. 세밀한 제어 불가
**예상 효과**: 경계 haze 전반적 감소

### 방안 C: 피부 세그멘테이션 모델 도입 (고비용)

경량 딥러닝 모델로 피부/비피부를 픽셀 단위로 분리:

```
입력: 카메라 프레임 (다운스케일)
모델: 경량 U-Net 또는 MobileNet 기반 semantic segmentation
출력: 피부 확률 맵 (0.0~1.0)
→ 현재 랜드마크 기반 마스크 대체 또는 보조
```

**장점**: 안경, 코, 헤어라인, 수염 등 모든 비피부 영역 정밀 제외. B612 수준 달성 가능성 가장 높음
**단점**: 모델 학습/준비 필요, 추론 비용 추가 (TFLite 경량 모델이라도 2~5ms), SDK 크기 증가
**예상 효과**: 근본적 해결

### Claude 제안: A + B 조합으로 먼저 시도

| 순서 | 작업 | 이유 |
|------|------|------|
| 1 | **방안 A: 코 보호 마스크** | 즉시 가능, 가장 큰 단일 문제(콧볼) 해결 |
| 2 | **방안 B: Erode 정제** | A로 해결 안 되는 경계 누수(안경, 헤어라인) 완화 |
| 3 | **실기기 테스트** | A+B 적용 후 매끈하게/모공 재테스트, B612과 비교 |
| 4 | **판단** | 충분하면 마스크 작업 완료, 부족하면 C(세그멘테이션) 검토 |

## 3. Codex 의견

### 핵심 판단

- Claude의 **A + B 우선 시도**에는 동의한다. 세그멘테이션으로 바로 가기 전에, 현재 ROI 마스크 구조 안에서 얻을 수 있는 개선 폭을 먼저 확인하는 것이 맞다.
- 다만 지금 병목은 단순히 "보호해야 할 부위가 몇 개 빠져 있다" 수준이 아니라, **하나의 `combined_mask`로 `매끈하게`와 `모공`을 동시에 만족시키려는 구조**에도 있다.
- 따라서 마스크 고도화는 "코 보호 추가"와 "경계 축소"만으로 보지 말고, **효과별로 요구하는 마스크 보수성이 다른 문제**까지 같이 다루는 편이 안전하다.

### Claude 의견에 대한 동의

- 코 윤곽/콧구멍은 실제 haze 기여도가 커서 별도 보호 대상으로 다룰 가치가 있다.
- `erode → feathering` 순서는 타당하다. 경계 누수를 줄이려면 feathering 전에 마스크를 안쪽으로 확정하는 쪽이 맞다.
- 세그멘테이션은 유력한 최종 후보지만, 현재 단계에서 1차 해법으로 바로 채택할 수준은 아니다.

### 보완이 필요한 부분

#### 1. `코 보호 마스크`는 코 전체 제외가 아니라 `코 내부/경계 보호`에 가까워야 함

- 코 피부는 `매끈하게`와 `모공` 모두에서 중요한 타깃 영역이다. nose 전체를 0으로 빼면 haze는 줄어도 **코 피부 보정 자체가 죽을 위험**이 있다.
- 우선 보호해야 할 것은 코 전체보다
  - **콧구멍 내부**
  - **콧볼 경계(alar crease)**
  - **콧등의 강한 윤곽선**
  에 가깝다.
- 따라서 구현도 `createNoseProtectionMask()` 하나로 코 전체를 빼기보다, **`nose_cavity_protect` + `nose_edge_soft_protect`**처럼 역할을 나눠 접근하는 편이 더 안전하다.

#### 2. 방안 B의 erode는 `고정 픽셀 값`으로 두기 어렵다

- 현재 마스크 해상도는 ROI 크기에 따라 **64~256px**로 가변이고, skin mask 자체도 이미 상단 `0.84`, 하단 `0.96`으로 **비대칭 축소**가 들어가 있다.
- 이 상태에서 `2~3px` 고정 erode를 더하면
  - 작은 얼굴에서는 과도하게 줄고
  - 큰 얼굴에서는 거의 의미가 없을 수 있다.
- 따라서 erosion/dilation 반경은 고정 px보다 **`mask_width` 또는 `face_width` 기준 정규화**가 필요하다.
- 가능하면 균일 erosion보다 **상단/측면 경계가 더 강한 비등방 shrink**가 더 맞다. 현재 문제는 얼굴 중심부보다 헤어라인, 안경, 콧볼 같은 경계 누수 쪽이 크기 때문이다.

#### 3. 안경테는 랜드마크 보호만으로는 끝나지 않을 가능성이 높다

- 눈/눈썹 보호 확대는 안경 주변 일부에는 도움이 되겠지만, **프레임 상단선, 코받침, 굵은 검은 테**는 랜드마크 polygon 밖에 남을 수 있다.
- morphology는 경계 누수를 줄이는 데는 유효하지만, **피부 마스크 안쪽으로 들어온 비피부 구조물**까지 구분해 주지는 못한다.
- 세그멘테이션 전에 시도할 수 있는 현실적인 중간안은 **ROI 내부 이미지 기반 exclusion map**이다.
- 예: `combined_mask` 안쪽에서 강한 luminance edge + 저채도/dark thin structure를 검출해 `smooth` 마스크만 추가 감쇠.
- 이 방식은 `매끈하게` haze에는 직접적이고, `모공` 축까지 같이 죽일 가능성은 비교적 낮다.

#### 4. `매끈하게`와 `모공`이 같은 마스크를 공유하지 않는 편이 낫다

- `매끈하게`는 비피부 누수에 매우 민감해서 **더 보수적인 마스크**가 필요하다.
- 반대로 `모공`은 볼/코 피부 영역을 충분히 포함해야 해서, 마스크가 너무 줄면 **효과 자체가 약해질 수 있다.**
- 즉 마스크 정밀도 문제는 "더 많이 빼자"로만 풀 수 없고, **어떤 효과에 얼마나 보수적으로 적용할지**까지 같이 설계해야 한다.
- 최소한의 1차 실험으로도
  - `base_skin_mask`
  - `smooth_mask = eroded(base)`
  - `pore_mask = base 또는 light-eroded`
  처럼 **2계층 마스크**를 나눠 보는 가치가 있다.

### Codex 제안: A/B를 그대로 쓰기보다 `A' + B' + Mask Split`으로 시작

| 순서 | 작업 | 이유 |
|------|------|------|
| 1 | **A' — 코 전체가 아니라 콧구멍/콧볼 경계 보호 추가** | haze 원인 부위를 직접 겨냥하면서 코 피부 보정은 유지 |
| 2 | **B' — 정규화된 erode + 필요 시 비등방 shrink** | 얼굴 크기/ROI 해상도에 따라 일관된 동작 확보 |
| 3 | **Smooth/Pore 마스크 분리 실험** | `매끈하게`와 `모공`의 상충 요구를 구조적으로 분리 |
| 4 | **안경 전용 이미지 기반 exclusion 검토** | 랜드마크 기반 보호의 한계 보완 |
| 5 | **그래도 부족하면 세그멘테이션 검토** | 고비용 해법은 현 구조의 한계를 확인한 뒤 판단 |

## 4. Gemini 의견

Claude의 실용적 접근(A+B)과 Codex의 기술적 정교함(A'+B')에 동의하며, 이를 **"인지적 불일치 해소(Cognitive Discrepancy Resolution)"**와 **"적응형 마스크 엔진(Adaptive Mask Engine)"** 관점에서 보완합니다.

### 핵심 분석: "Haze"는 단순한 누수가 아니라 '경계의 파괴'

시각적으로 Haze가 느껴지는 이유는 피부가 아닌 곳에 블러가 먹었기 때문이기도 하지만, **인간의 뇌가 '형태를 인지하는 핵심 엣지(Anchor Edges)'가 뭉개졌을 때** 가장 강하게 발생합니다. 안경테, 콧날의 날카로운 선, 헤어라인의 대비가 그 예입니다.

### 1. "Anchor Edge" 기반의 동적 마스크 감쇠 (Dynamic Anchor Protection)

단순히 랜드마크로 영역을 빼는(Exclusion) 방식은 한계가 명확합니다. 랜드마크 사이의 직선/곡선은 실제 얼굴의 복잡한 윤곽을 완벽히 따라가지 못하기 때문입니다.

*   **Gemini 제안:** 마스크 생성 단계에서 **소벨(Sobel) 또는 캐니(Canny) 기반의 엣지 맵**을 추출하고, 이를 `combined_mask`와 곱하여 **"중요 엣지 위에서는 보정 강도가 자동으로 0에 수렴"**하게 만드는 하이브리드 방식을 도입해야 합니다.
*   **기대 효과:** 안경테나 콧날처럼 랜드마크가 듬성듬성한 곳에서도, 이미지 자체의 강한 선이 마스크를 '밀어내는' 효과를 주어 Haze를 원천 차단합니다.

### 2. 마스크의 '심도(Depth)' 개념 도입: Soft-errosion & Gradient Control

Codex가 제안한 `Mask Split`에서 한 걸음 더 나아가, 마스크를 단순히 0 또는 1이 아닌 **"영향력의 심도"**로 관리해야 합니다.

*   **Gemini 제안:** `smooth_mask`는 **비등방성(Anisotropic) 가우시안 블러**를 적용하여 얼굴 외곽(경계)으로 갈수록 급격히 감쇠하게 하고, `pore_mask`는 **등방성(Isotropic)**으로 유지하여 피부 면적을 최대한 확보합니다.
*   **수치적 제안:** `smooth_intensity`가 높아질수록 Erode의 강도를 비선형적으로 높이는 **'보수적 적응형 마스크(Conservatively Adaptive Mask)'** 로직을 추가하십시오. 많이 뭉갤수록(Smooth 높음) 더 좁은 영역만 건드려야 사고가 나지 않습니다.

### 3. 세그멘테이션(C)으로 가는 징검다리: "Color-Space Skin Likelihood"

TFLite 모델 도입(방안 C) 전에, 현재의 랜드마크 마스크 내부에 **"색상 기반 피부 확률(Skin Color Likelihood)"** 필터를 씌우는 것을 제안합니다.

*   **방법:** YCrCb 또는 HSV 색 공간에서 전형적인 피부톤 범위를 정의하고, 마스크 영역 내에서도 이 범위를 벗어나는 픽셀(안경테, 검은 머리카락, 콧구멍의 어둠)은 마스크 가중치를 0.2 이하로 즉시 떨어뜨립니다.
*   **장점:** 딥러닝 모델 없이도 픽셀 단위의 정밀도를 어느 정도 확보할 수 있으며, 연산 비용이 매우 낮습니다.

### Gemini의 최종 전략 제안: "2-Step Multi-Scale Refinement"

| 단계 | 명칭 | 핵심 로직 | 대상 문제 |
|------|------|----------|----------|
| **Step 1** | **Structural Anchor** | 랜드마크(A') + 이미지 엣지 기반 감쇠 | 안경테, 콧날, 콧구멍 Haze |
| **Step 2** | **Spectral Split** | Smooth(보수적/비등방) vs Pore(공격적/등방) 분리 | 경계 누수 vs 보정 면적 확보 상충 |

## 5. Claude 종합 (1차 의견 수렴)

### Codex 피드백 평가

**4개 보완 모두 유효합니다.** 특히:

1. **코 전체 제외가 아닌 콧구멍/콧볼 경계만 보호** — 맞습니다. 제 초안의 "코 보호 마스크"는 너무 광범위했고, 코 피부는 매끈하게/모공 모두의 핵심 타깃이므로 전체를 빼면 안 됩니다. `A → A'`로 수정합니다.

2. **Erode 정규화** — 맞습니다. 마스크 해상도가 64~256px로 가변이므로 고정 2~3px는 일관성이 없습니다. `mask_width` 비례로 가야 합니다.

3. **안경테는 랜드마크로 안 됨** — 맞습니다. 안경테는 MediaPipe가 추적하지 않으므로 랜드마크 기반 보호의 한계입니다. 이미지 기반 exclusion(luminance edge + dark structure)이 현실적인 중간안입니다.

4. **매끈하게/모공 마스크 분리** — **가장 중요한 지적입니다.** 프로토타이핑에서 매끈하게와 모공의 마스크 보수성 요구가 상충하는 것을 확인했습니다. 마스크 분리가 **유력한 우선 실험안**이며, 단일 마스크 + 효과별 soft attenuation 조합이 충분한지는 아직 검증 전이므로 "구조적으로 불가능"이 아닌 "유력 가설"로 취급합니다.

### Gemini 피드백 평가

**방향은 맞지만 과잉 설계 경향이 있습니다.**

| 제안 | 판단 | 이유 |
|------|------|------|
| Anchor Edge (Sobel/Canny 기반 마스크 감쇠) | **부분 수용** | Codex의 "이미지 기반 exclusion"과 방향은 같지만 **역할이 다름**: 마스크 단계의 edge exclusion은 적용 영역 자체를 줄이는 것(형태 보존)이고, 셰이더의 edgeProtection은 포함된 영역 안에서 compression을 낮추는 것(질감 보존). 중복이 아닌 **보완 관계**일 수 있으므로, 적용 위치와 역할 분리를 설계 시 확인 필요 |
| Color-Space Skin Likelihood | **수용** | 비용 대비 효과 좋은 제안. 단, Gemini 원안의 "0.2 이하로 즉시 떨어뜨린다"는 하드 컷은 조명/피부톤 다양성에 취약하므로 **soft likelihood attenuation**(확률적 가중치 감쇠)으로 적용해야 함 |
| 비등방성 가우시안 블러 + 보수적 적응형 마스크 | **거부** | 현 단계에서 과잉. 먼저 단순한 erode + 마스크 분리로 효과를 확인하고, 부족하면 그때 검토 |
| "인지적 불일치 해소" 프레이밍 | **거부** | 불필요한 추상화. "경계가 뭉개지면 뿌옇게 보인다"로 충분 |
