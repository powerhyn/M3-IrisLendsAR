# NLR-W2 합성 수식 벤치 기록

> 기기 S23+, 1인 실시간 토글 육안 체감. 블라인드 A/B/C/D(정답표는 GpuRenderActivity.kt benchCombos에만).
> 조건: lum:meas 고정, veto legacy 0 고정, cap 기본 1.275 고정.

## Round 1 (2026-07-03, APK b284) — Codex R1 3후보

| 슬롯 | 수식 | 판정 |
|---|---|---|
| A (ID5) | 현행 TintLinearV2 | **가장 자연스러움** — 단 경계 이질감은 여전 |
| B (ID3) | KM 반투명 코팅 | 스티커 느낌, B~D 간 편차 작음 |
| C (ID4) | Oklab mean-shift + guard | 〃 |
| D (ID6) | Pivot bidirectional | 〃 |

**사용자 원문**: "b~d까지는 큰 편차 없이 스티커 느낌의 렌더링으로 너무 어색하고 A가 그래도 자연스러운 편인데 이 경우에는 경계가 여전히 이질적."

### 해석 (수치 분석, 가설 → Round 2로 검증)

- B~D 공통점 = "균일 목표색" 계열 → **바탕 대비 전달률**이 낮음. KM의 바탕 반응 기울기 ≈ Tc²/(1−Rc·base)² ≈ 0.07 (바탕 텍스처의 ~7%만 결과에 반영) ↔ 현행 A(곱셈형)는 홍채 위 기울기 ≈ lensL×scale ≈ 2.5.
- **곱셈형은 대비 비율을 보존**(홍채 결 유지), 가산/코팅형은 절대차만 보존(어두운 바탕에서 결이 소멸) → 스티커.
- 따라서 A의 결함은 곱셈 골격이 아니라 **정규화 기준(avg_iris_luma)이 흰자 픽셀에도 적용**되는 것 하나 — W1 재정의("경계 톤 불연속")와 정합.

## Round 2 (준비) — 후보 E: TintLinear radial-pivot

D 슬롯(ID6) 교체. 곱셈 골격 유지 + 정규화 기준을 공간 연속 보간:
`ref = mix(avgIrisLum, 0.70, smoothstep(1.0, 1.25, irisDist))` → `tintMul = min(lum×clamp(0.85/ref, 0.8, 7.0), cap)`

- 홍채 내부: 현행 A와 **비트 동일** (자연도 보존)
- 흰자: ref≈0.70 → tintMul≈0.85 = 홍채 평균 톤과 일치 (target 0.96→0.64, Δfinal ≈ −11%p 가시)
- 근거: 리서치 F3(Meta localized tone mapping)·F9(Chanel 국소 통계)·F12(ModiFace radial)의 1-tap 합성. Codex R2 검토 예정(채택 전).

### Round 2 결과 (2026-07-03, b285→b286)

- **E-v1 (램프 1.0~1.25, b285)**: "여전히 비슷" — 램프 창 오설계. 가시 띠(1.0~1.15)에 보정 0~40%만 적용, 100% 구간은 veto/feather로 알파가 죽은 바깥 (cap 실패 함정의 변형).
- **E-v2 (램프 0.90~1.10, b286)**: 사용자 "밝은 부분에서 더 밝게 빛나는 느낌 — 곱연산 같다" + 캡처 판독(w2r2_05_A vs 06_D): **역설 발견** —
  - 곱셈 구조는 그대로라 밝기 비례 자체는 불변 (사용자 직관 정확)
  - **톤 매칭의 역효과**: A는 흰자 위에서 ~흰색(0.96)까지 올라가 흰자에 위장되는데, E-v2는 홍채 톤(회베이지)으로 맞춰져 **흰 흰자와의 대비가 커져 솔리드 띠로 더 도드라짐**. "경계 톤 일치" 목표가 흰자 위에서는 오답.
- **방향 전환**: 검증 클레임(실물 렌즈 외곽=최암 잉크, 흰자 겹침부 반투명 가라앉음)대로, 밝은 패턴 에셋의 흰자 겹침부는 톤 축이 아니라 **알파 축(조기 페이드)**. Normal 진단("수식 무관 빛남")과도 정합.

## Round 3 (준비, b287) — 후보 E-v3: V2 수식 그대로 + sclera 알파 조기 페이드

`fade = 1 − smoothstep(0.95, 1.15, irisDist)` → `mix(baseL, tinted, opacity × fade)`
- 홍채 내부(≤0.95): 현행 A와 동일
- 흰자 겹침 띠: 1.15에서 렌즈 완전 소멸 (서클 확대감 ~15% 보존)

### Round 3 결과 (b287, E-v3)

- 사용자: "여전히 밝은 부분은 더 밝은 느낌" + **"기존 구현 무시하고 리서치대로 가는 게 맞지 않냐"** 재확인 요청.
- 자기 교정: E 계열은 리서치 1번 결론("휘도 곱셈 주입은 선례 없음")에서 이탈한 경로였음을 인정. 1차 후보들의 스티커 룩은 리서치가 아니라 **구현 근사(국소 블러 대신 전역 평균)** 탓 — Meta 계열의 질감 전달은 주파수 분리가 본질.

## Round 4 (준비, b288) — 후보 G: quotient 셰이딩 트랜스퍼 (리서치 정실 구현)

`detail = clamp(lum / blurLum(3×3, C10 패턴), 0.6, 1.6)` → `tinted = lensL × 0.85 × detail`
- 틴트 레벨 = 상수 (**밝기 비례 항 구조적 부재** — "밝은 부분 더 밝음" 소멸 예상)
- 질감 = 국소 비율(quotient)로 곱셈 전달 (A가 자연스러웠던 메커니즘 보존)
- 부수: 작은 캐치라이트는 비율이 커져 틴트를 뚫음 (W3 목표 부분 커버)

슬롯: A=현행 V2 / **B=G 단독** / C=G+흰자 페이드(0.95→1.15) / D=E-v3(V2+페이드만)

### Round 4 결과 (b288~b290)

- **G(quotient, B)**: "전체 톤 균일은 달성, 그러나 스티커 같은 어색함" — 3×3 국소비율이 미세 질감만 남기고 중간 스케일 홍채 구조를 소거. 홍채 내부 느낌은 A(V2 전대역 곱셈)가 훨씬 좋음. → 사용자 제안: 알파를 낮추는 방향(투명도 슬라이더로 시험 가능).
- **D(V2+페이드) 무변화 + cap 스윕 무변화** 신고 → R5 진단으로 전환.

## Round 5 (b291~b292) — 진단 및 재정비

- **기하 디버그(C 슬롯, irisEdgeDist 밴드 시각화) 결과**: 빨강(페이드 창 0.95~1.15)이 빛나는 링과 겹치긴 하나, **링의 밝은 부분이 초록(<0.95, "홍채 안쪽" 판정 존)에도 걸침** → **검출 홍채 반경 > 실제 홍채** 오차 확정. 기하 기준 마스크(페이드·veto 시작점)가 실제 홍채/흰자 경계보다 바깥에 있어 페이드가 가시 링을 못 자르던 원인.
- **사용자 가설 명확화**: "조명 적응을 빼자" = 반사류가 아니라 **"바탕이 밝으면 렌즈를 더 밝게 그리는" 메커니즘 제거** — ① 픽셀 단위 lum 곱셈 + ② 장면 단위 avgLum 정규화 둘 다. → **B 슬롯 = 상수 틴트**(`tint = lensL × 0.85` 고정)로 재배선(b291), 가설 직접 검증 대기.
- **재배선(b291~292)**: B=상수 틴트 / C=기하 디버그(창이 슬라이더 연동) / D=V2+페이드(창 슬라이더 연동). **dead "밝기" 슬라이더 → uFadeStart(0.8~1.4) 재배선** — C로 빨강 창을 링에 맞추고 D로 결과 확인하는 라이브 튜닝 루프 완성. cap 신설 sweep {0.95,1.05,1.15,off}(하한 0.85 확장)은 A/D에서만 유효.

### Round 5~6 결과 (b291~b293)

- 상수 틴트(R5 B)는 **사용자 의도 오해석** — 정정: "tint-linear는 유지, **장면 밝기에 따른 증폭(scale=0.85/avgLum)만 고정**" → R6 B = TintLinear 고정 K=3.4.
- **⭐ R6 핵심 판정 (b293)**: **B(고정 K=3.4)에서 밝게 빛나는 현상 소멸. A(적응)에서는 잔존.**
  - 해석: 빛남의 주범 = 적응이 실내에서 만드는 **고증폭(K 5.5~7)**. K≈3.4면 중간 휘도 픽셀(눈꺼풀/경계, lum 0.25~0.45)의 tintMul이 1.0~1.4에 머물러 화이트화 안 됨.
  - lum:meas↔fb는 **선명도만 영향, 빛남 무관** (둘 다 이 조명에선 고K 영역이라 정합).
- **cap: 전 모드·전 값(0.95 포함)에서 무변화** — 이론(A에서 0.95면 가시 변화)과 불일치 → **배선 단절 의심**. R6b에서 C 디버그에 cap 진단(보라 혼색) 추가.
- C 디버그 의미 정정 안내: 빨강=전환 램프(부분 렌더), **파랑=완전 컷** — 링 소멸은 링이 파랑에 들어가야.

## Round 6b (b294) — K 라이브 스윕 + cap 배선 진단

- B: `K = 슬라이더값 × 4` (f0.8→3.2 ~ f1.4→5.6) — 빛남 시작 K 임계 탐색 + 선명도 최적점.
- C: cap ≤ 1.2면 밴드 보라 혼색 — cap 버튼 눌러 색 변화 없으면 setScleraTintMax 체인 단절 확정.
- **수렴 중인 canonical 가설**: `TintLinear + scale 상한 대폭 강화` — 기존 clamp(0.85/avgLum, 0.8, **7.0**)의 상한 7.0이 병인. B 스윕으로 찾은 "빛남 임계 K" 직하로 상한을 내리면(예: 3.5~4) 적응은 유지하되 고증폭 구간만 제거 — canonical 변경이 상수 1개로 끝남.

### Round 6b~7 결과 (b294~b296)

- **B 스윕 판정: 빛남 임계 f≈1.1 = K≈4.4** (그 이하는 빛남 없음). → canonical 후보 = 기존 scale clamp 상한 7.0 → **4.0~4.2**(임계 직하)로 인하.
- cap 보라 진단(C): **판정 미수신** — cap 배선 여부 미결 (kickoff §남은 판정 참조).
- R7(b296): B = K 4.2 고정 + 슬라이더 = 채도 부스트(1.0~2.2, 휘도 보존) — **판정 대기**. 보조 축: 투명도 슬라이더 조합.
