# P7-W4 (NLR-W1) cap sweep 벤치 결과 — 판정: cap 무효 + 문제 재정의

> 일자: 2026-07-03. 기기 S23+ (APK b283), SKU 6 누드 애쉬 로제, 형광 실내, lum:meas.
> 방법: cap 토글 {OFF → 1.275 → 1.5 → 2.0} 자동 화면 캡처(logcat 감시 연동) + 사용자 실시간 육안 + Normal 블렌드 진단 대조.

## 판정

**cap(uScleraTintMax) 효과 미미 — 무효.** 3중 근거:
1. 사용자 육안: "별 차이 없는 느낌" (OFF↔1.275↔1.5↔2.0)
2. 캡처 대조: 같은 프레이밍 샷 간 diff가 모션/지터 성분과 분리 안 됨, 흰자 링은 전 값에서 잔존
3. **Normal(증폭 0) 진단**: 증폭이 전혀 없는 Normal에서도 밝은 링이 흰자 위에 그대로(오히려 더) 보임 → "lum 증폭 = 빛남 원인" 가설 기각

**soft-knee fallback도 진행 안 함** — 같은 틴트-배율 축의 다른 형태라 동일하게 무효 예상.

## 원인 분석 — R1 합의의 visibility budget 누락

`Δ출력 = α_sclera(veto·feather로 축소) × Δ(틴트색)` 인데:
- 밝은 SKU는 렌즈색 linear ≈ 0.7~0.85 → tintMul 1.275만 돼도 출력이 흰색 상한(클립) 근처 → cap OFF(클립 1.0)와의 색 차이 수 %
- 그 수 %에 veto로 줄어든 α를 곱하면 **1~3% → 인지 불가**
- R1(2026-06-10) 3모델 합의 "(c) 비율 cap"은 이 계산을 생략한 물리 가정 오류. 메모리 `physical-assumption-validation`(R1 전 visibility budget 필수) 재위반 사례 — 환경 반사 옵션 C와 동일 실패 패턴.
- 정합 증거: 재베이스라인에서 증폭 강도가 크게 다른 lum:meas↔lum:fb의 빛남이 둘 다 ②로 동일했음.

## ⭐ 문제 재정의 (사용자 인사이트, 2026-07-03)

> "Normal은 그냥 위에 얹는 거라 **동일한 톤**으로 렌더링돼서 거슬릴 게 없는데, Lum Tint는 **경계를 기준으로 서로 다른 톤**으로 렌더링되니까 어색하게 느끼는 것."

- 진짜 문제 = "흰자가 밝다"가 아니라 **휘도 비례 틴트가 만드는 공간적 톤 불연속** (홍채 위=어둡게 녹음 / 흰자 위=밝음 — 같은 렌즈가 두 톤으로 갈라짐)
- 처방 방향 = 틴트-배율 상한이 아니라 **공간적으로 연속인 합성 수식** (선례 힌트: ModiFace 공간 가중, US6508553 radial fade)
- → 기존 구현(TintLinearV2 계열 패치)에 집착하지 않고 **최적 합성 수식 원점 재조사** 결정 (deep-research → Codex 교차 검토)
