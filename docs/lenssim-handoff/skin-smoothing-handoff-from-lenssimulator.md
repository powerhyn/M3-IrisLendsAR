# 피부 보정(Skin Smoothing) 이식 스펙 — LensSimulator에서 검증 완료

> 출처: `/Volumes/M3-P31/Projects/TedMong/CGG/LensSimulator` (CGG 렌즈 시뮬레이터 SDK, 2026-06-10)
> 검증: Galaxy S23+ 실기기 육안 평가 통과 (사용자 승인 — "아주 마음에 듦"), 30fps 유지
> 이 문서는 동일 방식을 IrisLensSDK에 적용하기 위한 전달 스펙이다.

## 알고리즘 개요 (3단계)

```
① 스킨 마스크 (1/4 해상도 R8)
   얼굴 외곽 폴리곤(값 1) − 눈썹×2/입술/눈 윤곽×2(값 0 덮어쓰기) → 가우시안 블러(페더링)
② 컬러 블러 (1/4 해상도 RGBA)
   분리형 가우시안 5-fetch × 2패스
③ 컴포지트 (풀해상도, 프래그먼트)
   에지 가드 + 디테일 보존 합성
```

## 핵심 셰이더 (GLSL 원문 — 검증된 확정 파라미터)

```glsl
// base = 원본 카메라, blur = ②결과, mask = ①결과 (모두 디스플레이 공간 동일 UV)
float lumaBase = dot(base, vec3(0.299, 0.587, 0.114));
float lumaBlur = dot(blur, vec3(0.299, 0.587, 0.114));
// 에지 가드 (surface blur 근사): 강한 에지(코선·얼굴 윤곽·머리카락·안경)는
// |base-blur| 휘도차가 커서 스무딩에서 자동 제외 — 저대비 질감(모공·잡티)만 평탄화
float edge = smoothstep(0.06, 0.18, abs(lumaBase - lumaBlur));
vec3 smoothed = blur + (base - blur) * 0.5;   // 고주파 디테일 50% 보존
base = mix(base, smoothed, mask * strength * (1.0 - edge));
```

**에지 가드가 품질의 핵심**이다. 이게 없으면 "전체적으로 뿌옇고 뭉개진" 느낌이 난다
(실기기에서 확인된 실패 모드). 에지 가드 도입 후 모공/잡티만 정리되고
코선·팔자·안경테·머리카락 경계가 선명하게 유지된다.

## 스킨 마스크 상세

### 랜드마크 (MediaPipe Face Mesh 478점 기준)

| 폴리곤 | 값 | 인덱스 |
|---|---|---|
| 얼굴 외곽 36점 (순서 체인) | 1 | `10,338,297,332,284,251,389,356,454,323,361,288,397,365,379,378,400,377,152,148,176,149,150,136,172,58,132,93,234,127,162,21,54,103,67,109` |
| 우 눈썹 10점 | 0 | `46,53,52,65,55,107,66,105,63,70` (아래 폴리라인+위 폴리라인 역순) |
| 좌 눈썹 10점 | 0 | `276,283,282,295,285,336,296,334,293,300` |
| 입술 외곽 20점 | 0 | `61,146,91,181,84,17,314,405,321,375,291,409,270,269,267,0,37,39,40,185` |
| 눈 윤곽 16점 ×2 | 0 | 우 `33,7,163,144,145,153,154,155,133,173,157,158,159,160,161,246` / 좌 `362,382,381,380,374,373,390,249,263,466,388,387,386,385,384,398` |

- 각 폴리곤은 무게중심 기준 TRIANGLE_FAN으로 렌더 (블렌딩 없이 값 덮어쓰기, 순서 중요: 외곽 먼저)
- 마스크 FBO에 그린 뒤 가우시안 블러 1회로 페더링 (저해상도 + bilinear가 추가 페더 제공)

### 이마 확장 (필수 — 실기기에서 발견된 문제의 해법)

MediaPipe 얼굴 윤곽 상단점(랜드마크 10)은 **헤어라인보다 한참 아래(이마 중간)**에 있어
그대로 쓰면 이마 상부가 보정에서 빠진다 (실기기 확인된 실패 모드).

해법: 광대 라인(454·234 중점)을 피벗으로, 그보다 위쪽 윤곽점들을
얼굴 세로축(턱152→이마10 단위벡터) 방향으로 **+35%** 늘린다:

```
up = normalize(forehead - chin)          // 픽셀 공간에서 계산
pivot = (cheekL + cheekR) / 2
for each point p:  t = dot(p - pivot, up)
                   if (t > 0) p += up * t * 0.35
```

- 가로 폭은 늘리지 않음 (축 방향 변위만), 턱/볼 라인 불변
- 헤어라인을 살짝 넘어가도 에지 가드가 머리카락 경계를 보호하므로 안전
- **주의**: 이 확장은 마스크 전용 — 다른 용도(워프 제어점 등)는 원본 윤곽 사용
- 참조 구현: `LensSimulator/sdk/android/.../internal/math/BeautyGeometry.kt#extendForehead` (단위 테스트 포함)

## 컬러 블러 상세

- 1/4 해상도, 분리형 가우시안 H/V 2패스
- 5-fetch linear sampling 트릭: offsets `0, 1.3846, 3.2308` (×offsetScale), weights `0.227, 0.3162, 0.0702`
- **offsetScale = 1.6** (2.0에서 완화 — 2.0은 뭉개짐, 실기기 튜닝값)
- 마스크 블러는 offsetScale 1.0

## 확정 파라미터 요약 (실기기 튜닝 완료)

| 파라미터 | 값 | 비고 |
|---|---|---|
| 에지 가드 smoothstep | 0.06 ~ 0.18 (휘도차) | 낮추면 더 많이 보호(보정 약화) |
| 디테일 보존 | 0.5 | 0.45는 약간 플라스틱 |
| 컬러 블러 offsetScale | 1.6 | 1/4 해상도 기준 |
| 이마 확장 | 0.35 | 광대 피벗, 축 방향 |
| 저해상도 타깃 | 뷰포트 1/4 | RGBA×3 + R8×2 |

## 비용 규율 (적대적 리뷰에서 확정된 요구사항)

1. **강도 0이면 비용 0**: 블러/마스크 패스 전부 생략 + 랜드마크 추출(얼굴 외곽 등)도
   뷰티 활성 플래그로 게이팅 (OFF 시 추출/필터링 생략)
2. **저해상도 타깃 지연 생성**: 첫 활성 프레임에 생성 (미사용 호스트 GPU 메모리 0)
3. 얼굴 외곽 점들은 One-Euro 필터 적용 (픽셀 공간, min_cutoff 0.5/beta 0.007) — 마스크 경계 흔들림 방지

## 함정 (우리가 밟은 것들 — 그대로 피할 것)

1. **렌즈 패스가 컴포지트 결과를 덮어쓰지 않게 할 것**: 렌즈 셰이더가 원본 카메라를 base로
   샘플해 불투명 출력하면, 렌즈 쿼드 사각형 영역의 피부 보정이 원본으로 되돌아간다
   (눈 주변 사각 패치 아티팩트). 해법: 렌즈 패스를 알파 블렌딩으로 전환 — `out = (tinted, a)`
   + SRC_ALPHA/ONE_MINUS_SRC_ALPHA. (적대적 리뷰 3관점이 독립적으로 발견한 blocker였음)
2. 마스크/블러 텍스처는 컴포지트와 **동일한 디스플레이 공간 UV**로 샘플 (다른 워프/변형이
   있다면 변형 후 UV로 샘플해야 정합)
3. 눈썹/입술/눈 제외 폴리곤을 마스크 블러 **전에** 그릴 것 (블러가 제외 영역도 페더링)
