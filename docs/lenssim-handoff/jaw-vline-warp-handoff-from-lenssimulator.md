# 핸드오프: 턱선 V라인 워프 — 확정 알고리즘·파라미터

> 출처: LensSimulator 실기기(S23+) 반복 검증 (2026-06-12, 커밋 6bacaec).
> 정본 코드: `LensSimulator/sdk/android/.../internal/math/BeautyGeometry.kt` (computeJawWarp),
> `LandmarkIndices.kt` (OVAL_JAW_CONTROL), `Renderer.kt` COMPOSITE_FS ①절, `BeautyGeometryTest.kt`.
> 피부 보정 핸드오프(skin-smoothing-handoff)와 같은 컴포지트 패스에서 동작하는 자매 스펙이다.

## 0. 모델 한 줄 요약

**인버스 워프**: 출력 픽셀 p의 소스 좌표 = `p − Σᵢ dᵢ·exp(−|p−cᵢ|²/2σ²)`
(cᵢ = 얼굴 측면 윤곽 제어점, dᵢ = 얼굴 세로축 방향 "안쪽" 변위, 전부 **디스플레이 픽셀** 공간).
정규화 좌표 계산 금지 — 종횡비 왜곡 (함정 #5 계열).

## 1. 확정 파라미터 (실기기 3회 반복으로 수렴)

| 파라미터 | 값 | 근거 |
|---|---|---|
| 제어점 | **측면 7점 × 양쪽 = 14점** — FACE_OVAL 체인에서 좌측 랜드마크 (323,361,288,397,365,379,378) / 우측 (93,132,58,172,136,150,149) | 볼 상부(광대 직하)부터 턱끝 옆까지. **광대 정점(454/234)·턱끝(152)은 제외** |
| 테이퍼 (볼 상부→턱끝 옆) | **[0.2, 0.45, 0.65, 0.85, 1.0, 0.85, 0.6]** | 광대 직하 0.2에서 완만 시작 → 하악체 최대 1.0 → 턱끝 옆 0.6 |
| 최대 변위 | **얼굴 폭(광대 간 거리) × 3.2%** × strength(0..1) | 4.5%는 풀 강도에서 과격 |
| 가우시안 σ | **얼굴 폭 × 13%** | 16%는 변위장이 볼 중앙까지 번짐 |
| 변위 방향 | 얼굴 세로축(이마 10 → 턱 152) 단위벡터에 대한 **수직 성분의 반대(안쪽)** | 좌우 대칭 자동 보장, roll 각도 불변 |
| 셰이더 early-out | 제어점 바운딩박스 + **3σ 마진** 밖이면 루프 생략 | 박스 밖 가중치 < e⁻⁴·⁵ ≈ 0.011 (서브픽셀) |
| 입력 | **One-Euro 필터링된** FACE_OVAL (전용 72채널) | 무필터 제어점이면 턱선이 출렁임 |
| 데모 기본 강도 | **25%** (풀 100%는 "확실하지만 자연스러운" 상한) | 사용자 확정 프리셋 |

## 2. 설계 이력 — 왜 이 값인가 (같은 실수 반복 방지)

실기기 피드백으로 기각된 2개 설계를 그대로 기록한다:

1. **하악선 5점 + 테이퍼 [0.6, 0.85, 1.0, 0.95, 0.8]** (초판):
   광대 바로 아래 제어점부터 최대 변위의 60%로 당김 → **볼이 쪽 빨려 들어가
   홀쭉해 보이는** 부자연스러움. 사용자: "볼을 쪽 빨아들여서 홀쭉하게 된 것처럼".
2. **하악선 5점 + 테이퍼 [0.1, 0.4, 0.8, 1.0, 0.7]**:
   상단을 죽이자 이번엔 **줄어들기 시작하는 위치가 턱관절 아래로 보임** — 시작점이
   너무 낮아 광대~턱 라인이 끊겨 보임.
3. **확정안**: 제어점 자체를 볼 상부까지 2점 상방 확장(5→7점/측) + 0.2부터의 그라데이션.
   "광대에서부터 완만하게 시작해 끊김 없이 이어지는 V라인"이 자연스러움의 핵심이었다.

## 3. 불변 조건 (위반 시 렌즈가 어긋난다)

- **눈 높이 변위 ≈ 0**: 워핑은 렌즈 합성보다 **앞** 단계다 (피부 → 워핑 → 렌즈).
  렌즈 쿼드는 무워프 랜드마크 좌표에 그려지므로, 워프가 눈 높이 픽셀을 움직이면
  홍채 픽셀과 렌즈가 어긋난다. **광대 정점을 제어점에서 제외한 이유**가 이것 —
  볼 상부(0.2)가 이 조건을 지키는 상한 부근이며, 단위 테스트가 게이트한다
  (BeautyGeometryTest: 눈 위치 변위 < 최대 제어점 변위의 5%).
- σ가 얼굴 폭 대비 작아야 위 조건이 성립한다 — σ를 키우려면 눈 높이 테스트를 같이 볼 것.
- **이마 확장(extendForehead)은 피부 마스크 전용** — 워프 제어점 계산에는 확장 전
  원본 oval을 쓸 것 (혼용하면 제어점이 위로 밀림).
- 퇴화 방어: 세로축 길이 < 1px 또는 광대 폭 < 8px이면 σ=0 반환 (워프 비활성).

## 4. 셰이더 평가부 (GLSL 검증본 — 컴포지트 프래그먼트 ①절)

```glsl
uniform vec4 uWarp[14];    // [cx, cy, dx, dy] — 디스플레이 px
uniform int uWarpCount;
uniform float uWarpSigma;  // px. 0이면 워프 꺼짐
uniform vec4 uWarpBounds;  // 제어점 [minX, minY, maxX, maxY] + 3σ 마진

vec2 dispUv = vUv;
if (uWarpSigma > 0.0) {
    vec2 px = vUv * uViewportPx;
    // 바운딩박스 밖이면 루프 생략 — uniform 기반 분기라 타일 단위 코히런트
    if (all(greaterThanEqual(px, uWarpBounds.xy)) && all(lessThanEqual(px, uWarpBounds.zw))) {
        vec2 disp = vec2(0.0);
        float inv2s2 = 0.5 / (uWarpSigma * uWarpSigma);
        for (int i = 0; i < uWarpCount; i++) {
            vec2 d = px - uWarp[i].xy;
            disp += uWarp[i].zw * exp(-dot(d, d) * inv2s2);
        }
        dispUv = (px - disp) / uViewportPx;
    }
}
// 이후 dispUv로 크롭/회전/미러 체인 → 카메라 샘플 (워프가 체인 최상단)
```

CPU 측(computeJawWarp)은 제어점·변위·바운딩박스를 프레임당 채워 유니폼으로 넘긴다
(uWarp 40→56 floats, 할당 0 — 배열 재사용). 강도에는 얼굴 소실 페이드를 곱해
스냅 오프를 방지한다.

## 5. IrisLensSDK 매핑 노트

- 감사 보고서의 **grid_mesh RBF 수학 결함 finding**(zero-변위 컨트롤 제외로 거리 감쇠
  소실 + 임계 절벽 + 정규화 공간 비등방 σ)과 직결된다: 본 스펙의 모델이 바로 감사
  수정안이 권고한 **"비정규 RBF 합(가우시안 가중 변위 합)"** 의 검증된 구현이다.
  grid_mesh를 수리하는 대신 이 모델로 교체하는 쪽이 단순하다 (메시 보간 불필요 —
  프래그먼트에서 직접 평가, 제어점 14개 × exp 1회는 바운딩박스 안에서만).
- face_warp_controller의 슬림페이스/V라인이 소비처라면: 픽셀 공간 계산(감사 finding
  "정규화 공간 비등방 sigma"의 처방)과 눈 높이 변위 ≈ 0 게이트 테스트를 함께 이식할 것.
- 468/478 랜드마크 번호는 동일 규약 (FACE_OVAL 체인은 MediaPipe canonical) —
  ADR-0001의 좌표 계약(§7) 하에서 그대로 유효.
- 단위 테스트 5종을 함께 이식 권장: 변위 방향(세로축 향함) / strength≤0 비활성 /
  눈 높이 변위 < 5% / 3σ 바운딩박스 정합 / 퇴화 입력 방어 — 합성 타원 얼굴로
  실랜드마크 없이 검증 (BeautyGeometryTest.kt 참조).
