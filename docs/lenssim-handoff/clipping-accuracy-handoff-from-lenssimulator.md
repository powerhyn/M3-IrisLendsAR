# 눈꺼풀 클리핑 정확도 인사이트 — LensSimulator → IrisLensSDK 핸드오프

작성: 2026-07-09 (LensSimulator 세션)
근거: LensSimulator 실기기(Galaxy S23+) 튜닝 확정 — 자글거림 3차 수정(`9152c0f`→`6a42a84`→`94b41f8`)
+ 클립 tuck 리매핑(`b8349eb`) + 계수 확정(`b0d1498`, 2026-07-09)
선행 문서: `mediapipe-internal-smoothing-bypass-handoff-from-lenssimulator.md` (IMAGE 모드 —
본 문서 §5에서 승격 확정 소식 포함)

> 이 문서는 **구현 코드 이식이 아니라 진단·교훈 인사이트**다. IrisLensSDK는 C++ 코어에서
> 자체 눈꺼풀 마스크·클리핑을 소유하므로, 아래 교훈을 각 단계(래스터/샘플링/리매핑/추적)에
> 맞게 대입하면 된다. 모든 수치는 LensSim 실기기(S23+, 1440×1080 프리뷰)에서 확정된 값.

---

## TL;DR

눈꺼풀 클리핑의 "정확도"는 서로 다른 4개 층의 문제가 겹쳐 보이는 것이었고, 층별로 따로
잡아야 했다:

1. **래스터 층 — 경계 텍셀 크롤링**: 저해상 마스크의 **이진** 래스터는 폴리곤이 서브텍셀
   이동할 때마다 경계 텍셀이 통째로 튄다(자글거림). 샘플링 측 스무딩(텐트 커널)은 완화일
   뿐이고, **래스터 측 MSAA(4×)가 원천 해결**이었다.
2. **해상도 층 — 안각 곡률**: 마스크 192×144는 안각(눈꼬리) 곡률이 뭉개진다. **256×192**로
   상향해 해소 (ADR-0008).
3. **리매핑 층 — 페더를 그대로 쓰지 말 것**: 마스크 페더 원본은 경계가 물렁해 '스티커가
   떠 있는' 느낌. 선형 tuck 리매핑(아래 §3)으로 경계를 눈 안쪽으로 당기고 전이 폭을 좁히는
   것이 착용감의 핵심이었고, **실기기 확정값은 최대치(tuck=1.0)** — 사용자는 렌즈가
   눈꺼풀에 확실히 '먹히는' 타이트한 클립을 선호했다.
4. **추적 층 — 위상 정렬**: 눈꺼풀 윤곽 점들을 렌즈 기저와 **동일 상수의 One-Euro**로
   필터링해야 한다. 무필터(또는 다른 상수) 윤곽은 필터된 렌즈 본체와 위상이 달라 클리핑
   경계만 따로 떨린다.

## 1. 래스터 층 — 마스크 MSAA가 근본 해결 (`94b41f8`)

증상: 정지 자세에서도 클리핑 경계가 프레임마다 자글자글 끓는다.

원인 진단: 눈꺼풀 마스크를 저해상 FBO에 **이진(안티앨리어싱 없는) 폴리곤 래스터**로 굽고
있었다. 랜드마크가 서브텍셀만 움직여도 경계 텍셀의 커버리지 판정이 0↔1로 통째로 뒤집힌다
— 경계가 텍셀 격자를 '기어가는'(crawling) 계단 노이즈.

시도 계보 (샘플링 측 → 래스터 측):
- 2×2 하프텍셀 박스 샘플: 잔여 큼 (1차)
- 3×3 텐트(1-2-1) 샘플: 완화되지만 잔여 (2차, `6a42a84`) — bilinear와 합쳐 ~3텍셀 스무딩
- **마스크 FBO를 MSAA 4×로 래스터 후 resolve: 원천 제거** (3차, `94b41f8`) — 경계 텍셀이
  이진이 아니라 커버리지 비율(0..1)을 갖게 되어 서브텍셀 이동이 연속값 변화로 나타난다.

교훈: **샘플링 커널을 키우는 것은 대증요법이다.** 노이즈의 원천이 래스터의 이진성이면
래스터에 안티앨리어싱(MSAA 또는 커버리지 계산)을 넣는 것이 맞고, 그 후 텐트 샘플은
선명도를 해치지 않는 수준(3×3 1-2-1)만 남기면 된다. tuck 리매핑(§3)이 전이 폭을 다시
조여주므로 스무딩으로 인한 물렁함은 상쇄된다.

## 2. 해상도 층 — 256×192 (ADR-0008, `e0c301b`)

192×144에서는 안각 근처의 눈꺼풀 곡률이 텍셀 몇 개로 뭉개져 클립 경계가 실제 눈매와
어긋났다. 256×192로 상향하니 해소. 비용은 마스크 래스터 픽셀 수 +78%지만 저해상 FBO라
전체 프레임 예산에서 무시 가능했다. (참고: 해상도를 올리면 그림자 밴드처럼 "텍셀 수 기준"
으로 설계된 효과의 실효 폭이 달라진다 — LensSim에선 그림자 강도 재튜닝이 필요했다.
마스크 해상도에 의존하는 파생 효과가 있다면 함께 점검할 것.)

## 3. 리매핑 층 — tuck 리매핑, 확정값 1.0 (`b8349eb` 도입 → `b0d1498` 확정)

마스크 페더 값 m(0..1)을 그대로 알파에 곱하면 경계가 넓고 물렁하다. 선형 리매핑:

```
tuckLo = 0.45 × t
tuckHi = 1.0 − 0.15 × t
m' = clamp((m − tuckLo) / max(tuckHi − tuckLo, 1e-4), 0, 1)
```

- t=0이면 항등(킬 스위치), t가 클수록 페더의 바깥쪽(m < tuckLo)이 잘려 경계가 눈 안쪽으로
  들어가고, 전이 폭(tuckHi−tuckLo)이 좁아져 또렷해진다.
- **실기기 확정 t=1.0 (슬라이더 최대)**: tuckLo=0.45, tuckHi=0.85 — 페더 하위 45%를 완전히
  잘라내는 강한 클립이 가장 자연스러웠다. "렌즈가 눈꺼풀 밑으로 들어가 보이는" 모습이
  착용감(밀착감)의 핵심이라는 것이 확정 결론.
- 파생 효과 동조: 윗눈꺼풀 접촉 그림자용 오프셋 샘플(maskAbove)에도 **동일한 리매핑**을
  적용해야 그림자 밴드가 클립 경계와 함께 움직인다 (리매핑을 한쪽만 하면 그림자가 경계
  바깥에 뜬다).
- 참고: EAR 기반 깜빡임 페이드는 LensSim ADR-0007/0008에서 기각 확정 — 깜빡임 대응은
  클립 마스크에 일임 (IrisLens 실기기 판정과 동일 결론 재확인).

## 4. 추적 층 — 윤곽 One-Euro 위상 정렬 (ADR-0008)

눈꺼풀 윤곽 16점(눈당)을 **렌즈 기저(홍채 중심·기저벡터)와 동일 상수**의 One-Euro로
필터링. LensSim 확정 상수: MIN_CUTOFF 3.0 / BETA 0.3 / D_CUTOFF 1.0 (near-raw 튜닝,
프레임 동기 체제 기준 — 정본 `FaceTracker.kt`).

핵심은 값 자체보다 **"본체와 윤곽이 같은 필터 상수"**라는 제약이다. 무필터 윤곽(혹은 다른
상수)은 필터된 렌즈 본체와 응답 위상이 달라, 렌즈는 가만히 있는데 클리핑 경계만 따로
떨리는 이중 떨림이 생긴다. IrisLens C++ 코어의 스태빌라이저에서도 "클리핑에 쓰는 윤곽
입력이 렌즈 위치와 같은 필터 체인을 통과하는가"를 점검할 가치가 있다.

## 5. 후속 확정 — IMAGE 모드 승격 (선행 문서 업데이트)

선행 문서(`mediapipe-internal-smoothing-bypass-…`)의 IMAGE 모드 A/B는 **2026-07-09 승격
확정**됐다: LensSim은 `RunningMode.IMAGE` 고정으로 전환(커밋 `21c6d8a`), 토글 제거. 최신
빌드에서 자글거림 해소·fps 24+ 유지·밀착감 개선을 실기기 확인. 클리핑 관점에서도 내부
스무딩 우회가 "윤곽이 눈을 늦게 따라와 클립이 미끄러지는" 성분을 제거해 기여했다.
(IrisLens는 그래프 직접 소유라 스무딩 계산기만 제거하는 더 좋은 해법 가능 — 선행 문서 §4.)
