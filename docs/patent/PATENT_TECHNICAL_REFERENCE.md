## 1. 발명의 전체 개요

### 1.1 발명의 명칭 (후보)

- "실시간 카메라 영상에서의 가상 콘택트 렌즈 오버레이 및 피부 보정을 위한 장치 및 방법"
- "다중 신호 기반 주파수 분리 피부 보정과 비대칭 타원 마스킹을 이용한 AR 렌즈 피팅 시스템"

### 1.2 기술 분야

본 발명은 모바일 기기의 카메라 영상에서 실시간으로 사용자의 홍채를 검출하고, 가상 콘택트 렌즈를 자연스럽게 합성하며, 동시에 피부 보정(뷰티 필터)을 적용하는 증강현실(AR) 시스템에 관한 것이다.

### 1.3 발명이 해결하는 핵심 과제

1. **실시간성**: 모바일 기기에서 30fps 이상의 처리 속도로 홍채 검출 + 렌즈 합성 + 피부 보정을 동시 수행
2. **자연스러움**: 가상 렌즈가 "스티커처럼 붙은" 느낌이 아닌, 실제 착용한 것 같은 사실적 합성
3. **피부 보정 품질**: 잡티는 제거하면서 주름, 피부결, 눈/입술 경계는 보존하는 선별적 보정
4. **안정성**: 영상 프레임 간 렌즈 위치/크기의 떨림(지터) 및 깜빡임 방지

### 1.4 전체 시스템 파이프라인

```
카메라 프레임 입력 (RGBA/YUV)
    │
    ├─[1] 프레임 전처리 (포맷 변환, 회전 보정)
    │
    ├─[2] 얼굴/홍채 검출 (TFLite 3단계 추론)
    │     ├── Face Detection (128x128)
    │     ├── Face Landmark (192x192, 478점)
    │     └── Iris Landmark (64x64, 좌우 각 5점)
    │
    ├─[3] 시간적 안정화 (One-Euro Filter + 신뢰도 게이팅)
    │
    ├─[4] 피부 보정 (주파수 분리 GPU 파이프라인)
    │     ├── ROI 기반 피부 영역 마스킹
    │     ├── 주파수 분리 (Gaussian 블러 → 저주파/고주파)
    │     ├── 3-신호 결합 잡티 감쇠
    │     ├── 톤 커브 + 휘도 샤프닝
    │     └── 색상 보정 (밝기, 색온도, 화이트닝)
    │
    ├─[5] 얼굴 변형 (RBF 메시 워핑)
    │     ├── 슬림 페이스 (볼 안쪽 이동)
    │     ├── V라인 (턱 축소)
    │     └── 눈 확대 (방사형 확장)
    │
    └─[6] 가상 렌즈 합성 (GPU 셰이더)
          ├── 비대칭 타원 마스크 (눈 윤곽 피팅)
          ├── 눈꺼풀 클리핑 (오클루전 처리)
          ├── 8종 블렌드 모드 (색상 합성)
          ├── 공막 보호 (이중 팩터 게이팅)
          └── 접촉 그림자 (깊이감 표현)
```

## 2. 종래 기술의 문제점

### 2.1 기존 피부 보정의 한계

**양측 필터(Bilateral Filter) 방식의 문제**:
- 에지 보존 필터이나 O(r²) 연산 복잡도로 모바일에서 느림
- 잡티와 피부결을 구별하지 못함 (크기 기반 단일 신호)
- 블러 강도를 높이면 피부가 "밀랍 인형"처럼 부자연스러워짐
- 눈/입술 경계에 후광(halo) 아티팩트 발생

**기존 주파수 분리(Frequency Separation) 방식의 문제**:
- 고주파 크기(magnitude)만으로 감쇠하므로:
  - 주름 (중간 크기) → 잡티로 오인하여 삭제
  - 색소침착 (낮은 진폭) → 검출 실패
  - 눈/입술 경계 (높은 진폭) → 잡티로 오인하여 흐림
- sRGB 색공간에서 블러 시 물리적으로 부정확한 평균 → 어두운 후광 발생
- 주파수 분리 후 톤이 평탄해져 "생기 없는" 결과

### 2.2 기존 가상 렌즈 합성의 한계

**2D 사각형 오버레이 방식의 문제**:
- 렌즈 텍스처를 홍채 위치에 단순 배치 → "스티커" 느낌
- 눈꺼풀이 덮는 부분까지 렌즈가 표시됨 (오클루전 미처리)
- 공막(흰자) 영역까지 렌즈 색상이 번짐
- 원형 마스크만 사용하여 실제 눈 형태와 불일치
- 깊이감(그림자) 없이 평면적

**기존 눈 마스킹의 문제**:
- 원형 마스크: 눈의 내측(코쪽)과 외측(관자놀이쪽)의 비대칭 형태를 표현 불가
- 다각형 SDF(Signed Distance Field): 16점 폴리곤 평가에 ~200+ 연산, 실시간 부적합
- 누루(caruncle, 눈 안쪽 붉은 조직) 보호 미고려

### 2.3 기존 얼굴 변형의 한계

- 랜드마크 직접 이동 방식: 제어점 주변에 불연속(핀칭) 발생
- 전체 픽셀 워핑: 연산량 과다, 모바일 실시간 불가
- 단일 효과만 적용 가능 (슬림+V라인+눈확대 동시 적용 어려움)

## 3. 핵심 발명 #1: 실시간 AR 렌즈 피팅을 위한 통합 파이프라인 시스템

### 3.1 과제의 해결 수단

본 발명은 얼굴/홍채 검출, 시간적 안정화, 피부 보정, 얼굴 변형, 렌즈 합성을 단일 GPU 파이프라인으로 통합하여 모바일 기기에서 실시간 처리를 달성한다.

### 3.2 시스템 구성

#### 검출 레이어
- **3단계 캐스케이드 추론**: Face Detection → Face Landmark (478점) → Iris Landmark (좌우 각 5점)
- **전용 추론 스레드**: GPU 가속 TFLite 추론을 별도 스레드에서 수행하여 렌더링 파이프라인과 분리
- **단일 슬롯(Single-Slot) 패턴**: 추론 요청/결과를 단일 슬롯으로 관리하여 최소 동기화 오버헤드

#### 렌더링 레이어
- **공유 렌더 컨텍스트**: 뷰티 필터와 렌즈 렌더러가 동일 GL 컨텍스트를 공유하여 제로카피(zero-copy) 처리
- **텍스처 풀(Texture Pool)**: 최대 8장의 텍스처를 오브젝트 풀로 관리하여 할당/해제 오버헤드 제거
- **핑퐁 버퍼링**: 필터 체이닝 시 텍스처 앨리어싱 방지

#### 디바이스 적응 레이어
- GPU 렌더러 문자열 파싱으로 디바이스 등급 자동 분류:
  - **HIGH** (Adreno 7xx, Mali-G710+, Apple GPU): 풀 해상도 주파수 분리
  - **MID** (Adreno 6xx, Mali-G7x): 하프 해상도 하이브리드 (블러는 1/2 해상도, 합성은 풀 해상도)
  - **LOW** (기타): 양측 필터 폴백

### 3.3 데이터 구조

**홍채 검출 결과 (IrisResult)**:
```
- 검출 상태: 전체 감지, 좌/우 개별 감지, 신뢰도 (0.0~1.0)
- 좌/우 홍채: 각 5점 랜드마크 (중심 + 상하좌우 경계), 반지름
- 얼굴 정보: 바운딩 박스, 회전각 (pitch, yaw, roll)
- 얼굴 메시: 478점 3D 좌표 (선택적)
- 프레임 메타데이터: 타임스탬프, 해상도
```

**렌즈 설정 (LensConfig)**:
```
- 불투명도 (0.0~1.0), 스케일, 오프셋 (x, y), 회전
- 블렌드 모드 (8종): Normal, Multiply, Screen, Overlay,
  LuminanceTint, LuminanceTintLinear, SoftLight, ColorReplace
- 에지 페더링 강도, 좌/우 눈 개별 적용 설정
```

### 3.4 발명의 효과

| 지표 | 종래 기술 | 본 발명 |
|------|----------|---------|
| 처리 속도 | 15-20fps (CPU) | 30fps+ (GPU 가속) |
| 렌즈 합성 품질 | 2D 스티커 | 눈꺼풀 오클루전 + 공막 보호 + 그림자 |
| 피부 보정 | 균일 블러 | 선별적 잡티 감쇠 (주름/에지 보존) |
| 안정성 | 원시 좌표 (지터 심함) | 다층 시간적 안정화 |
| SDK 크기 | 18~33MB (경쟁사) | ~9MB |

## 4. 핵심 발명 #2: 다중 신호 결합 피부 잡티 감쇠 알고리즘

### 4.1 해결하려는 과제

주파수 분리 후 고주파 성분에서 잡티(여드름, 점 등)만 선택적으로 제거하되, 주름, 피부결, 눈/입술 경계와 같은 보존해야 할 구조는 유지해야 한다. 종래의 단일 신호(magnitude) 기반 감쇠로는 이들을 구별할 수 없다.

### 4.2 과제의 해결 수단

고주파 성분의 **크기(magnitude)**, **에지 그래디언트(edge gradient)**, **색차 편차(chroma deviation)** 3가지 독립 신호를 결합한 복합 잡티 점수(blemish score)를 산출한다.

#### 3가지 신호의 정의

**신호 1: Magnitude (크기)**
```
magnitude = dot(abs(high_freq), vec3(0.2126, 0.7152, 0.0722))
```
- 고주파 성분의 휘도 가중 절대값
- Rec.709 선형광 계수 사용 (sRGB와 다름)
- 큰 값 = 큰 변화 (잡티 또는 에지)

**신호 2: Edge Gradient (에지 강도)**
```
lumCenter = dot(center_color, vec3(0.2126, 0.7152, 0.0722))
dx = lumRight - lumLeft   (수평 차분)
dy = lumUp - lumDown      (수직 차분)
edgeStrength = length(vec2(dx, dy))
```
- 원본 이미지의 중심 차분 기반 Sobel류 에지 검출
- 감마 2.0 공간에서 계산 (선형 변환의 빠른 근사)
- 큰 값 = 구조적 경계 (주름, 눈/입 경계)

**신호 3: Chroma Deviation (색차 편차)**
```
origY = dot(original, vec3(0.299, 0.587, 0.114))
blurY = dot(blurred, vec3(0.299, 0.587, 0.114))
origCb = original.b - origY
origCr = original.r - origY
blurCb = blurred.b - blurY
blurCr = blurred.r - blurY
chromaDev = length(vec2(origCb - blurCb, origCr - blurCr))
```
- 원본과 블러 간의 YCbCr 색차 성분 차이
- 휘도를 제거하여 순수 색상 편차만 측정
- 큰 값 = 색소침착, 붉은 여드름 등 색상 이상

#### 결합 공식

```
blemishScore = magnitude
             × (1.0 - edgeWeight × clamp(edgeStrength × 5.0 × 0.68, 0, 1))
             × (1.0 + chromaWeight × clamp(chromaDev × 10.0 × 0.66, 0, 1))
```

**각 항의 역할**:
- `magnitude`: 기본 잡티 크기 (기존 방식 호환)
- `(1.0 - edgeWeight × ...)`: 에지가 강할수록 점수 감소 → **주름/경계 보존**
- `(1.0 + chromaWeight × ...)`: 색차가 클수록 점수 증가 → **색소침착 감쇠 강화**

**기본 파라미터값**:
- edgeWeight = 0.5
- chromaWeight = 0.3

#### 다단계 감쇠 적용

blemishScore를 사용하여 미세 텍스처(모공), 중간 잡티, 큰 구조물을 구별:

```
// 미세 텍스처 대역 (모공 등) - 강하게 감쇠
microTextureBand = smoothstep(attn_low × 0.55, attn_high × 1.35, blemishScore)

// 큰 구조물 보호 (점, 모반 등) - 약하게 감쇠
largeDetailProtection = smoothstep(attn_high × 4.8, attn_high × 9.5, blemishScore)
largeDetailCompression = 0.38  // 최대 62%만 감쇠
```

추가 보호 메커니즘:
- **그림자/하이라이트 보호**: 어두운/밝은 영역에서 효과 강도 자동 감소
- **에지 보호**: `edgeProtection = 1.0 - edgeWeight × clamp(edgeStrength × 5.0 × 0.68)`
- **색차 보호**: `chromaProtection = 1.0 - chromaWeight × clamp(chromaDev × 10.0 × 0.66)`

### 4.3 종래 기술 대비 차이점

| 비교 항목 | 종래 (magnitude only) | 본 발명 (3-신호 결합) |
|----------|---------------------|---------------------|
| 주름 | 부분 삭제됨 | 에지 보호로 보존 |
| 색소침착 | 미검출 (낮은 진폭) | 색차 감지로 감쇠 |
| 눈/입 경계 | 흐림 발생 | 에지 보호로 보존 |
| 잡티 (점, 여드름) | 정상 감쇠 | 정상 감쇠 (호환) |
| 모공 | 감쇠 | 미세 텍스처 대역으로 제어 |

### 4.4 성능

- 추가 비용: 텍스처 샘플 4회 + ALU 약 15회
- 별도 렌더 패스 불필요 (기존 합성 셰이더에 인라인)
- Mali-G78 (MID 등급) 기준 1080p에서 +0.4ms

## 5. 핵심 발명 #3: GPU 기반 주파수 분리 뷰티 파이프라인

### 5.1 해결하려는 과제

모바일 GPU에서 실시간으로 주파수 분리 기반 피부 보정을 수행하되, 후광 아티팩트를 방지하고 자연스러운 결과를 얻어야 한다.

### 5.2 파이프라인 구조 (6 서브패스)

```
[입력 텍스처] (sRGB)
    │
    ▼
[패스 1a] sRGB→선형 RGB 변환 + 수평 가우시안 블러
    │     (gamma 2.2 역변환, 적응형 반경 6~28px)
    ▼
[패스 1b] 수직 가우시안 블러 → 저주파(Low Freq) 텍스처
    │
    ▼
[패스 2a] 저주파에 추가 수평 가우시안 블러
    │
    ▼
[패스 2b] 추가 수직 가우시안 블러 → 평활 저주파(Smoothed Low) 텍스처
    │
    ▼
[패스 3: 합성(Composite)] ← 핵심 패스
    │  입력: 원본, 저주파, 평활 저주파, 피부 마스크
    │  처리:
    │  ① 고주파 인라인 추출: high = original - lowFreq
    │  ② 3-신호 결합 잡티 감쇠 (상기 발명 #2)
    │  ③ 파운데이션 블렌딩: smoothedLow + 감쇠된 high
    │  ④ 톤 커브 (중간톤 리프팅)
    │  ⑤ 피부 마스크 적용: mix(original, beauty, skinMask)
    │  출력: 보정된 프레임
    ▼
[패스 4: 휘도 샤프닝]
    │  마스크 인식 언샤프 마스크 (4-이웃 크로스 패턴)
    │  휘도 채널만 샤프닝, 색차 보존
    ▼
[패스 5: 색상 보정]
    │  밝기 + 색온도 + 화이트닝 통합 패스
    ▼
[출력 텍스처]
```

### 5.3 핵심 기술 요소

#### 선형 RGB 공간 블러 (후광 제거)

**문제**: sRGB(감마 보정된) 색공간에서 가우시안 블러를 수행하면 물리적으로 부정확한 가중 평균이 계산되어 밝음/어두움 경계에 어두운 후광 아티팩트가 발생한다.

**해결**: 블러 전에 sRGB→선형 RGB 변환을 수행하고, 최종 출력 시 역변환한다.
```
선형화: linear = pow(srgb, 2.2)
역변환: srgb = pow(max(linear, 0.0), 1.0/2.2)
```
- 에지 검출에는 빠른 근사(gamma 2.0: `s * s`)를 사용하여 연산 비용 절감
- 블러에만 선택적으로 선형화를 적용하여 나머지 ALU는 sRGB 유지

#### 고주파 추출 인라인 최적화

**종래 방식**: 별도의 고주파 추출 패스 (`high = original - lowFreq + 0.5`)가 필요하여 풀 해상도 텍스처 1장의 추가 쓰기/읽기 발생

**본 발명**: 합성 셰이더 내에서 고주파를 ALU로 인라인 계산
```
high = original - lowFreq  (합성 셰이더 내부)
```
- 텍스처 수 동일(3장)에 패스 1개 절약
- `+0.5` 오프셋 불필요 → 정밀도 손실 위험 제거
- 모바일 TBDR GPU에서 약 2ms 대역폭 절약

#### Soft Light 블렌딩 (파운데이션 효과)

종래의 가산(additive) 블렌딩 대신 Pegtop Soft Light을 사용:
```
blend = clamp(vec3(0.5) + adjusted_high, 0.0, 1.0)
beauty = (1.0 - 2.0 × blend) × smoothLow² + 2.0 × blend × smoothLow
```
- **영점 항등성**: 고주파 = 0일 때 blend = 0.5 → 출력 = 입력 (변화 없음)
- **톤 의존 응답**: 게인 = 2a(1-a), 중간톤에서 최대 0.5
- **출력 범위 보장**: 유효 입력에 대해 수학적으로 [0,1] 출력 보장
- **GPU 효율**: 단일 수식, 분기(warp divergence) 없음

#### 2차 중간톤 리프트 (톤 커브)

주파수 분리 후 평탄해진 톤을 자연스럽게 복원:
```
f(x) = x + intensity × x × (1 - x)
```
- **경계 보존**: f(0) = 0, f(1) = 1 (하이라이트/새도우 불변)
- **0.5 중심 대칭**: x = 0.5에서 최대 리프트 (+intensity × 0.25)
- **단조 증가**: intensity ≥ 0이면 항상 f'(x) ≥ 0
- **수학적 유계**: intensity ≤ 1.0 → f(x) ≤ 1.0 (클리핑 불가)

#### 휘도 전용 샤프닝 (색차 보존)

```
lumCenter = dot(center, LUMA_709)       // Rec.709 휘도
lumBlur = weighted_avg(neighbors)        // 4-이웃 크로스 평균
lumSharp = lumCenter + amount × (lumCenter - lumBlur)  // 언샤프 마스크
ratio = min(lumSharp / lumCenter, 2.0)
sharpened = center × ratio               // 비례 스케일링
```
- 휘도 채널만 샤프닝하여 색상 노이즈 증폭 방지
- **마스크 인식 경계 처리**: 비피부 이웃 → 중심값으로 대체하여 경계 후광 방지
- 비율 기반 적용으로 색상/채도 보존

### 5.4 디바이스 적응형 처리

| 등급 | 기준 | 처리 방식 | 프레임 시간 목표 |
|------|------|----------|---------------|

  → [패스 3~5] 풀 해상도 합성/샤프닝/색상 보정 → 출력

### 5.5 ROI 기반 피부 마스킹

MediaPipe 478점 얼굴 메시에서 피부 영역 마스크를 생성:
```

2. 보호 마스크 반전 생성:
   - 눈 (16+16점), 눈썹 (8+8점), 입술 (22점), 코 (7+6점)
3. 결합: combined = skin × (1-eye) × (1-eyebrow) × (1-lip) × (1-nose)
4. 페더링: 15px 반경 부드러운 경계 블렌딩
```

## 6. 핵심 발명 #4: 비대칭 타원 눈 마스킹 및 공막 보호

### 6.1 해결하려는 과제

가상 렌즈를 홍채 위에 자연스럽게 합성할 때, 눈의 실제 형태에 맞게 마스킹하고 흰자(공막)로의 색번짐을 방지해야 한다.

### 6.2 비대칭 타원 마스크

#### 16점 눈 윤곽 피팅

MediaPipe 얼굴 메시의 눈 윤곽 16점에서 6개 파라미터를 추출:
```
입력: 16개 눈 윤곽 랜드마크
출력: (cx, cy, rxInner, rxOuter, ry, rotation)

1. 중심 (cx, cy) = 16점의 평균
2. 회전각 = atan2(외측 코너 Y - 내측 코너 Y, 외측 코너 X - 내측 코너 X)
3. 내측 X반경 (rxInner) = 중심~내측 코너 거리 × 0.85  ← 누루 보호 15%
4. 외측 X반경 (rxOuter) = 중심~외측 코너 거리 × 1.0
5. Y반경 (ry) = 회전 좌표계에서 16점의 최대 Y편차
```

#### 비대칭 타원 SDF 평가

```glsl
float asymmetricEllipseMask(vec2 uv, vec2 center, vec3 radii, float rotation, float feather) {
    vec2 d = uv - center;
    // 회전 변환 (눈 축 정렬)
    d = vec2(d.x * cosR + d.y * sinR, -d.x * sinR + d.y * cosR);

    // 비대칭: 내측(코 방향)과 외측(관자놀이 방향)에 다른 반경 적용
    float rx = (d.x < 0.0) ? radii.x : radii.y;  // rxInner vs rxOuter
    float ry = radii.z;

    float ellipseDist = length(vec2(d.x / rx, d.y / ry));
    return smoothstep(1.0, 1.0 - feather, ellipseDist);
}
```

**종래 기술 대비 장점**:
- 원형: 눈 형태 불일치 → 비대칭 타원: 실제 눈 형태 근사
- 다각형 SDF: ~200+ 연산 → 단일 length() 계산: ~10연산 (20배 빠름)
- 누루(caruncle) 보호: 내측 반경 15% 축소로 붉은 조직 노출 방지

### 6.3 공막 보호 (이중 팩터 게이팅)

렌즈 색상이 흰자(공막)에 번지는 것을 방지하는 연속 감쇠 알고리즘:

```glsl
float calcScleraFactor(vec3 cameraColor) {
    // 팩터 1: 밝기 (공막은 밝다)
    float brightness = dot(cameraColor, vec3(0.299, 0.587, 0.114));
    float brightFactor = smoothstep(0.5, 0.7, brightness);

    // 팩터 2: 채도 (공막은 무채색에 가깝다)
    float saturation = (maxChannel - minChannel) / max(maxChannel, 1e-4);
    float lowSatFactor = 1.0 - smoothstep(0.05, 0.2, saturation);

    return brightFactor × lowSatFactor;
}
// 적용: finalAlpha *= (1.0 - scleraFactor × 0.5)
```

**핵심 설계**:
- **이중 조건**: 밝기만으로는 노란 조명에서 오검출, 채도만으로는 밝은 물체에서 오검출 → 두 조건 결합
- **연속 감쇠**: 이진(on/off)이 아닌 smoothstep으로 부드러운 전환
- **보수적 감소**: 최대 50% 투명도 감소 (완전히 숨기지 않음)
- **조명 불변**: 주광/텅스텐/LED 조건에서 모두 유효 (테스트 완료)

### 6.4 접촉 그림자 (깊이감 표현)

눈꺼풀 아래에 얇은 그림자를 추가하여 렌즈가 홍채 위에 "놓여있는" 깊이감 표현:

```glsl
float calcContactShadow(float fragY, float minY, float eyelidFeather, float eyeOpening) {
    float shadowDepth = 4px / detH;  // 고정 4픽셀
    float shadowIntensity = clamp(intensity, 0.0, 0.25);  // 최대 25%

    // 그림자 시작점 = 마스크 페더 끝점 (이중 어둡게 방지)
    float shadowZone = smoothstep(
        minY + eyelidFeather,
        minY + eyelidFeather + shadowDepth,
        fragY
    );
    float shadowFactor = (1.0 - shadowZone) × shadowIntensity;

    // 눈 거의 감긴 상태에서 자동 비활성화
    float shadowEnable = smoothstep(0.015, 0.025, eyeOpening);
    return shadowFactor × shadowEnable;
}
```

**핵심 설계**:
- **비중첩 영역**: 마스크 페더 [minY, minY+feather] 와 그림자 [minY+feather, minY+feather+4px] 분리 → 이중 어둡게 방지
- **눈 열림 인식**: 눈 열림 < 0.015일 때 그림자 비활성화 (감긴 눈에 그림자 방지)
- **마스크 분리**: 그림자는 미적 레이어로 구조적 클리핑과 독립

### 6.5 블렌드 모드 (8종)

| 모드 | 수식 | 용도 |
|------|------|------|
| Normal | `mix(base, blend, α)` | 기본 알파 블렌딩 |
| Multiply | `mix(base, base × blend, α)` | 어둡게 |
| Screen | `mix(base, 1-(1-base)×(1-blend), α)` | 밝게 |
| Overlay | `base<0.5 ? 2ab : 1-2(1-a)(1-b)` | 대비 강화 |
| LuminanceTint (sRGB) | 휘도 보존 + 색조 변경 | 빠른 색상 교체 |
| LuminanceTint (Linear) | 선형 공간 + 정반사 복원 | 물리 기반 색조 |
| SoftLight | Pegtop 공식 | 자연스러운 색상 오버레이 |
| ColorReplace | 디테일 보존 색상 교체 | 홍채 텍스처 블렌딩 |

**LuminanceTint Linear 모드의 정반사 복원**:
```glsl
// sRGB↔선형 빠른 근사: linear ≈ srgb², srgb ≈ √linear
float realSpec = smoothstep(0.7, 0.95, luminance);
// 밝은 영역(눈 반짝임)에서 렌즈 색상 감소 → 자연스러운 하이라이트 보존
```

## 7. 핵심 발명 #5: RBF 기반 얼굴 변형 메시 시스템

### 7.1 해결하려는 과제

슬림 페이스, V라인, 눈 확대 등 복수의 얼굴 변형 효과를 동시에 적용할 때, 자연스럽고 부드러운 변형을 실시간으로 달성해야 한다.

### 7.2 과제의 해결 수단

#### 2단계 아키텍처: 그리드 메시 + RBF 보간

```
478점 얼굴 랜드마크
    ↓ (약 30점만 제어점으로 선택)
그리드 메시 (20×20 = 441개 정점)
    ↓ (제어점에 변위 설정)
RBF 보간 (가우시안 기저함수)
    ↓ (모든 정점으로 변위 확산)
최종 정점 위치 계산
    ↓
GPU 렌더링 (삼각형 래스터화)
```

#### LOD(Level of Detail) 시스템

얼굴 크기에 따라 메시 밀도 자동 조절:
```
LOW:    8×8 격자 (81 정점, 128 삼각형) — 얼굴 < 화면의 15%
MEDIUM: 14×14 격자 (225 정점, 392 삼각형) — 15%~30%
HIGH:   20×20 격자 (441 정점, 800 삼각형) — > 30%
```

#### RBF 보간 알고리즘

```
weight(d) = exp(-d² / (2σ²))    σ = 0.15 (얼굴 폭 기준)
```

- 활성 제어점(변위 ≠ 0)만 사용하여 연산 최소화
- 가중치 임계값 1e-4 이하 건너뛰기
- 전체 정점에 부드럽게 변위 확산 → 불연속 없음

#### 효과별 변위 계산

**슬림 페이스**:
- 볼 랜드마크 8점 × 좌우 = 16점을 제어점으로 사용
- 최대 변위: 얼굴 폭의 3% (MAX_SLIM_FACE_DX = 0.03)
- Y위치 가중: 볼 중심에서 강하고 위/아래로 감소 (종 모양)
- 거리 감쇠: 코사인 폴오프 `weight = 0.5 + 0.5 × cos(d × π)`

**V라인**:
- 턱 랜드마크 5점 × 좌우 + 턱끝 8점
- 최대 X변위: 2%, 최대 Y변위: 2.5%
- Y위치 선형 가중: 아래쪽 점이 더 크게 이동
- 턱끝 고정 앵커로 점 수렴 방지

**눈 확대**:
- 눈 윤곽 16점 + 홍채 중심을 제어점으로 사용
- 최대 스케일: 25% (MAX_EYE_ENLARGE_SCALE = 0.25)
- **방사형 확장**: 홍채 중심 기준 외부로 확장
- 내부 영역(동공 근처): 축소 계수로 홍채 보존
- **눈썹 동기 리프트**: 눈 확대 시 눈썹도 30% 비율로 자동 상승

### 7.3 종래 기술 대비 차이점

| 비교 | 직접 랜드마크 이동 | 전체 픽셀 워핑 | 본 발명 (그리드+RBF) |
|------|------------------|-------------|-------------------|
| 연속성 | 불연속(핀칭) | 연속 | 연속 (RBF 보간) |
| 연산량 | O(제어점) | O(픽셀수) | O(정점×제어점) |
| 다중 효과 | 간섭 | 순차 적용 | 동시 합성 |
| 실시간 | 가능 | 불가 | 0.74ms/프레임 |

## 8. 핵심 발명 #6: 다층 시간적 안정화 아키텍처

### 8.1 해결하려는 과제

실시간 영상에서 프레임마다 검출되는 홍채/랜드마크 좌표의 미세 떨림(지터)과 검출 실패 시 갑작스러운 소실(깜빡임)을 방지해야 한다.

### 8.2 3층 구조

```
Layer 1: 신뢰도 이력현상(Hysteresis) + 가시성 페이드
    ├── 추적 진입 임계값: 0.3 (낮음) / 재획득 임계값: 0.6 (높음)
    ├── 페이드 인: ~100ms / 페이드 아웃: ~200ms
    └── 검출 실패 시 최대 5프레임 유지 (hold frames)

Layer 2: 아웃라이어 거부 + 눈 깜빡임 감지
    ├── 프레임 간 거리 > 2×홍채 반경 → 아웃라이어 의심
    ├── 연속 2프레임 동일 방향 → 실제 이동으로 수용
    └── Eye Aspect Ratio(EAR) < 임계값 → 깜빡임 감지 → 위치 고정 + 페이드

Layer 3: One-Euro Filter (해부학적 부위별 튜닝)
    ├── 홍채 중심 (x, y):   min_cutoff=4.0, beta=15.0
    ├── 홍채 반경:           min_cutoff=4.0, beta=7.5  (느린 반응)
    ├── 눈꺼풀 (상/하):      min_cutoff=4.0, beta=12.0 (깜빡임 대응)
    └── 타원 파라미터 (6개): 개별 beta 설정
```

### 8.3 One-Euro Filter 알고리즘

적응형 저역 통과 필터로, 움직임 속도에 따라 스무딩 강도를 자동 조절:

```
1. 속도 추정:  dx = (value - prev) / dt
2. 속도 필터링: filtered_dx = lowpass(dx, dCutoff)
3. 적응형 컷오프: cutoff = minCutoff + beta × |filtered_dx|
4. 위치 필터링: output = lowpass(value, cutoff)

lowpass(x, prev, alpha) = alpha × x + (1-alpha) × prev
alpha(cutoff, dt) = 1.0 / (1.0 + 1/(2π × cutoff × dt))
```

**핵심**: 느린 움직임(지터) → 낮은 cutoff → 강한 스무딩, 빠른 움직임 → 높은 cutoff → 빠른 반응

### 8.4 시간적 안정화 부가 기능

- **반경 데드밴드**: 0.0003 미만의 반경 변화 무시 (노이즈 억제)
- **렌즈 지속**: 검출 실패 후 최대 2초간 마지막 유효 위치 유지
- **렌즈 크기 캐시**: ±4픽셀 미만의 크기 변화 시 리스케일링 건너뛰기

## 9. 부가 발명 요소들

### 9.1 경량 가이드 필터 (O(1) 복잡도)

- 적분 이미지(integral image) 기반 O(n) 가이드 필터
- 서브샘플링 가속: 2x, 3x, 4x 다운샘플 + 업샘플
- 적응형 반경: face_width / 30
- 에지 보존율 ~80% (가우시안 대비)

### 9.2 품질 게이트 시스템

4가지 정량적 품질 지표를 결합한 자동 품질 판정:

| 지표 | 측정 방법 | 통과 기준 | 근거 |
|------|----------|----------|------|
| 라플라시안 분산 감소 | 피부 영역 라플라시안 분산 비교 | 30%~60% | 30% 미만: 불충분, 60% 초과: 과도 |
| SSIM (구조 유사도) | 비피부 영역 글로벌 SSIM | > 0.95 | Wang 등 (2004) |
| 후광 아티팩트 | 경계 Sobel 그래디언트 증가율 | < 15% | Paris & Durand (2006) |
| 시간 일관성 | 연속 300프레임 CV | < 5% | ITU-T P.910 |

판정: 3/3 통과 → GO, 2/3 → CONDITIONAL_GO, ≤1/3 → NO_GO

### 9.3 A/B 비교 프레임워크

피부톤 그룹(ITA 기반 밝음/중간/어두움) × 조명 × 거리 × 피부 상태별 자동 비교:
- 이상적 라플라시안 감소율 0.45에의 근접도
- SSIM 및 후광 지표 비교
- 선호율 > 70%를 통과 기준으로 사용

### 9.4 3티어 릴리즈 게이트

```
Tier 1 (Hard Stop): 크래시, 메모리 누수, 프레임 시간, 시간 안정성
Tier 2 (Quantitative): 품질 지표, GPU 프레임 시간, 텍스처 풀 사용량
Tier 3 (Qualitative): 사용자 블라인드 A/B 선호도, "뿌옇다"/"인공적" 피드백률
```

### 9.5 버퍼 풀 및 텍스처 풀

- 오브젝트 풀 패턴으로 런타임 할당/해제 최소화
- 메모리 압력 콜백 (Android onTrimMemory) 대응
- LRU 기반 유휴 텍스처 정리

## 10. 도면 설명 가이드

특허 명세서에 필요한 도면 목록:

### 도면 1: 전체 시스템 파이프라인 블록 다이어그램
- 카메라 입력 → 검출 → 안정화 → 뷰티 → 워핑 → 렌즈 합성 → 출력
- 각 블록의 입출력 화살표

### 도면 2: 3-신호 결합 잡티 감쇠 흐름도
- 입력: 고주파 성분, 원본 이미지, 블러 이미지
- magnitude/edge/chroma 3개 경로가 병렬로 계산
- 결합 → blemishScore → 다단계 감쇠 → 출력

### 도면 3: GPU 주파수 분리 파이프라인
- 6 서브패스의 텍스처 흐름
- 각 패스의 입출력 텍스처 표시
- 디바이스 등급별 분기 (HIGH/MID/LOW)

### 도면 4: 비대칭 타원 마스크 기하학
- 눈 윤곽 16점과 피팅된 타원
- rxInner, rxOuter, ry 표시
- 누루(caruncle) 보호 영역 표시

### 도면 5: 공막 보호 감쇠 그래프
- X축: 홍채 중심으로부터의 거리
- Y축: 알파 값
- 밝기 팩터, 채도 팩터, 결합 팩터 3개 곡선

### 도면 6: RBF 메시 변형 과정
- 6a: 원본 그리드 (제어점 표시)
- 6b: 슬림 페이스 변위 벡터
- 6c: V라인 변위 벡터
- 6d: 눈 확대 방사형 변위
- 6e: 3효과 동시 적용 결과

### 도면 7: 시간적 안정화 3층 구조
- 입력 원시 좌표 → Layer 1 (신뢰도) → Layer 2 (아웃라이어) → Layer 3 (필터) → 출력
- 각 레이어의 처리 내용

### 도면 8: One-Euro Filter 적응형 동작
- 느린 움직임 시 곡선 (강한 스무딩)
- 빠른 움직임 시 곡선 (빠른 추종)

### 도면 9: 접촉 그림자 영역 배치
- 눈꺼풀 라인, 페더 영역, 그림자 영역의 비중첩 배치

## 11. 경쟁사 대비 차별점

### 11.1 피팅몬스터 (InterVision210)

| 기능 | 피팅몬스터 | IrisLensSDK 차별점 |
|------|-----------|------------------|
| 렌즈 렌더링 | 3D FaceGeometry | 비대칭 타원 마스크 + 공막 보호 (경량) |
| 스무딩 | 3-layer (Landmark×2 + Visibility) | 3-layer + 해부학적 부위별 파라미터 |
| 피부 보정 | 상세 불명 | 3-신호 주파수 분리 (공개 가능) |
| SDK 크기 | ~33MB | ~9MB |

### 11.2 Perfect Corp (PerfectLib)

| 기능 | Perfect Corp | IrisLensSDK 차별점 |
|------|-------------|------------------|
| ML 프레임워크 | MNN (FP16) | TFLite (직접 호출, 범용) |
| 렌즈 렌더링 | PBR (Normal Map + IBL) | GPU 셰이더 + 8종 블렌드 (경량) |
| 눈 정밀화 | 2nd-step eye model (228KB) | 랜드마크 기반 + 비대칭 타원 피팅 |
| 피부 분할 | 경량 파싱 모델 (~413KB) | 랜드마크 기반 ROI 마스킹 |
| SDK 크기 | ~18MB | ~9MB |

### 11.3 본 발명의 고유 기술

경쟁사에서 확인되지 않은 본 발명 고유의 기술:
1. **3-신호 결합 잡티 감쇠** — magnitude + edge gradient + chroma deviation
2. **비대칭 타원 SDF 눈 마스킹** — 내측/외측 반경 차별화 + 누루 보호
3. **선형 RGB 공간 주파수 분리** — 후광 아티팩트 원천 제거
4. **Soft Light 파운데이션 블렌딩** — 자연스러운 보정 효과
5. **2차 중간톤 리프트** — 수학적으로 유계인 톤 복원
6. **접촉 그림자 비중첩 배치** — 페더/그림자 영역 분리
7. **디바이스 적응형 하이브리드 해상도** — MID 등급용 1/2 블러 + 풀 합성

## 12. 용어 정의

| 용어 | 정의 |
|------|------|
| 홍채(Iris) | 눈의 색이 있는 부분으로, 동공을 둘러싸는 원형 구조 |
| 공막(Sclera) | 눈의 흰자 부분 |
| 누루(Caruncle) | 눈 안쪽 코 방향의 붉은 조직 |
| 주파수 분리(Frequency Separation) | 이미지를 저주파(색조/형태)와 고주파(텍스처/디테일)로 분리하는 기법 |
| One-Euro Filter | 움직임 속도에 따라 스무딩 강도를 적응적으로 조절하는 저역 통과 필터 |
| RBF (Radial Basis Function) | 방사형 기저 함수. 중심으로부터의 거리에 따라 가중치가 결정되는 보간 방법 |
| SDF (Signed Distance Field) | 부호 있는 거리장. 도형의 경계로부터의 거리를 부호로 표현하는 방법 |
| TBDR (Tile-Based Deferred Rendering) | 모바일 GPU의 타일 기반 지연 렌더링 아키텍처 |
| TFLite | TensorFlow Lite. 모바일/에지 디바이스용 경량 ML 추론 프레임워크 |
| 페더링(Feathering) | 마스크/경계의 부드러운 그라데이션 처리 |
| sRGB | 표준 RGB 색공간 (감마 보정 적용) |
| 선형 RGB | 감마 보정이 제거된 물리적으로 정확한 RGB 색공간 |
| 양측 필터(Bilateral Filter) | 공간적 거리와 색상 차이를 모두 고려하는 에지 보존 블러 |
| 블렌드 모드 | 두 이미지 레이어를 합성하는 수학적 연산 방식 |
| EAR (Eye Aspect Ratio) | 눈의 세로/가로 비율. 눈 깜빡임 감지에 사용 |
| ROI (Region of Interest) | 관심 영역. 처리 대상 이미지의 부분 영역 |
| ITA (Individual Typology Angle) | 피부톤 분류를 위한 표준 지표 (밝음/중간/어두움) |
| SSIM (Structural Similarity Index) | 이미지의 구조적 유사도를 측정하는 지표 |
